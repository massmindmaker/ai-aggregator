## Decisions Made

- **MIN_RUN_COST = 1₽** floor for the run-start gate (Claude's discretion per CONTEXT). The authoritative debit is still per-run cost via settleRun; the gate only blocks obviously-empty wallets before spending an upstream call.
- **READ COMMITTED + guarded UPDATEs** (not the dev-docs §2.3 SERIALIZABLE sample). Overspend/double-spend safety comes from the per-row lock postgres takes on the updated row plus the WHERE guard — so there is intentionally no 40001 serialization-failure retry loop. `grep -c "ISOLATION LEVEL SERIALIZABLE"` = 0 by design.
- **Debit `tg_user_balances`, not `tg_users`** — confirmed the live spendable table via the topup-check credit route (`INSERT … ON CONFLICT DO UPDATE SET balance_rub = balance + EXCLUDED.balance_rub`) and migration 0019. The dev-docs §2.3 `tg_users` sample is wrong for this codebase.
- **White-label error labels** — the gateway path no longer emits `openrouter` in error text (renamed call-failure label to `upstream_error`, fetch-failure label to `upstream`). Upstream URL/provider name is never logged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] enc_key encoding contract (no BYOK write route exists yet)**
- **Found during:** Task 3 (loadProviderCredential)
- **Issue:** The plan says to decode `enc_key` "in the SAME encoding the BYOK write route used (verify in 0026 / the write route)." A repo-wide grep showed `enc_key` and `agent_provider_credentials` are referenced ONLY in migration 0026 + planning docs — there is NO write route inserting into that table yet. So there is no existing encoding to "match exactly."
- **Fix:** Chose `Buffer.from(enc_key, 'base64')` — the Node-idiomatic Buffer→TEXT convention — and documented in a code comment + this SUMMARY that the future BYOK write route MUST store `encryptSecret(key).toString('base64')` to match. The legacy `external_api_key_encrypted` path uses a raw `Buffer` into a `bytea` column, but `enc_key` is a TEXT column (0026 line 71) so a string encoding is required.
- **Files modified:** apps/agent-worker/src/db.ts
- **Verification:** tsc clean; decryptSecret expects the iv|ct|tag blob crypto.ts produces, which base64 round-trips losslessly.
- **Committed in:** 564e5f5 (Task 3 commit)

**2. [Rule 2 - Missing Critical] White-label error label leak on the aiag path**

- **Fix:** Renamed the gateway-path failure labels to `upstream` / `upstream_error`. The OpenRouter direct fallback keeps an internal-only label.

## VPS verification (deferred)

Per the AIAG no-local-runtime rule, the following were NOT run locally — the operator runs them on `ai-aggregator.ru` after deploy (build the worker manually per the TMA-deploy memory, then `pm2 restart agent-worker`):

2. **Unit suite:**
   ```
   cd apps/agent-worker && npm install && npm test
   ```
   (locally only `npx tsc --noEmit` was run — exit 0; vitest is installed by `npm install` on the VPS)
3. **Task 1 verify (deferred):**
   ```
   cd apps/agent-worker && npx vitest run --reporter=basic
   ```
4. **Zero-balance gate (R0-2):** pick/create a tg_user with `balance_rub = 0`, run an aiag agent → the run ends `failed` with error `insufficient_balance`; no upstream call recorded.
5. **Paid run (R0-1 + R0-2):** top a user to e.g. 100₽, run an aiag agent →
   ```
   SELECT * FROM gateway_transactions ORDER BY created_at DESC LIMIT 1;   -- type='api_usage' with markup in delta
   SELECT balance_rub FROM tg_user_balances WHERE tg_user_id = <id>;      -- dropped by the run cost
   ```
   Confirm the run is `completed` AND balance changed together (single tx).
6. **Concurrency (R0-3):** fire 4 simultaneous runs against an agent whose `daily_budget_rub` affords ~2 →
   ```
   SELECT spent_today_rub, daily_budget_rub FROM agents WHERE id = <id>;  -- spent_today_rub <= daily_budget_rub, never exceeded
   ```
   over-budget runs are `failed` with `budget_exceeded_daily_settle`.
7. **Picker (R0-6):** create an agent via the new provider picker (`provider_id` set, real BYO key) → its run routes to that provider; upstream name stays hidden from the user-facing notification.
