## Phase Boundary

Emergency remediation of the shipped Telegram Mini App (`apps/tg-miniapp` + `apps/agent-worker`) so it is **safe to put traffic on**. Closes the four live integrity holes found in the 50/108 tech-stack eval: agent runs that earn $0 and give away free inference, an auth middleware that an unpatched Next.js CVE can bypass, a likely 1000× crypto-overpay, and a shipped provider-picker that misroutes because the worker never read its columns.

**In scope:** the agent execution + billing path (`agent-runner.ts`, `db.ts`), the gateway routing seam (`packages/api-gateway` `:4000`), TMA auth (`middleware.ts`, `auth/verify`), and the Next.js runtime version. **Out of scope (later phases):** MCP gateway, Mastra/AI-SDK layering, observability stack, two-sided marketplace, 152-ФЗ screens, the jUSDT decimals audit (tracked as R1-8 unless it blocks).

**Hard constraints:** no-local-runtime — **verify on VPS `ai-aggregator.ru`** after deploy; bare-metal pm2+nginx (no Docker for the app); white-label upstream names stay hidden; reuse existing AES-256-GCM (`crypto.ts`); never expose a personal Telegram handle; `master` is the default branch → **work on a branch**, prod migrations are manual/untracked (`sudo -u postgres psql aiag` for ALTER).
</domain>

## Implementation Decisions (LOCKED — from the R0 roadmap, post-context7-corrected)

### R0-1 — Route `kind='aiag'` runs through the gateway (revenue + white-label)
- In `apps/agent-worker/src/agent-runner.ts` `resolveUpstream()`, for `connection_type='aiag'` build the upstream as `http://127.0.0.1:4000/v1/chat/completions` with `AIAG_GATEWAY_KEY` (a gateway api-key), NOT `OPENROUTER_URL` directly.
- Fall back to OpenRouter only if the gateway lacks the requested model. Apply `provider.markup` for cost accounting.
- Add `AIAG_GATEWAY_KEY` to `/srv/aiag/shared/.env`. Verify on VPS that `gateway_transactions` records agent runs and `X-AIAG-Upstream` stays hidden from the user.

### R0-2 — Debit the prepaid balance per run + gate run-start on balance
- `apps/agent-worker/src/db.ts`: add `debitBalance(tgUserId, costRub)` and call it **in one transaction** with `markCompleted` (so a crash can't record cost without debiting).
- Gate run start in `runAgent()` on `tg_user_balances.balance_rub >= MIN_RUN_COST`; on insufficient balance → `markFailed('insufficient_balance')` + DM. Today `db.ts` has ZERO `tg_user_balances` references — this is the core fix that stops free inference.

### R0-3 — Atomic daily-spend (kill the 4× TOCTOU)
- Replace the read-snapshot + later check with an atomic guarded update: `UPDATE agents SET spent_today_rub = spent_today_rub + $d WHERE spent_today_rub + $d <= daily_budget_rub RETURNING id`. If no row returned → over budget → fail.
- Merge `markCompleted` + `incrementDailySpend` into one `sql.begin()` transaction.

### R0-4 — Patch the auth-bypass CVE + harden JWT (CORRECTED — middleware already verifies)
- `middleware.ts` ALREADY `jwtVerify`s and overwrites `x-tma-user-id` from `sub` — so the fix is NOT a new verify layer. The fix is: **bump Next.js to ≥14.2.33** (CVE-2025-29927 lets `x-middleware-subrequest` skip middleware) and strip the `x-middleware-subrequest` header at nginx.
- Pin `jwtVerify(token, secret, { algorithms: ['HS256'] })` (+ optional iss/aud); add a Redis-backed JWT denylist for revocation.

### R0-5 — Fail hard on missing JWT secret
- Remove the `?? 'dev-only-change-in-prod'` fallback in BOTH `middleware.ts:5` and `auth/verify/route.ts`; throw at startup if `TMA_JWT_SECRET` is unset (and ideally assert length ≥ 32).

### R0-6 — Wire migration 0026 provider columns into the worker
- Extend `AgentRow` (`db.ts:11-27`) + `loadAgent()` SELECT with `provider_id, model_id, auth_ref, base_url_override`; add a `resolveUpstream()` branch: `provider_id IS NOT NULL` → load+decrypt `agent_provider_credentials` (generic OpenAI path). Back-compat: `provider_id IS NULL` ⇒ existing aiag/external_openai logic untouched.

### Testing (ships WITH R0, not after)
- Unit tests for `resolveUpstream` (all branches), `estimateCostRub`, and the atomic-deduct/budget math; one integration test of the enqueue → worker → gateway-settle → balance-debit path. (`apps/agent-worker` currently has zero tests.)

### Security threat model (MANDATORY in each PLAN)
- Each plan includes a `<threat_model>` block: auth-bypass (CVE), balance-drain/free-inference, TOCTOU overspend, SSRF on worker `fetch`, secret exposure. Block on high-severity.

### Claude's Discretion
- Exact `MIN_RUN_COST` value; transaction boundaries' precise SQL; how `AIAG_GATEWAY_KEY` is provisioned in the gateway; test framework choice (match `apps/web`'s); nginx directive form for stripping the header; whether the denylist is a separate Redis set or reuses an existing one.
</decisions>
