<objective>
Build the FREE opt-in: an agent owner marks their own agent transferable and optionally sets a sale price in credits. This writes only DB flags (`agents.transferable = TRUE`, `agents.transfer_price_credits`) — NO mint, NO gas, NO chain (CONTEXT.md decision #3: "сделать передаваемым = бесплатный DB-флаг + цена"; the real mint is lazy, acquirer-paid, at actual transfer in plan 03). CONTEXT.md open question #4 (UX surface) is RESOLVED here + in plan 04: the **owner** sets transferable + price on the owner detail page and gets a **share link** (`/agents/[id]/offer`); the **acquirer** opens that link → a public **offer page** (plan 04) backed by THIS route's read → pays via TON Connect (plan 03). Two distinct surfaces: owner = "make transferable + share"; acquirer = "accept gift / buy".

Purpose: the toggle that makes an agent eligible for gift/sale + the public read the acquirer's offer page consumes. The toggle mirrors the existing `publish/route.ts` opt-in pattern; the public read mirrors the existing public `nft/collections` read pattern (unguarded, non-sensitive fields only).
Output: a new make-transferable route + 3 added columns in the detail GET SELECT + a new public transfer-offer read route.
</objective>
