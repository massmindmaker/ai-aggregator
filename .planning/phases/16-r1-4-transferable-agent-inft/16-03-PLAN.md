<objective>
The keystone. Build the two-step async transfer/sale flow, an EXACT structural copy of the Phase-15 Startonus pattern (`nft/purchase` → `nft/webhook`) crossed with the Wave-1 atomic money tx (`templates/[id]/rent`):

1. **Initiate** (`POST /tg/api/tma/agents/[id]/transfer`): the acquirer (recipient) requests the agent. We insert a `pending` `transfer_charges` row, call Startonus `generateInvoice` to mint a TEP-62 NFT onto the ACQUIRER's TON wallet (acquirer pays the mint fee in TON via TON Connect), and return the TON Connect transaction. We do NOT move ownership yet.
2. **Finalize** (`POST /tg/api/tma/agents/transfer/webhook`): when Startonus confirms the mint, in ONE `sql.begin` we atomically: move the agent (guarded UPDATE on old owner), wipe personal history (`DELETE FROM agent_runs`), strip secrets the new owner must not inherit, and — for a SALE — debit the buyer + credit the seller 100% (AIAG 0%, exactly like author-rent) with two equal-and-opposite ledger rows under one `ref_id`. Idempotent.

Purpose: this is the whole feature's money + ownership-move. Reuses the existing Startonus plumbing (CONTEXT.md / correction: do NOT build a custom minter) and the live rent atomic-tx invariant (SECURITY.md).
Output: two new routes. Memory re-key is a documented STUB seam here (memory is near-empty pre-D-5; plan 04 owns the seam doc/edge-cases).
</objective>
