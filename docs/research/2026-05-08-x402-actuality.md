# x402 Actuality Report — May 2026

**Дата:** 2026-05-08
**Контекст:** перепроверка spec'а Phase 16 (`docs/superpowers/specs/2026-05-08-phase16-x402-protocol-design.md`) перед имплементацией.
**TL;DR:** Phase 16 spec в целом актуален, но требует ~7 точечных правок. Главное — мы уже корректно ссылаемся на v2 (что хорошо), но **TON не поддерживается** ни одним из существующих facilitators, наша Phase 16.3 — реально greenfield. Появились серьёзные конкуренты (Stripe MPP, ACP, AP2) — стоит упомянуть в позиционировании. РФ-санкционные риски усилились (20-й пакет ЕС, апрель 2026).

---

## 1. Текущая версия спецификации

- **x402 v2** запущен **11 декабря 2025**. Анонс: [x402.org/writing/x402-v2-launch](https://www.x402.org/writing/x402-v2-launch).
- Спека: github.com/**x402-foundation/x402** (репо переехало из `coinbase/x402` в Foundation; coinbase/x402 теперь dev-fork).
- Канонические доки: [docs.x402.org](https://docs.x402.org).
- Whitepaper: x402.org/x402-whitepaper.pdf.
- v2 объявлен **non-breaking** относительно v1 — SDK обратно совместимы. Но рекомендованы новые header-имена.

## 2. Breaking changes / эволюция с launch (май 2025 → май 2026)

| Что | Было (v1) | Стало (v2) |
|---|---|---|
| Headers | `X-PAYMENT`, `X-PAYMENT-RESPONSE`, `X-Accept-Payment` | `PAYMENT-SIGNATURE`, `PAYMENT-RESPONSE`, `PAYMENT-REQUIRED` (legacy alias accepted) |
| Network ID | ad-hoc strings (`base`, `solana-mainnet`) | **CAIP-2** (`eip155:8453`, `solana:5eykt4...`) — старые строки тоже принимаются |
| Architecture | монолит SDK | **plugin-driven**: chains/assets/schemes регистрируются, не хардкодятся в SDK |
| Identity | только per-request | **wallet sessions** (CAIP-122 SIWx) — можно пропускать on-chain после первой оплаты |
| Schemes | `exact` only | `exact`, `upto` (range), `deferred` (Cloudflare proposal — settle позже), `credit` (внеспеково — наш паттерн) |
| Replay | EIP-3009 nonce | то же + EIP-712 domain separator с chainId enforced |

Метрики экосистемы (источники: x402.org/Block.co/agentpaytrend.com):

- Май 2025: launch.
- Конец 2025: 100M payments processed.
- Апрель 2026: 69k активных агентов, 165M транзакций, $50M cumulative volume.

- Python: 29.3% — production-ready.
- Go: 19.1% — production-ready.
- **Rust** — community fork, не official.
- Поддержка: EVM, Solana, Stellar, Algorand, Aptos, Hedera.

**Facilitators (ranked by share, апрель 2026):**

2. **PayAI** — №2, ~13.78% share. Base + Solana + Polygon + другие.
3. **Cloudflare** — добавил x402 в Agents SDK + MCP servers, продвигает `deferred` scheme.
4. **OpenZeppelin** — audited smart-account contracts с programmable spending limits.
5. **Self-hosted** из `coinbase/x402` — наша опция для 16.3.

**Третьи стороны / интеграторы:**

- **Vercel** — член x402 Foundation; Vercel AI Gateway имеет x402 middleware для serverless functions.
- **Cloudflare** — co-founder Foundation (сентябрь 2025).
- **Anthropic** — член Foundation, но **собственного payments-протокола нет**; рекомендуют x402 для Claude tool-use агентов.
- **Google** — член Foundation; продвигает свой **AP2 (Agentic Payments Protocol)** с x402-extension для крипто.
- **Visa, AWS, Circle** — члены Foundation.
- **AWS Bedrock AgentCore** (анонс 2026) — payments built with **Coinbase + Stripe** (двухрельсовая интеграция).

**КРИТИЧНО:** TON официально нигде не упомянут — ни в `docs.x402.org/core-concepts/network-and-token-support`, ни в spec'ах, ни в release tags. Утверждение из Phase 16.3 ("write our own thin shim because TON has no canonical x402 facilitator yet") — **корректно и подтверждено**. Telegram сделал в апреле 2026 fee cut в 6x (~$0.0005/tx), запустил собственный validator на 2.2M TON — экосистема активна, но **x402-on-TON это greenfield**, нам придётся писать спеку самостоятельно.

USDT-on-TON через нативный jetton-transfer — наш самостоятельный путь. Для USDT-on-EVM есть готовый Utexo (можно рассмотреть как ускоритель для 16.3, но не TON).

## 5. Adoption — кто реально подключился

**Подключились (production):**
- Vercel AI Gateway — x402 middleware.
- Cloudflare Workers + Agents SDK + MCP.
- AWS Bedrock AgentCore (через Coinbase rail).
- Десятки smaller facilitators (PayAI, Nevermined, Eco Protocol).

**Заявили поддержку, но без чёткой production-интеграции:**
- Google (через AP2 wrapper).
- Anthropic (как Foundation member; рекомендации без своего рельса).

**Кто не пошёл:**
- **OpenAI** выбрала **ACP (Agentic Commerce Protocol)** совместно со Stripe (сентябрь 2025) и **Stripe MPP** (март 2026) вместо x402. Это значит, что ChatGPT-агенты по умолчанию платят через Stripe, не x402. Можем поддерживать **оба** — нам это политически выгодно.
- **Replicate, Fal, RunPod** — пока не приняли x402, остаются на API keys.

**Метрики:** 69k активных агентов / 165M tx / $50M cumulative volume к апрелю 2026 — небольшой рост в денежном выражении (avg ~$0.30/tx, что подтверждает hypothesis о micropayments).

## 6. Альтернативы за прошедший год

| Протокол | От кого | Когда | Что | Угроза для нас |
|---|---|---|---|---|
| **Stripe MPP** | Stripe + Tempo | март 2026 | session-based streaming, off-chain, fiat | Высокая — у Stripe огромный merchant footprint. Они идут после **same** segment. |
| **ACP** | OpenAI + Stripe | сентябрь 2025 | merchant-checkout REST, Apache 2.0 | Низкая — другой use case (commerce, не API access). |
| **AP2** | Google | 2025 | authorization auditing для агентов; имеет x402-extension | Низкая — комплементарно, не конкурент. |
| **L402** | Lightning Labs | 2023 (жив) | Lightning + macaroon | Низкая — BTC volatility убивает per-request pricing. |
| **Coinbase x402** | Coinbase + Foundation | май 2025 | то, что мы делаем | — |

**Вывод 2026:** Реальный выбор для агент-native use case = **x402 vs Stripe MPP**. Мы выбрали x402, что обоснованно для крипто-friendly агентов (РФ + TG Mini App). Но **стоит держать MPP в дорожной карте** как Phase 16.5 для интеграции через Stripe rails (если ИП поверх Tempo сможет работать в РФ).

## 7. РФ блокеры — ситуация хуже, чем в Phase 16 spec

- **20-й пакет санкций ЕС (апрель 2026)** — sweeping ban на все crypto-asset transactions с российскими/белорусскими providers. Это значит: **EU-based** facilitators (включая Coinbase Europe) не должны обслуживать РФ-IP / РФ-зарегистрированных entities. Coinbase US — формально неподсанкционен, но в практике screen'ит OFAC и может flag'нуть ИП РФ.
- **USDC под Circle** — Circle (US-based) уже несколько лет blacklist'ит russia-linked адреса. Если наш `payTo` адрес попадёт в их oracle — фриз балансов. Митигация: ротация адресов, sweeper в cold-multisig (что уже в spec'е), но угроза реальна.
- **Self-host facilitator стало обязательным**, не опциональным. Полагаться на Coinbase facilitator для production — высокий operational risk. Нужно ускорить `Phase 16.3 self-host` до Phase 16.1 или 16.2.
- **115-ФЗ + поправки 173-ФЗ к 2026** — порог 600k₽/год для ВЭД-режима всё ещё актуален (не изменился). Phase 16 §8 здесь корректен.
- **KYC для facilitators в РФ** — если мы становимся facilitator (self-hosted), мы попадаем под 115-ФЗ/161-ФЗ как оператор-агрегатор. Нужна легальная экспертиза + возможно лицензия ОЭЗП. **Это новый блокер, в spec'е не учтён.**
- **SDK availability**: `@coinbase/cdp-sdk` доступна через npm/pypi — формально не блокируется. CDP API — на cdp.coinbase.com, доступен без VPN из РФ (на момент проверки апрель 2026). Но в любой момент Coinbase может ввести geo-fence — закладывать резерв.

## 8. Best practices 2026 — что изменилось

1. **Replay protection:** v2 спека делает явным enforcement EIP-712 domain separator с chainId — раньше некоторые SDK его пропускали. Phase 16 spec надо проверить на это в `verifyPayment`.
2. **Random 32-byte nonce** (не sequential) — стандарт; даёт parallel signing. Уже учтено.
3. **Fee handling:** Cloudflare's `deferred` scheme набирает популярность для AI-агентов с unpredictable cost (видео-генерация, long-running). Стоит рассмотреть для нашего Phase 16.4 (streaming subscriptions).
4. **Idempotency:** официальная рекомендация — `Idempotency-Key` header (не x402-specific). Наш `UNIQUE (network, tx_hash)` достаточен, но добавить header-уровень не помешает.
5. **Refunds:** в v2 появилась расширенная семантика через `credit` mode — то, что мы изобрели сами в Phase 16.2. Нужно сверить наш формат с тем, что Coinbase de facto рекомендует, чтобы не разойтись.
6. **Sanctions oracle:** Chainalysis Free Sanctions Oracle всё ещё free + on-chain, но **TRM Labs** в 2026 предлагает более широкий фид (включая EU 20-й пакет). Стоит рассмотреть upgrade.

## Phase 16 spec deltas — конкретные правки

Список, отсортированный по критичности:

1. **§1.1 References — обновить URL.** Spec репо переехало в `github.com/x402-foundation/x402`. Coinbase fork — теперь dev. Также добавить ссылку на whitepaper x402.org/x402-whitepaper.pdf и docs.x402.org. **Severity: high.**

2. **§1.3 Headers — уточнить CAIP-2.** v2 рекомендует CAIP-2 для `network` (например `eip155:8453` вместо `base`). SDK принимают оба, но для будущей совместимости в `accepts[]` стоит дублировать оба формата либо указать CAIP-2 как primary. **Severity: medium.**

3. **§3 Network selection — добавить колонку "Facilitator".** Сейчас не явно, кто умеет verify+settle для каждой сети. Особенно для Solana мы говорим "Coinbase SVM SDK" — это так, но PayAI тоже опция. **Severity: low (clarity).**

4. **§3 + §7.3 TON — explicit disclaimer.** Подтвердить, что TON spec мы пишем сами; нет canonical Foundation extension. Добавить TODO: предложить нашу TON-extension в Foundation после 16.3 (чтобы не остаться единственными). **Severity: high.**

5. **§8 Compliance — добавить параграф про 20-й пакет ЕС.** Coinbase Europe не должен обслуживать наш payTo. Использовать только Coinbase US facilitator или **сразу self-host** (предпочтительно). **Severity: critical.**

6. **§8 Compliance — добавить параграф про facilitator-status.** Если self-hostим, мы в РФ становимся "оператором ЦФА/иностранной эл. валюты"; потенциально 161-ФЗ + 259-ФЗ применимы. Нужна правовая экспертиза до запуска 16.3. **Severity: critical.**

7. **§10 Roadmap — переставить "Self-host facilitator" из 16.3 в 16.1 или 16.2.** Operational risk быть зависимыми от Coinbase facilitator с РФ-адреса слишком велик. **Severity: high.**

8. **§12 Open questions — добавить пункт "Stripe MPP coexistence".** Решить, поддерживаем ли мы MPP вторым рельсом для агентов из ChatGPT-экосистемы. **Severity: medium.**

9. **§9 Risks — добавить строку "Circle blacklist'ит наш payTo".** Mitigation: rotation, multi-address sweeper. **Severity: medium.**

10. **§1.4 PaymentRequired — рассмотреть SIWx session.** v2 даёт wallet sessions (CAIP-122). Для high-QPS агентов это альтернатива нашему `credit` mode и может быть проще для интеграторов. Стоит хотя бы упомянуть как Phase 16.4 candidate. **Severity: low.**

**Не требует правок (актуально):** §1.4-1.6 shapes, §2.1 flow, §4 pricing, §5 schema, §6 middleware pseudocode, §11 examples — всё совпадает с актуальной v2 семантикой.
