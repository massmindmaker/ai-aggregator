## Итог ревью

Проект не является пустым прототипом: уже есть значительная локально проверенная база API, каталога и денежного учёта. Но полного коммерческого сервиса пока нет. Локальные тесты с подменённым провайдером не доказывают работающий production, полноценный авторский рынок или оплаченный внешний inference.

| Блок | Что уже есть | Что ещё не закрыто |
|---|---|---|
| Покупательский API | Durable chat, embeddings, scalar completions, streaming; сохранение идентичности запроса, резервирование, результат, replay и восстановление расчёта | Общее runtime-включение и настоящие upstream-проверки; default по исходникам остаётся `legacy` |

## Что изменено в этой волне

1. **Сетевой транспорт (`packages/shared/src/safe-fetch.ts`).** Bun подключается к проверенному IP с исходными Host и TLS serverName, без неявного proxy. Node сохраняет свой dispatcher и оба callback-контракта lookup, включая `all=true`. Abort охватывает ожидание DNS; поздний DNS-ответ не запускает запрос. Закрываются собственные Agent и отброшенные response body; стандартные credentials не переносятся между origin. Нормализуются развёрнутые IPv6 loopback/mapped/unspecified адреса.
2. **Probe (`packages/shared/src/author-probe.ts`).** Неподходящие HTTP-ответы и content type освобождают body, а не оставляют соединение висеть. Это усиление helper, не реализация durable probe operation.
3. **Одобрение (`apps/web/src/app/api/admin/models/[id]/approve/route.ts`).** Старый endpoint больше не активирует авторскую модель без version lifecycle. Проверка и изменение обычной модели выполняются под блокировкой; UPDATE имеет условия и RETURNING. Обязательный audit находится в той же транзакции, а не в best-effort вызове после изменения.
4. **Редактор и создание модели (`apps/web/src/app/admin/models/...`).** Пять server actions перепроверяют роль и step-up при каждом вызове. Прямое чтение обеих страниц тоже защищено. Три редактирующих операции проверяют актуальную модель внутри транзакции и не обходят авторские версии. Удаление upstream привязано к ID модели. Вложенная форма заменена на `formAction`.
5. **Два старых дефекта тестов.** История миграций ожидала 80 файлов вместо уже существующих 87. Тест повреждённого шифротекста иногда не менял его байты. Ожидание обновлено до текущей истории, повреждение стало детерминированным. Исторические SQL-миграции и алгоритм шифрования не переписывались.

Добавлены регрессии для сетевых границ, Node lookup, старого approve, пяти server actions и структуры форм. До изменений наблюдались RED, а не только успешные тесты после написания кода.

## Дополнительный условный риск БД

`packages/database/src/index.ts` возвращает `neon-http` для Neon/Vercel URL, скрывая отличие приведением к типу PostgreSQL. У установленного `drizzle-orm/neon-http/session.js` метод `transaction` прямо выбрасывает `No transactions support in neon-http driver`.

Это **не доказательство, что production сейчас использует Neon**, и не дефект обычного pg/TCP пути. Но заявка автора и новые атомарные операции требуют транзакционного драйвера. До приёмки конкретного стенда необходимо подтвердить pg/TCP либо отдельно исправить и проверить Neon-путь. В этой волне драйвер и production-конфигурация не менялись.

После этого — AG-3b с native денежными регрессиями, а не переписывание уже принятого chat/batch ядра.

Не переоткрывать Arena/Agents Market и не начинать заново brainstorm того же специфицированного проекта. Не переносить непроверенные признаки `done` из старых чатов или scorecard. Внешнюю независимую проверку повторить, когда доступен рецензент; текущий пакет не имеет независимого одобрения.
