# TON: Task5 — начисление и восстановление в изолированном контуре

29.09.2026. Область: только AI Aggregator, текущая ветка `feat/ag-author-version-20260928`.

## Реализовано

Проверенный native TON-кандидат сначала получает неизменяемое наблюдение с подтверждённой записью. Только отдельный тестовый исполнитель после этого вызывает прежнюю SQL-функцию начисления. Ответ проверяется по точным полям и данным счёта; чужой чек, неверная сумма, лишние поля и ошибочные даты не принимаются.

Потеря подтверждения не считается откатом. При повторном запуске тот же счёт получает прежний чек, без второго начисления. Конфликт доказательств сохраняет отдельную запись на ручную проверку. Смена владельца блокировки проверяется до и после начисления; уже совершённая операция не отменяется, но старый процесс не двигает позицию и не освобождает чужую блокировку.

Экспорт `settleTonInvoice` убран из общего пакета БД и оставлен во внутреннем подмодуле. Это ограничение графа вызовов, НЕ разграничение полномочий PostgreSQL. Рабочий bootstrap по-прежнему принимает только `disabled|observe` и не получает функцию начисления.
