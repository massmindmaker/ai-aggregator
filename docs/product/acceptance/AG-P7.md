## Метод и правила статусов

Прочитаны фактически: `e2e/auth.setup.ts`, `e2e/api.spec.ts`, `e2e/home.spec.ts`,
`e2e/author-lifecycle.owned.spec.ts`, `playwright.config.ts`, `playwright.owned.config.ts`,
`playwright.author-owned.config.ts`, `scripts/verify-owned-auth.mjs`, `.github/workflows/ci.yml`,
`package.json`, `apps/web/src/lib/marketplace/catalog.ts`, артефакты прогонов
`.superpowers/sdd/**`, `docs/consolidation/2026-09-29-author-lifecycle-checkpoint.md`,
`docs/product/acceptance/AG-P6.md`, `AG-P1-route-coverage.md`.

**Playwright в этой инвентаризации не запускался** — это отдельный прогон контролёра. Поэтому
каждая строка опирается только на уже существующие артефакты прогонов либо помечена
UNVERIFIED.

- **PASS** — сценарий имеет фактическое утверждение о поведении И артефакт прогона
  (`*.json` репортера с `status: passed` или сохранённые скриншоты прогона).
- **UNVERIFIED** — кода/теста достаточно только чтобы «было», нет артефакта прогона, либо
  проверка поверхностна (HTTP 200 / наличие `<body>` / наличие `<h1>`), либо сценарий обойден
  через прямой SQL и не проходит через пользовательский интерфейс или HTTP.
- **FAIL** — требование AG-7 прямо нарушено: заявленный отдельный артефакт/evidence отсутствует.
  «Нет артефакта, которого роадмап требует отдельно» — это FAIL, а не UNVERIFIED.

Зелёный тест без артефакта прогона PASS не считается. Наличие экрана, спеки или чекпоинта
PASS не считается.

## Что блокирует приёмку v1

1. **Покупательского end-to-end сценария нет вообще.** Ни один браузерный прогон не
   создаёт ключ покупателя и не делает реальный HTTP-вызов к gateway. Начисление автору в
   пройденном сценарии создано прямым SQL с синтетическим телом
   (`e2e/author-lifecycle.owned.spec.ts:213-309`) — связка «покупатель заплатил → автор
   получил» не проверена ни разу.
2. **Авторский probe обойден интерфейсом.** Подтверждение провайдера сделано SQL-вызовами
   с синтетическим телом (`:138-156`). Сценария «автор нажал кнопку и увидел результат
   проверки» не существует.
3. **Claims ↔ runtime не сверяются.** Спеки `claims-vs-runtime.spec.ts` нет; STT-фильтр
   (`catalog.ts:104-112`) существует, но никто не проверяет, что витрина и `/v1/catalog`
   согласованы. Путь `apps/web/src/lib/pricing.ts` из плана не существует — поправить.
4. **Клавиатурной проверки нет ноль.** Ни одного нажатия Tab, ни одной проверки видимого
   фокуса, safe-area не проверяется. Мобильное покрытие — два дашборд-экрана.
5. **Три обязательных артефакта отсутствуют** (`AG-7-artifact.md`, `AG-7-artifact.json`,
   `AG-7-decision.md`). AG-7 прямо требует отдельных evidence для release artifact, pilot и
   release decision — сейчас их нет физически.
6. **Админ покрыт только в авторском контуре.** Витринные approve/freeze, топ-апы, возвраты,
   KYC, настройки существуют как vitest-тесты без артефактов прогонов; браузерного покрытия
   нет. Плюс роль админа в прогоне выставляется прямым `UPDATE`, а не через интерфейс.
7. **Артефакты прогонов старше кода.** `author-browser-results.json` — от `93be317`-линии;
   последующие коммиты AG-6 (`1919ca6`, `d2149b9`) браузерный контур не трогали, но при
   общей ветке это нужно подтвердить отдельным прогоном перед приёмкой.
