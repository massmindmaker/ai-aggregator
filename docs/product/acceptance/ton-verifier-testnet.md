# TON verifier/recovery: локальная приёмка и внешние ограничения

Дата: 29.09.2026. Продукт: только AI Aggregator.

## Что входит в этот пакет

Task5 соединяет проверенный native-кандидат, неизменяемое наблюдение и прежнюю SQL-функцию начисления только в явно внедрённом тестовом контуре. Task6 подключает к общему worker наблюдатель. По умолчанию режим `disabled`: TON не создаёт соединение БД, провайдера или таймер. Это не обещание отсутствия существующего Redis у остального worker.

`observe` требует точных pins: `tvm:-3`, native TON, provider `toncenter-v3-testnet`, origin `https://testnet.toncenter.com`, verifier `aiag-toncenter-v3-verifier-v1`, finality policy `toncenter-v3-testnet-provider-attested-mc-depth-2-v1`, корректный серверный PostgreSQL URL. Неизвестный режим, `settle` и jetton отвергаются. Секреты не изобретаются и не попадают в сообщения об отказе запуска.

Текущий worker index принадлежал принятому Recovery Task3 (`5363069`), затем принятому batch-пакету (`b949c80`). Перед изменением его байты сверены с последним принятым состоянием. Добавлен один вызов после `loadSharedEnv`; текущие gateway/media/batch/crons не заменялись. Завершение ожидает результат TON close, не дублирует остановку при двух сигналах и не объявляет неизвестный исход чистым завершением.

## Границы достоверности

| Проверка | Что подтверждает | Статус |
|---|---|---|
| Pure verifier/provider fixtures | Разбор схемы, pins, цепочка свидетельств, причины отказа | Предыдущий принятый пакет; повторяется профильная регрессия |
| Одноразовая PostgreSQL + синтетический provider | Запись, дедупликация, потеря ACK, restart, lease takeover, одно начисление | Локальные сценарии выполнены |
| Worker bootstrap с заглушками внешних ресурсов | Default disabled, порядок env/start, отказ settle, остановка, безопасный журнал | Локальные сценарии выполнены |
| Автоматизированное независимое source review | Проверка предоставленных исходников отдельными контекстами Space Bunny Alpha | Task5 H/I и Task6 J: APPROVE; это не аудит человеком |
| Новый реальный read-only запрос провайдеру | Текущая доступность и схема реального endpoint | НЕ ВЫПОЛНЕН; отдельное разрешение |
| Успешный, aborted, bounced и late native transfer | Реальная testnet-транзакция, конечный результат и сохранность кредита | НЕ ВЫПОЛНЕН; нужен отдельно разрешённый signer/test funds |
| Jetton master/wallet/full path | Полный путь конкретного разрешённого токена | НЕ ПРИНЯТ; runtime native-only |
| Mainnet/production | Реальные деньги, пользователи, deployment и рабочие роли БД | НЕ ВКЛЮЧЕНО |

Полные численные результаты финального объединённого прогона находятся в свежем checkpoint; ранее выполненные проверки не объявляются заново проведёнными, если их не запускали.

## Денежная безопасность

Публичный пакет БД больше не экспортирует `settleTonInvoice`. Внутренний подмодуль доступен только выделенному bootstrap в текущем runtime-графе; bootstrap не использует функцию начисления. Отдельный fixture-вызов принимает только результат чистого верификатора после durable observation ACK. Ответы `settled`, `already_settled`, `review_required`, `evidence_conflict`, `not_found` проверяются по точной форме. Ошибка или таймаут не означает откат транзакции.

Счётчики `processed/pagesAdvanced` показывают только принятую часть страницы после подтверждённого cursor CAS. Это не финансовая статистика и не число платежей. Записи старше границы сканирования не включаются в обработанную часть. При потере lease до начисления вызов запрещён; при потере после совершённого начисления деньги не откатываются, но старая задача не продолжает работу. Повтор идёт через прежнюю SQL-идемпотентность.

Если основная операция уже остановлена, последующий сбой освобождения lease не скрывает её причину. При этом `mutationOutcome:unknown` сохраняется. При закрытии provider race просыпается от abort немедленно; незавершённая DB-операция ограничена10секундами, release ещё10, pool ещё5. Эти бюджеты относятся к TON-компоненту, не обещают новый общий SLA остановки всех старых очередей.

## Что требуется перед runtime settlement

Нужен отдельный пакет полномочий PostgreSQL с разными принципалами worker и Web/API. Отрицательные тесты должны запрещать Web/API прямой SQL-вызов начисления и обход через изменение event/decision/receipt/grant-таблиц, включая унаследованные и PUBLIC-права. Положительные тесты должны доказать worker settlement и повтор с одним начислением. Нельзя заменять это TypeScript-типом, внутренним импортом или переменной окружения.

Настройка рабочих credentials, ACL migration на production, реальный read-only запрос и переводы требуют соответствующих отдельных решений. Настоящие90исторических миграций в этой волне не переписывались.

## Повтор локальных проверок

Запускать в актуальном worktree, по одному тяжёлому прогону под общим `flock /tmp/ai-ecosystem-build.lock`. Основные проверки: worker TypeScript и build, строгий `apps/worker/tsconfig.ton-recovery-test.json`, TON focused-набор, owned native observation/settlement suite, прежнее TON core58 и общий unit suite. Native helper `scripts/with-native-test-services.sh` сам берёт блокировку: не удерживать внешний flock при его вызове.

Не включать `observe` на обычной машине лишь для проверки сборки: это разрешает read-only обращения к закреплённому testnet-провайдеру. Использовать предусмотренные синтетические fixtures и одноразовую БД. Отсутствие provider key само по себе не запрещает сетевые запросы.
