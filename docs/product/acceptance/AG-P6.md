# AG-6: восстановление и наблюдаемость — состояние и остаток

Дата среза: 30.09.2026. Ветка: `feat/ag-author-version-20260928`.
Этап AG-6 роадмапа: «для авторских запросов реализованы recovery сохранённого результата,
подтверждённое отсутствие списания, спор и возврат без нового inference. Opening balances,
общая observability и полноценный backup/restore rehearsal на отдельном стенде остаются
открытыми».

Этот документ фиксирует, что из этого реально закрыто локально, а что нет.
**Это не приёмка release и не подтверждение production-восстановления.**

## Что закрыто локально (проверено кодом и тестами)

### Recovery сохранённого результата без нового inference
- Операторское восстановление в авторском цикле: `docs/consolidation/2026-09-29-author-lifecycle-checkpoint.md`.
- Durable recovery наблюдений TON: `docs/consolidation/2026-09-29-ton-observation-recovery.md`
  (claim/cursor recovery, дедупликация, ограниченное завершение, отключённый bootstrap).
- Начисление/replay в тестовом контуре: `docs/consolidation/2026-09-29-ton-settlement-and-startup.md`.

### Спор, возвоз, отсутствие повторного списания
- Возвоз создаёт отдельную обратную запись; спор удерживает начисление; старые чеки не меняются
  при обновлении/откате модели (`2026-09-29-author-lifecycle-checkpoint.md`).
- Повтор старого платежа в восстановленной копии возвращает прежний receipt; незавершённый платёж
  можно начислить, не меняя источник (`2026-09-29-ton-roles-and-restore-checkpoint.md`).

### Backup/restore репетиция (локальный стенд)
- Код: `packages/database/scripts/ton-worker-restore.ts` — настоящие `pg_dump` / `pg_restore`.
- Тест: `packages/database/scripts/__tests__/ton-worker-restore.native.integration.test.ts`.
- Подтверждено: сохранены owners/ACL, сравниваются все таблицы рассматриваемых схем, права
  функций и точный снимок финансовых записей. Проверены неуспешная приёмка копии, потеря
  подтверждения CREATE и конфликт одноимённого объекта. Архив и собственная БД очищаются;
  чужой подтверждённый конкурирующий объект не удаляется.
- Источник: `3135690`; репетиция подтверждена независимыми review (APPROVE).

## Что НЕ закрыто — не выдавать за готовое

1. **Отдельный стенд восстановления.** Репетиция выполняется в том же тест-кластере, где уже
   существуют глобальные роли. Это **не** off-host / cross-cluster disaster-recovery аттестация.
   Не настраиваются регулярные backup и не заявляются RPO/RTO.
2. **Opening balances** при переходе на новую схему биллинга не подтверждены отдельной
   проверкой. Есть только `greatest(10000, duration)`-подобные правила в STT и точные снимки
   в репетиции; отдельного теста «баланс на момент cutover совпадает» нет.
3. **Общая observability** (tenant → run → request → charge, связывающая оплату/вызов/очередь
   для разбора спора) не принята. Отдельные счётчики и журналы есть в продуктах, но сквозная
   связка для оператора не подтверждена.
4. **Native-стенд Aggregator требует bootstrap+migrate.** Без миграций native-тесты падают с
   `relation "users" does not exist` — это выглядит как красный тест, но им не является.
   Хелпер `/tmp/ai-ecosystem-run` не пережил перезагрузку хоста и должен быть создан заново.
5. **Полный unit-прогон после волн 30.09** не выполнен: проверены только typecheck и
   сфокусированные наборы. Исторические прогоны (2683/2862/2897 PASS) относятся к более
   ранним коммитам и не переносятся автоматически.

## Критерий закрытия AG-6

- [ ] Репетиция `pg_dump`/`pg_restore` на **отдельном** стенде (другой кластер/хост-симуляция)
      с теми же сравнениями owners/ACL/снимка финансовых записей.
- [ ] Проверка opening balances: снимок до cutover совпадает после, первый расход списывается
      с корректного остатка.
- [ ] Сквозная observability-связка tenant → run → request → charge, позволяющая разобрать спор
      по одному идентификатору.
- [ ] Полный unit-прогон на актуальном коммите с зафиксированным exit code.
- [ ] Независимое ревью волны (сейчас Codex на cooldown до 04.10, используется ZAI GLM).

Runtime settlement по-прежнему `disabled`/`observe`; production-восстановление не заявляется.
