Дата20.09. Статус: implementation contract следующего AG-P1 пакета; реализация/приёмка ещё не выполнены. Base `116668e` после принятого embeddings `a587e88`/merge`4a5acdb`. Только local source/native; runtime/deploy/платные вызовы исключены. Superpowers SDD + Caveman, два владельца и один итоговый financial/TypeScript review, без повторного аудита принятых foundations.

## Research inputs → decision → acceptance → deferred

D03/D11 из production-continuation07.09: один подтверждённый usage и один расчёт. Source exploration текущего `routes/v1/completions.ts` показывает, что legacy уже преобразует prompt в user chat message; отдельного completions provider API здесь нет. Decision: явный ограниченный compatibility route поверх существующего reviewed `admittedChat`, с отдельной durable route identity и text_completion DTO. Никаких новых моделей, цен, provider research или фиктивного утверждения о нативном text-completions API. Acceptance: реальный mounted handler/adapter/PostgreSQL + mock network transport, точные деньги, restart/replay/recovery. Deferred: prompt batches, suffix/infill, echo/logprobs/sampling overrides, stream/BYOK и реальные provider activation.

## Frozen wire contract

- Новый явный HTTP mode `stored_chat_embeddings_completions`; сохраняет stored chat и embeddings, добавляет только POST `/v1/completions` и trailing slash. Старые `stored_chat_only` и `stored_chat_embeddings` оставляют completions501; legacy default не меняется. Прочие write routes/methods сохраняют restricted guards. Worker mode `stored_chat_embeddings_completions_v1` соответствует ровно новому HTTP mode и allowedRoutes `['chat','embeddings','completions']`; старые пары/defaultdisabled неизменны.
- Strict body: `model`, `prompt` — одна непустая well-formed Unicode строка, optional positive safe-integer `max_tokens`, optional `stream:false`, optional existing `aiag_mode`. Whole JSON body cap262144 bytes как chat. Whitespace сохранять. Отклонять `prompt:string[]`, token arrays, пустые строки, streamtrue, BYOK header и все остальные поля, включая `n,best_of,echo,suffix,stop,logprobs,temperature,top_p,user,seed`, до claim/admission/provider. Не имитировать batch через join.
- Единственный server-owned conversion: scalar prompt → `messages:[{role:'user',content:prompt}]`, optional max_tokens сохраняется, streamfalse. Provider request/quote/profile/usage ровно existing admittedChat; модель typechat и reviewed profile неизменны.
- Canonical fingerprint SHA256 UTF8 compact JSON: `[1,"completions","stored",model,requestedModeOrNull,declaredSessionIdOrNull,prompt,["absent"]|["present",maxTokens],false]`. Omitted streamfalse эквивалентен explicitfalse; omitted maxtokens отличается от explicit value, как chat. Idempotency/SID grammar existing, persisted unique scope включает routecompletions. Тот же key на chat/embeddings независим. Auth обязателен на replay; stored read предшествует fresh resolver/policy/pricing. TTL/tombstone прежние.
- Stored/public DTO exact keys: `{id,object:'text_completion',created,model,choices:[{text,index:0,logprobs:null,finish_reason}],usage:{prompt_tokens,completion_tokens,total_tokens,cached_input_tokens?}}`. `text` всегда string; accepted chat null content преобразуется в пустую строку, finish_reason сохраняется. `id/created/model/usage` сохраняются из sanitized trusted chat response, никаких supplier/provider/debug fields. Единственный choice, finish_reason stop|length|content_filter. При чтении durable route определяет parser; форму body не использовать как authority.
- Existing exact quote/retail/supplier rounding и caching policy неизменны. Отдельного тарифа/platform fee нет. Invalid provider response/usage ПОСЛЕ dispatch остаётся unknown held и не вызывает refund/redispatch; это не preflight rejection. SQL обязан проверить text DTO against trusted chat usage/profile before atomic persist.

## Minimal implementation seams

Не копировать третий финансовый executor и не создавать общий modalities framework.

1. `stored-chat-attempt.ts` получает только trusted dependency `admissionRouteKind?:'chat'|'completions'`, defaultchat. Capture/validate этот route до await, admissionArgs используют его, confirmed ACK проверяет route. Это не поле request body. Existing quote, single runPromise, bound mechanics, confirmed dispatch, usage capture, outcome/settlement неизменны. `persistOutcome` по-прежнему получает sanitized CHAT response; completions HTTP composition детерминированно проецирует его в text DTO перед sole `recordGatewayHttpOutcome`. Executor result response остаётся chat-shaped внутренним артефактом; HTTP200 разрешён только через authoritative stored read нового DTO. Tests доказывают defaultchat и explicitcompletions, mismatched routeACK не даёт dispatch.
2. Новые narrow `stored-completions-http-identity.ts`, `stored-completions-http-contract.ts`, `routes/v1/stored-completions.ts`. Детерминированный projector chat→text располагается рядом с DTO parser, не вызывает provider. Использовать существующий fresh chat resolver и policy. Для policy можно сузить тип входа identity к реально читаемым requestedMode/attemptBody, чтобы передать conversion; не выдавать durable completions identity за chat. PII проверяет scalar prompt через один usermessage. Whitelist/RU/provider/session guards сохраняются.
3. `http-storage-result.ts`, `http-storage.ts`, `http-terminal-recovery.ts`: добавить routecompletions и typed response parser, projection. Старые parser defaultchat и overloads сохраняются. Persist, readv1/v2, recovery используют trusted admission/request route. Generic writers остаются единственными.
4. Additive `0078_gateway_stored_completions.sql`, historical0077 и старше не редактировать. Изменить request route constraint, identity validator, admission route/model binding (`completions` требует modelTypechat), locked outcome/read/recovery guards. В route-aware response validator добавить exacttext branch; допускается построить временный chat-shaped DTO, проверить его existing chat validator, но вернуть SHA256 canonical ORIGINAL text body. Checked persisted cap остаётся1MiB. Двухаргументный chat overload не менять семантически. Quote/supplier functions не менять без реального route hardcode: их текущая chat-shaped арифметика уже подходит. Обновить только затронутые canonical SQL mirrors.
5. Worker parser/allowedRoutes/explicitbootstrap pair добавить completions; selectors требуют request.route=admission.route, success/outcome/result agreement. Existing stored modes сохраняют свои allowedRoutes. Unknown-dispatched никогда не выбирается.
6. `config.ts/server.ts`, current public catalog config guards: новый mode сохраняет текущую chat/embeddings availability. Каталожная primary operation для chat-модели остаётся chat.completions: новый route — compatibility endpoint, не новая модель/тариф и не новая обязательная DTO operation. Никаких новых обещаний внешнему strict consumer.
