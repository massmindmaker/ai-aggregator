# Stored embeddings: один законченный lifecycle

Дата: 2026-09-20. Статус: implementation contract, ещё не реализация/приёмка.
Root: `/home/bob/Projects/ai-aggregator`. Начать после финальной сборки текущего RUB+TON пакета; migrations 0074–0076 не редактировать. Этот пакет заканчивается mounted native proof и одним итоговым независимым financial/TypeScript review. Activation, deploy и платные inference calls вне пакета.

## Результат и граница

`POST /v1/embeddings` в новом явном `GATEWAY_HTTP_EXECUTION_MODE=stored_chat_embeddings` выполняет claim → reserve → dispatch grant → один provider POST → trusted usage + durable response → settle → replay. Режим `stored_chat_only` сохраняет embeddings 501, `legacy` остаётся default. Новый режим сохраняет stored chat и его прежнюю семантику. Остальные неподдержанные write routes остаются 501; legacy embeddings/failover в новый путь не попадают.

Одна candidate v1: `openai/text-embedding-3-small`, modelType `embedding` (подтверждён `routing/resolver.ts` и `database/src/schema/enums.ts`), routeKind `embeddings`. Upstream/adapter `openrouter`, provider endpoint `openai`, `only:['openai']`, `allow_fallbacks:false`, `require_parameters:true`. Контракт adapter: `openrouter-pinned-provider-embeddings-v1`. Контекст 8192 tokens на input, vector dimension 1536. Ни failover, ни redirect hop, ни retry после dispatch.

Metadata, прочитанные controller 20.09: [endpoints](https://openrouter.ai/api/v1/models/openai/text-embedding-3-small/endpoints), [embeddings API](https://openrouter.ai/docs/api/api-reference/embeddings/submit-an-embedding-request). Endpoints перечисляют OpenAI и Azure, OpenAI context 8192 и `supported_parameters:[]`; API описывает float/base64, dimensions и optional id. Это источник candidate capability, **не доказательство реального provider исполнения и не billing authority**. Локальная приёмка использует mock transport; реальная совместимость параметров и pinned endpoint остаётся отдельной эксплуатационной проверкой при будущей activation, не блокирует local acceptance.

## Замороженный request/response контракт

1. Строгий JSON body: `model`, `input`, optional `encoding_format:'float'`, optional `dimensions:1536`, optional `aiag_mode` из существующего списка modes. `input` — одна непустая строка либо 1–16 непустых строк; каждая до 8192 UTF-8 bytes, общий HTTP body до 262144 bytes. Отвергать token arrays, nested arrays, пустые строки/массивы, base64, другие dimensions, user/provider/routing overrides, неизвестные поля и BYOK header. Unicode должен быть well-formed; whitespace и порядок inputs сохраняются. Byte cap ограничивает ресурсы и не объявляется tokenizer proof.
2. Нормализовать input в ordered `readonly string[]`, defaults в `float`/1536. Adapter отправляет `encoding_format:'float'`, поле dimensions не отправляет, поскольку v1 принимает только default1536; transport assertion фиксирует это поведение. Provider policy полностью server-owned.
3. Positive response DTO: `{object:'list', model, data:[{object:'embedding',index,embedding:number[1536]}], usage:{prompt_tokens,total_tokens}}`. Ровно inputCount элементов, indices 0..N-1 в порядке запроса; каждый vector component — конечный JSON number. Сверять returned model с pinned model. Optional provider `id` проверять, если присутствует, и хранить только в trusted usage как `providerResponseId:string|null`; public DTO его не требует и не синтезирует. Provider costs/metadata/debug поля не выходят наружу.
4. Provider response читать с bounded byte reader: максимум 1048576 bytes, затем parse/validate; `Content-Length` сам по себе не authority. SQL сохраняет прежний canonical JSONB cap 1048576 bytes. Переполнение любого cap/невалидный ответ после dispatch означает unknown outcome, без фиктивной zero-charge записи. Не изменять float values при sanitation. Не обещать, что произвольные конечные числа всегда укладываются в canonical JSONB cap.
5. Trusted usage: safe integers `promptTokens>=0`, `totalTokens===promptTokens`, `promptTokens<=8192*inputCount`; внутренние `completionTokens=0`, `cachedInputTokens=0`. Никаких estimates/fallback-to-zero при отсутствии usage. Snapshot содержит billingRequestId, attemptId, выбранную candidate/profile identity, inputCount, dimensions, encodingFormat, reportedModel, optional providerResponseId и usage/formula версии. Prompt/input/vector не входят в quote, ledger, logs или PII telemetry.

## Identity, деньги и unknown outcomes

Canonical fingerprint — SHA-256 UTF-8 compact JSON tuple:

```text
[1,"embeddings","stored",model,requestedModeOrNull,declaredSessionIdOrNull,
 [input0,...],"float",1536]
```

Omitted defaults эквивалентны explicit defaults; scalar input эквивалентен одноэлементному массиву. Omitted mode сохраняет `null`, не подменяется текущим default key policy. Idempotency-Key grammar/digest и SID grammar ровно существующие chat правила. Scope unique остаётся `(org,key,route,billingMode,keyDigest)`: тот же key на chat не конфликтует с embeddings. Fingerprint mismatch — 409, без новой попытки. Auth обязателен на каждом replay. Перед fresh resolver/quote читается persisted result; изменение тарифа/model availability после успешного запроса не мешает replay. В payload БД сохраняется sanitized result на прежние168часов; после expiry остаётся tombstone, повторного provider call нет.

Frozen decimal strings из `model_upstreams` — единственный тариф. Использовать `parseCandidateBillingFacts`, `quoteEmbeddingMaximum`, `calculateTokenCharge`; не JS float, не внешнюю цену. Для `C=8192`, `N=inputCount`, input tariff `I` cents/1k и markup `M`:

| Величина | Формула |
| --- | --- |
| Retail reserve, microcredits | `ceil(I*C*N*M)` |
| Retail actual | `half_up(I*promptTokens*M)` через existing arithmetic с completion/cache0 |
| Supplier reserve, USD micro | `ceil(10*I*C*N)` |
| Supplier actual, USD micro | `ceil(10*I*promptTokens)` |

Supplier не вычисляется из retail; markup и retail rounding туда не входят. Сохраняются PostgreSQL BIGINT/decimal precision проверки. Zero reserve fail-closed; zero actual из корректного rounding допустим. Существующие formula identifiers можно сохранить: input-only является их частным случаем; новую семантику выделяют modelType/adapterContract и строгая embeddings shape. `actualChargePolicy.cachingDiscount='1'` фиксирован для embeddings, cache usage всегда0. Один frozen candidate, максимум целого batch; SQL перепроверяет цены, shape, границы и actual, а не доверяет вычисленному клиентом числу.

Тот же admission state machine и locks: confirmed claim ACK даёт право одному handle продолжить; confirmed dispatch grant с matching attempt/pricing даёт право ровно одному POST. ACK loss на claim/admit/dispatch/outcome/settle — reconciliation/pending, без fallback writer. Abort до dispatch может cancel confirmed held admission; с момента dispatch invocation отмена клиента не освобождает деньги и не прерывает запись результата. HTTP/provider error, timeout, malformed/missing usage, invalid vector, price-bound violation после dispatch остаются `dispatched` unknown: ни refund, ни redispatch, ни выдуманный usage. Документировать этот сохраняемый financial hold как operational limitation v1.

Atomic outcome writer сохраняет usage + supplier actual + sanitized response в одной транзакции; HTTP200 разрешён только через authoritative stored read после settled. Rejected/pending/expired/unavailable и fixed error DTO сохраняют semantics existing HTTP contract. Worker восстанавливает **только** `outcome_recorded` success с согласованным durable result; unknown dispatched он не разрешает.
