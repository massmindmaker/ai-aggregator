## 5. Технические требования к перестройке
1. **Алиасы вкладок в `parseHash`**: перед lookup добавить карту `ALIASES={gonka:'pack'… }` — точнее: `overview→overview(Z1)`, `features→agentmarket`, `tma→agentmarket`, `web→aggregator`, `design→design`, `video→pack`, `arch→platform`, `deploy→platform`, `gonka→pack`, `wave1→money`, `pack→pack`, `plan→roadmap`. Старые hash-ссылки (`#gonka::…`, `#wave1`, `#video`) ведут в новые зоны; deep-link путь после `::` не ломается.
2. **Ключи TODOS не переименовывать** — localStorage-чекбоксы `aiag_chk_<k>` привязаны к ключам (`membershipmint`, `p16e2e`, …). Блок TODOS переносится в Z1 as-is.
3. **Счётчик карточек** на навигации (`.ct`) считается из `t.cards.length` — при перестройке массива пересчитается сам, руками не править.
4. **Зона 3 с подразделами**: у TABS-зоны добавить поле `sub:[{id:'tma',name:'TMA'},{id:'webapp',name:'Web-app'}]` — рендер подразделов сделать опциональным чипом, движок chipsEl не менять.
5. **Бейдж «архив»**: расширить `cardEl` — поле `c.arch:1` рисует badge `архив` рядом с ty-бейджем (стиль `.badge.arch{color:var(--ink-faint);border-style:dashed}`).
