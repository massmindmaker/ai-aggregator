## Binding contract

New captureStoredChatHttpIdentity({body: unknown, idempotencyKey: unknown, declaredSessionId: unknown}) returns a detached deeply readonly object: contractVersion1, routeKind chat, billingMode stored, idempotencyKeyDigest, requestFingerprint, requestedMode (Mode|null), declaredSessionId (string|null), attemptBody (supported strict Task5 body with aiag_mode removed). It returns no raw idempotency key or caller billing identifier. Args are trusted composition values in the future; body remains untrusted.

- Idempotency key is required exact ASCII1..128, allowed A–Z/a–z/0–9/._:-. No trim, folding or Unicode normalization. Reject embedded/trailing newline and whitespace. Digest is SHA256 over exact UTF8 bytes, lowercase64hex. Missing/null/empty invalid.
- SID uses existing captureDeclaredSessionId exact contract: explicit null when header absent; invalid undefined/empty/whitespace/Unicode rejected. SHA fingerprint incorporates SID including null and case.
- Parse/detach through existing admission JSON safety helper before reading properties; reject accessors/prototypes/non-JSON values without invoking getters. Body supports only existing parseStoredChatBody fields plus optional aiag_mode enum auto/fastest/cheapest/balanced/ru-only. Remove only this explicitly accepted extension before reusing strict Task5 parser. Reject unsupported fields, streams true, tools/media/BYOK extensions and spoofed ownership/UUID fields; no silent stripping.
- Mode identity captures CLIENT INTENT: absent aiag_mode maps to null, explicit auto stays auto. This is a root clarification of gate A “requested routing mode”: never hash a mutable policy default. New execution later resolves requestedMode ?? currentPolicy.default_mode ?? auto. Read/replay fingerprint therefore stays stable when policy/default/catalog changes. Explicit null is invalid input. Absence and explicit mode differ.
- Fingerprint v1 uses a fixed documented JSON encoding built from explicit keys or tuple: version1, chat/stored, requested model slug, requestedMode/null, SID/null, ordered exact role/content messages, max_tokens presence and exact safe positive value if present, normalized stream false. Message order/text whitespace/Unicode, model, mode, SID and max presence/value are meaningful. Input JSON object key order and formatting are not; stream absent/false equivalent. Do not include raw key, trace/X-Request-Id, authenticated org/key (SQL scope handles them), current prices/provider/candidate/default max/policy revision or generated IDs.
- attemptBody preserves model/messages and max presence for existing Task5, normalizes stream false, excludes aiag_mode. Detached/frozen nested messages survive later caller mutation. No live model lookup or quote is needed; pass parsed model to existing strict parser. Existing public route still uses its current contract until separate cutover.
- All malformed input fails with one fixed sanitized bad-request error/code. No payload values/getter errors or raw key appear in errors/logs. No new generic serializer framework or public transport API.
