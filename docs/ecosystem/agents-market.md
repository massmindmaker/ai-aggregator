| AM-W7 | P1, W1…W6 | Разрыв межконтурных FK, перенос собственных данных по rehearsed runbook, независимый deploy; UX/support/recovery | 108/108 доказаны; недоступность Arena не мешает запуску агента |

Физический split данных делать после отключения cross-DB запросов: инвентаризация FK/владельцев → backup вне исходного хоста → репетиция на копии → freeze новых writes → перенос с counts/checksums и проверкой ledger → переключение → smoke → наблюдение. Откат определяется моментом возобновления записи: после новых writes нельзя просто вернуть старую БД без обратной синхронизации. Боевой cutover — отдельное согласованное действие.

Допущение v1: один полноценно поддержанный runtime (приоритет существующему Hermes-контурy), расширяемый интерфейс для остальных. Новые runtime-коннекторы, торговля iNFT и общий кооперативный memory-слой не входят в обязательный v1. Уже доступные трансферы должны оставаться корректными и исключать личную историю; если рекламируются как часть v1, для них заранее расширить обязательную матрицу, не оставлять скрытый недоделанный платный путь.

Существующее правило BYOK=0 для AIAG-моделей сохранить до явной смены политики. Возможную отдельную цену найма/инструментов показывать заранее; BYOK не означает разрешения выполнять чужие платные tools без лимита. Выручка inference у Aggregator и выручка агентского сервиса — разные экономические операции с общей корреляцией, а не двойное списание одной услуги.

**Контрольная демонстрация:** пользователь нанимает агента; run вызывает Aggregator своим service key; после timeout/retry остаётся одна корректная покупка услуги; владелец видит начисление; другой наниматель не видит историю; агент с пустым бюджетом не запускает платный upstream; тестовая версия попадает в Arena без секретов.

**Обязательное уточнение 06.09:** веб-версия и TMA — отдельные релизные поверхности. Добавить AM-W4a: web shell/auth/workspace/author/billing; AM-W4b: TMA auth/navigation/chat/launch/reconnect. Обе зависят от общего API и AM-W3, но могут выпускаться независимо. AM-W7 закрывается только после обеих. Оценка общей программы увеличивается на 15–30 инженерных дней до резерва; затем уточняется после инвентаризации существующего /agentmarket.
