## 1. МОДЕЛЬ СУЩНОСТЕЙ (ответ: шаблон vs наём vs клон)

| Сущность | Что | В БД | Содержит | НЕ содержит |
|---|---|---|---|---|
| **Шаблон** | Публичная СПЕЦИФИКАЦИЯ («чертёж»), не рабочая копия | `agent_templates` | name, system_prompt, tools[], model_slug, mcp_url, price | ключи, mcp-auth, память, история (исключены SELECT'ом) |
| **Агент** | Живой экземпляр, владелец = 1 юзер, крутится воркером | `agents` | спек + зашифр. ключи + своя память + бюджет | — |
| **Клон** | Агент, созданный из публичного шаблона. Владелец = клонирующий | `agents` (тот же) | спек шаблона (без ключей), своя чистая память | секреты/память создателя (NULL) |
| **Наёмный агент** | Запуск чужого агента БЕЗ владения | **в коде НЕТ** | — | — |

**Операции (что есть в коде / чего нет):**
- **Создать-из-шаблона** (`POST /templates/[id]/clone`) — LIVE, только free. Даёт ВЛАДЕЮЩУЮ копию.
- **Арендовать** (платный клон, рента автору) — API `/rent` готов, но `/clone` отдаёт 402 для платных → **разблокировать**.
- **Клонировать конкретного агента** (не шаблон, если создатель разрешил) — **НЕТ в коде** (клон только из templates). Нужен флаг `cloneable` на agents + роут, ИЛИ всегда publish→clone.
- **Нанять** (запуск-без-владения) — **НЕТ в коде**. Сегодня любая операция = клон. Нужна сессионная таблица + **память в namespace на нанимателя**, либо честно назвать «Установить».
- **Опубликовать** (`/publish`) — LIVE, шарит спек без секретов. **Передать** (iNFT) — LIVE (память пока не перешифровывается, STUB D-5).

🔴 **Терминология:** одна код-операция `clone` сейчас изображает 3 концепта → путаница имён (форензик: /templates под 4 именами). Нужны чёткие ярлыки: **Создать** (из шаблона) · **Арендовать** (платно автору) · **Скопировать** (агента напрямую) · **Нанять** (без владения).

## 2. ИЗОЛЯЦИЯ ТУЛОВ И ПАМЯТИ (ответ на вопрос «мои или общие создателя?»)

**При КЛОНЕ — ВСЁ ТВОЁ.** Клон получает только СПЕК (промпт, список тулов, модель, URL MCP), но НЕ: ключи создателя, его MCP-токен, его память, историю — всё NULL/пусто. Память привязана к `agent_id` (у клона свой uuid) → **чистая изолированная память с нуля**; ключи подключаешь свои (BYOK). Доказано кодом: `clone/route.ts` («cloner wires their own keys»), `publish/route.ts` («NEVER select …_encrypted, agent_memory, agent_runs»). MCP после клона = токен NULL → **нужен UI-алерт «подключи свой MCP-токен»**.

**При НАЙМЕ (если строим):** спек создателя read-only, ключ модели = AIAG-gateway (дебет нанимателя), MCP-auth создателя; **память ОБЯЗАТЕЛЬНО в namespace `(agent_id, наниматель)`** — иначе наниматели читают чужую память (OWASP LLM06). История — per-наниматель.

Источники изоляции: Blaxel multi-tenant, OWASP LLM06:2025, «Agent Spec» (arxiv 2510.04173), GPT-Store hire vs Dify clone.

## 3. СООТВЕТСТВИЕ HERMES (наши настройки vs реальный рантайм)

🔴 **Поправки к нашему канону (`/CLAUDE.md` устарел):**
1. **У Hermes ЕСТЬ REST API** (`POST /api/model/set`, `/api/jobs`, `/api/sessions` на `:8642`) — наш UI МОЖЕТ удалённо управлять Hermes-агентом. Старое «нет remote API» — неверно. (Нужен стабильный API-ключ — токен ротируется при рестарте.)
2. **Модели НЕ per-role:** Hermes = ОДНА главная модель (чат) + **11 aux-слотов** (vision, compression…). **image_gen и voice/TTS — это ТУЛСЕТЫ, не модели.** → наша «мультимодель» = чат-модель + vision-слот + image/voice как инструменты со своим провайдером (НЕ 4 равных слота модели).
3. **Изоляция юзеров = `hermes profile`** (свои порты/память/конфиг), один gateway-процесс, НЕ pod-на-юзера.

**Маппинг возможность Hermes → наш UI:**
| Hermes | Наш UI агента |
|---|---|
| main model + provider + base_url | «Чат-модель» (пикер + URL) |
| 11 aux-слотов | «Расширенные настройки модели» (коллапс) |
| toolsets (web/browser/image_gen/tts/code…) | тумблеры «Инструменты» |
| MCP (stdio/HTTP, include/exclude) | секция MCP (серверы + тулы) |
| SOUL.md (free text) | «Личность» = textarea (не структур. поля) |
| MEMORY.md+USER.md+FTS5 (НЕ вектор) | «Память» — просмотр/правка текста (не обещать «семантику») |
| approval manual/smart/off | «Безопасность» — радио |
| **Kanban + run-trace (богатые)** | **проксировать** — история задач + трейс |
| cron (fan-out, skill-инъекция) | «Расписание» |
| skills (agentskills.io Hub) | «Навыки» — каталог |
| 22 платформы из 1 gateway | «Каналы» (мы показываем только TG) |

**Гэпы:** у Hermes есть, у нас нет/заглушка — kanban (полный), богатый run-trace, approval-режимы, skills hub, 22 канала, profiles, voice. У нас есть, у Hermes нет — биллинг/кредиты, маркетплейс-шаблонов, crypto/TON, transferable-iNFT, budget-card (наши надстройки).

## 5. IA-РЕДИЗАЙН (предложения основателя — спроектировано)

### A. «Агенты» → 3 сегмента: **Нанять · Мои · Создать**
- **Мои** = текущий инбокс. **Нанять** = CharCard-сетка готовых агентов (клон/аренда, переиспользует templates API). **Создать** = из шаблона (рейл) / с нуля (`/agents/new`) / AI-builder (◷ R&D плашка).
- Реализация: `searchParams.tab` + segment в `app/agents/page.tsx`; для пустого инбокса дефолт = «Нанять».

### B. «Маркет» → **5 настоящих разделов** (развить, НЕ сворачивать)
`[Агенты] [Скиллы] [MCP] [Тузы] [Базы знаний]` — горизонтальный сегмент. ⚠️ Недавнее сворачивание в один чип было НЕ тем направлением. Скиллы/Тузы/MCP — **данные УЖЕ в коде** (`AVAILABLE_TOOLS`, `MCP_PRESETS`), нужен только листинг + честный статус (live/скоро). Базы знаний = ◷ фаза 3 с описанием.

### C. **Досье агента** `/agents/[id]` — блочное, всё видно
- Sticky-шапка: аватар + статус + метрики `[прогонов][баланс][последний]` + amber «Запустить».
- Табы: **Чат** (run-trace+composer) · **Конфиг** (блоки: Личность / Мультимодель◷ / Инструменты / Провайдер / MCP / Бюджет / Расписание — инлайн-правка по блоку) · **Активность** (История + **Канбан** переезжает сюда, доступен всем) · **Публикация** (publish + transfer + статы).
- Канбан с отдельного роута → sub-switch в «Активность» (старый роут = редирект).
