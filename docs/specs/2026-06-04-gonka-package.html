01 · Why fund a demand-side partner

Four reasons a host-funded network wins by backing us.

Gonka's incentive program is funded by compute hosts, who only earn when compute is consumed. So the strongest proposal isn't "cool tech" — it's measurable, retained, net-new usage. Here is the usage we bring.

①Distribution into your named region

Gonka's mission is serving regions kept "structurally dependent" on US/Chinese AI infrastructure. RU is exactly that region — OpenAI/Anthropic are largely card-and-geo-walled there. We are already live in that market, in Russian, with crypto-credit billing that sidesteps the card rails Western APIs require. You buy demand from your hardest-to-reach segment with zero new BD effort.

②Agents = sustained, repeat demand

A single agent isn't one inference — it's a loop: every run is multiple model calls, and agents run on schedules and across conversations. One onboarded builder becomes a recurring stream of completions. For a network whose economics depend on consumed compute, agent workloads are the highest-retention demand shape there is.

already built

③The access layer, not scaffolding

We already run a production OpenAI-compatible gateway with per-call metering, configurable markup, and white-label routing behind a single adapter interface. Adding Gonka was a new adapter file, not a new platform — and it already returns live completions (next section). You get a fully-instrumented front-end into a new audience for the cost of integrating, not building.

④A live delegated-wallet reference

Gonka's developer roadmap points at delegated wallets / agent accounts — spend within limits, no per-call signing. We already ship the enforcement layer: an atomic ledger with per-agent daily caps, per-call caps, tool allowlists, and one-tap revocation. Back it with a Gonka wallet and it becomes a working reference implementation of delegated agent compute spend.

Honesty guardrails (kept in the pitch on purpose). Our commission applies only to models we supply; a user routing their own provider — Gonka included — is charged zero, enforced in code. So we have no markup incentive to push Gonka; we route it because it's a genuinely good provider for our users. Gonka stays a provider, not a dependency: an outage fails over to a fallback row and never hard-breaks an agent. And we treat Gonka as metered, verifying real per-token cost before seeding price — no building on a number that's about to change.
