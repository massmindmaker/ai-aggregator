# Hermes-only движок — архитектура

> Решение основателя 2026-07-10: самопальный агент-луп удаляется, движок = **только Hermes**. Два пути: (1) **connect-your-own** — юзер сам поднял Hermes, TMA = интерфейс; (2) **managed** — юзер создаёт агента, мы автоматически поднимаем его инстанс/профиль Hermes на нашем VPS, тот же TMA = интерфейс. Наниматели = изолированные профили внутри инстанса владельца; свои скиллы/плагины подключать не могут (берут настроенное владельцем) — хочешь своё, создавай своего агента.
> Источники фактов: `scout16-hermes-profiles.md` (живой VPS `v2026.6.19-923-g1b75b3fd9` + доки NousResearch/hermes-agent), `scout15-worker-anatomy.md` (анатомия нашего воркера).

## Факты Hermes (проверено)
- **Профиль** = директория `~/.hermes/profiles/<name>/`: свои `config.yaml`, `.env`, `SOUL.md`, `memories/`, `sessions/`, `state.db`, `skills/`, `mcp_servers.*`, `cron/`, `auth.json`. **НЕ файловая песочница** — тот же ОС-юзер.
- **Скиллы и MCP — per-profile: ДА.** Подтверждено живьём (у разных профилей разные enabled-флаги и свои `mcp_servers`).
- **`base_url` + `api_key` — per-profile: ДА** (свои `providers.*` + отдельный `.env`). **Поле `model` в REST-теле игнорируется** — модель фиксируется server-side.
- **Провижининг профиля — только CLI:** `hermes profile create <name> [--clone-from <src>]`. REST `/api/profiles` → 404.
- **Мультитенантность:** дефолт — **процесс на профиль** (свой порт). Опция **multiplex** — все профили в одном процессе, роутинг по префиксу `/p/<profile>/...`.
- **RAM:** офиц. 4GB min / 8GB рекоменд. (на инстанс). Эмпирика VPS: gateway-процесс ≈300MB RSS, systemd `MemoryMax=550M`.
- **Изоляция памяти — открытый баг #4726 (P3, без PR):** holographic-провайдер пишет в общий `~/.hermes/memory_store.db` для всех профилей. На VPS активен провайдер `honcho`; делит ли он хранилище — **в источниках не найдено**.

## Факты нашего кода
- `agent-runner.ts` = 983 строки. LLM-луп: ~756-961 + `resolveUpstream` 134-206 + `callWithFallback`/`callModel` 362-423 + `runSubAgent` 486-557. Луп и инфраструктура **прошиты вместе внутри `runAgent`**.
- Очередь `agent-run`: продюсеры — TMA `agents/[id]/run/route.ts`, `scheduler.ts`. 12 из 40 TMA-роутов зависят от воркера.
- Дебет — `settleRun` (`db.ts:683-751`), зовётся только из `agent-runner.ts:855`, списывает `tg_user_balances` по `run.tg_user_id`.
- **Gateway не видит `tg_user_id`/`agent_id`** — дебетует org-баланс по единому `AIAG_GATEWAY_KEY`.
- `connection_type='hermes_managed'` — ветка в коде есть; `'hermes_own'` — только комментарий в миграции 0045, кода нет.

## Решения
- **D-H1 — биллинг переезжает в gateway.** Per-profile `api_key` = ключ нашего gateway, резолвится в `(agent_id, payer_tg_user_id)`; gateway дебетует `tg_user_balances`. Воркер денег больше не трогает. Обоснование: gateway — единственная точка, видящая usage Hermes.
- **D-H2 — воркер не умирает, становится control-plane:** очередь, cron, история, провижининг профилей (shell-out на CLI), поллинг `/api/jobs`, хранение секретов. LLM-луп удаляется.
- **D-H3 — наём = профиль:** `hermes profile create <agent>_<hirer> --clone-from <agent>` + собственный api_key + собственный `memories/`. Наниматель не правит скиллы/MCP: control-plane не даёт ему запись в config.
- **D-H4 — аренда профилей возможна ТОЛЬКО на managed.** Провижининг требует CLI на хосте; на чужом Hermes (connect-your-own) exec-доступа у нас нет. Connect-your-own = один агент = один пользователь, без сдачи в аренду. Показать ограничение в UI.
- **D-H5 — наём заблокирован до доказательства изоляции памяти.** Баг #4726 открыт. Спайк обязан проверить `honcho` на кросс-профильное чтение. Не изолирует → hire не включаем (OWASP LLM06, `SECURITY.md`).
- **D-H6 — модель фиксируется на профиль**, не на запрос. «Мультимодель per-role» через Hermes REST в текущей версии недостижим; смена модели = `/api/model/set`. Убрать обещание из UI, поправить канон.
- **D-H7 — режим процессов решает спайк.** Гипотеза: multiplex даёт один процесс на все профили (~300-550MB суммарно, а не на профиль) — тогда экономика managed радикально лучше. Мерить, не предполагать.

## Порядок работ
1. **Спайк R4** — числа (блокирует всё).
2. **D-H1** — gateway-биллинг по per-profile ключу (money-path: отдельная спека + Opus-ревью).
3. **Control-plane** — провижининг профилей + прокси REST + история.
4. **Вырезание лупа** — только после того, как control-plane закрывает функции лупа.
5. **UI** — два пути (свой / managed) + честное ограничение аренды (D-H4).

## Что ломается при удалении лупа (и чем закрывается)
tool-broker, MCP-подключения, память, история, mid-run бюджет-гейты, `call_agent` — все живут внутри `runAgent`. Аналоги в Hermes: скиллы/MCP — per-profile (есть), память — `memories/` профиля (изоляция под вопросом, см. D-H5), история — `sessions/`. Бюджет-гейты mid-run в Hermes **отсутствуют** → переносятся в gateway вместе с биллингом (D-H1). `call_agent` (суб-агенты) — аналога в источниках не найдено, функция под вопросом.
