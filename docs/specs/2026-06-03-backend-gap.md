# AIAG BACKEND — gap analysis (what is NOT done yet)

**Date:** 2026-06-03 · **Against:** `docs/specs/research/SYNTHESIS.md` (Waves 0–3, D-0…D-14)
**Method:** read the synthesis build order + the actual code in `apps/{agent-worker,tg-miniapp,web,worker}` and `packages/{api-gateway,database}`, then checked the three Wave-0 branches (`feat/wave0-d0-margin`, `feat/wave0-safefetch-defaultmodel`, `feat/wave0-d8-initdata`) against `master`.

**One-line state:** Wave-0 money-correctness + cheap-security work is **done on branches but NOT merged to master**. Wave 1–3 (deposit reconnect, jetton, real runtime, MCP, managed-Hermes, creator economy, delivery, character pipeline) is **almost entirely NOT built**. The largest user-facing gap: there is **no working money-in path** — deposit is TON-coin-comment client-poll only (no jetton/USDT, no server reconciler, no per-user addresses), so the whole prepaid-credit product rests on a hand-poll that loses funds in the documented failure modes.

## What's NOT backed (user-facing features with no working backend)

- **Topping up reliably.** The only money-in path is a client-poll of native TON coin matched by a text comment. No server reconciler → a user who closes the app before the poll succeeds may have paid and not been credited. No USDT jetton at all. **This is the #1 product hole.**
- **Connecting a non-OpenAI provider key (Anthropic/Google).** Schema + reader exist (migration 0026), but there is **no write route** to save a BYO key from the TMA, and **no native adapter** in the gateway — a saved Anthropic/Google key would 404. Effectively BYOK is OpenAI-compatible-only and not wired end-to-end.
- **Live/streamed agent replies.** Runs are async BullMQ; the run route is a stub that enqueues and returns 202. No SSE, no token streaming to the WebApp.
- **Agent semantic memory.** Only flat key-value TEXT (`agent_memory`); no pgvector recall.
- **Telegram delivery of results.** `bot-api.ts` raw-fetches `/sendMessage` and labels cost in "₽" (TMA is supposed to be credits). No Business mode, no per-user bot.
- **Creator earning from templates.** No publish/clone/lineage/payout tables at all; blocked on D-0 storing margin.
- **Gonka / managed-Hermes / MCP tools / character cards.** No backend code exists for any of these.
- **Per-call tool billing safety.** A paid tool (`image_gen`) inside a run that later fails is silently free, and tool spend can exceed the daily budget.
