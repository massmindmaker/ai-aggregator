# R-11 — Two-sided marketplace economy (creator monetization for agent TEMPLATES)

**Researcher:** senior staff eng (code-grounded + external)
**Date:** 2026-06-03
**Scope:** payout models for creator-published agent **templates** (Poe price-per-message + subscription rev-share; fees/holds/rails), publish/clone/remix with lineage + attribution, ratings, anti-abuse (sybil, fake usage), ranking by REAL usage (avoid the Virtuals tradable-token casino), and how all of it maps onto our crypto-credit ledger with **author payout IN credits**.
**Primary code read:** `packages/database/migrations/{0018_agents.sql,0019_ton_wallets.sql,0007_gateway_model_reviews.sql}`, `packages/database/src/schema/{earnings.ts,fraudFlags.ts,models-marketplace.ts}`, `packages/database/src/functions/settle-charge.sql`, `packages/shared/src/revshare.ts`, `apps/agent-worker/src/db.ts` (`settleRun`), `apps/tg-miniapp/src/lib/agent-templates.ts`, canon `docs/specs/2026-06-02-WHAT-WE-ARE-BUILDING.md`.
**External:** Poe creator monetization (price-per-message + subscription bounty, Stripe payout, 23 countries, $10 min), OpenAI GPT Store (engagement-pool, opaque, 25-conv/wk gate), Virtuals Protocol (tradable-token casino post-mortem), wash-trading / sybil detection literature.

---

## Summary

**We already own ~80% of the machinery — but it was built for the wrong product half.** `apps/web` has a complete, production-grade two-sided economy for AI **models** (Phase 14): `author_earnings` per-request accrual, `payouts` with KYC/tax/bank rails, **sticky-tier rev-share** (70/75/80/85% in `packages/shared/src/revshare.ts`), a 30-day hold (`available_at = NOW() + 30 days`), accrual wired *inside the settlement function* (`aiag_settle_charge` → `accrue_author_earnings` hook), ratings (`gateway_model_reviews`, 1–5, one-per-user), and fraud primitives (`fraud_flags`, `device_fingerprints`). **None of it is connected to the TMA agent-template world**, which is the actual subject of R-11.

The TMA side is a green field: `agents` (migration `0018`) has a `template_kind` *string* but **no author, no clone-lineage, no visibility, no publish, no ratings, no creator-earnings**. "Templates" today are **6 hardcoded built-ins** in `apps/tg-miniapp/src/lib/agent-templates.ts` — there is no creator-published template at all. The TMA money path (`settleRun` in `apps/agent-worker/src/db.ts`) debits the user and records cost, but has **zero author-side credit** and a load-bearing rule we must not break: **`if (isExternal) return`** (own-key/BYOK ⇒ charge 0).

**Core recommendation:** do **not** invent a new economy. Build the template economy as the **crypto-credit twin** of the existing web rev-share, with three deliberate divergences forced by the canon: (1) **author payout IN credits** to an internal `tg_user_balances` row (not RUB/Stripe — TMA is crypto-credit, two-entity boundary forbids fiat payout from the crypto half); (2) **rev-share is taken from OUR markup margin only, never from upstream cost** — the author is paid out of the spread the gateway already earns, so a template can never make us lose money; (3) **commission is zero on own-key runs** (the `isExternal` short-circuit), so creators earn only when the cloner uses an AIAG-supplied model — exactly the existing commission rule. Ranking is by **realized credit-margin from distinct paying clones**, never by a tradable token or raw run count — this is the explicit anti-Virtuals stance. Anti-abuse reuses `fraud_flags`/`device_fingerprints` plus a self-clone/self-run exclusion baked into the accrual hook.

## Key findings (with sources)

### F1 — A complete RUB rev-share economy already exists for web *models* (reuse the pattern, retarget the unit)

`packages/database/src/schema/earnings.ts` defines the full stack, already on prod (Phase 14):
- `author_earnings` — **per-request accrual** rows: `gross_rub`, `tier_pct_decimal`, `net_rub`, `author_share_rub`, `status` (`accruing|locked|paid`), and **`available_at`** (the hold clock).
- `payouts` — `amount_rub`, `tax_withheld_rub`, `net_paid_rub`, `method` (`card_ru|ip_account|ooo_account|smz_check`), encrypted bank details, `kyc_snapshot`, `tax_act_storage_key`, status machine `requested|processing|paid|failed|reversed`.
- `author_tier_history` — sticky-tier audit trail.

The rev-share math is pure + unit-tested in `packages/shared/src/revshare.ts`: tiers **70% baseline / 75% volume-sticky (3 consecutive months ≥ 100k RUB, hysteresis on the way down) / 80% self-hosted / 85% exclusive self-hosted**; `authorShareRub(marginRub, tierPct)`. **The share is computed on `margin`, not gross** — this is the design principle to carry over verbatim.

Critically, accrual is **inside the atomic settlement** (`packages/database/src/functions/settle-charge.sql:120-151`): after the org balance is debited, a guarded `BEGIN/EXCEPTION` block JOINs `requests → models`, takes `current_tier_pct(author)`, and inserts the `author_earnings` row with `available_at = NOW() + INTERVAL '30 days'`, `ON CONFLICT (gateway_request_id) DO NOTHING`. Two load-bearing properties: **(a) accrual only fires for `m.status='live'`** (the authoritative "does this earn" cutoff), and **(b) accrual failure cannot roll back settlement** (inner exception → `RAISE WARNING`, reconcile later). This is the exact shape the template hook should copy.

### F2 — The TMA template world has none of it; "templates" are 6 hardcoded built-ins

- `agents` (migration `0018_agents.sql`): columns are `tg_user_id, template_kind (VARCHAR 40), name, system_prompt, tools, model_slug, budget_rub_monthly, status`. **No `author_tg_user_id`, no `cloned_from`, no `published`/`visibility`, no `version`.** `template_kind` is a label, not a foreign key to a creator artifact.
- `apps/tg-miniapp/src/lib/agent-templates.ts`: `AGENT_TEMPLATES` is a static array of 6 entries (writer/coder/…), each a hardcoded `systemPrompt` + `suggestedTools` + `defaultModelSlug`. Grep for `publishAgent|clone` in `apps/tg-miniapp/{src,app}` → **no matches**. There is no clone code path; "create from template" just pre-fills a form.
- Canon (`WHAT-WE-ARE-BUILDING.md` §5, §8, §11-Этап 3) confirms templates (private/public, "share settings not data", clone) are **🔨 not built** — explicitly "таблицы спека и шаблонов" listed under "Чего ещё НЕТ". So R-11 is greenfield on the TMA side; there is no legacy to preserve, only a pattern (F1) to mirror.

### F3 — The TMA money path: where author-credit must hook in, and the rule that bounds it

`apps/agent-worker/src/db.ts` `settleRun()` is the single transaction that moves money on the TMA side. In one `sql.begin` (READ COMMITTED + guarded `UPDATE … WHERE <guard> RETURNING`, **no SERIALIZABLE/retry loop**):
1. `markCompleted` (writes `cost_rub`, tokens),
2. **`if (isExternal) return;`** — own-key/BYOK/external provider ⇒ no debit, **no markup, and therefore no author share** (canon §6 commission rule, `apps/agent-worker/CLAUDE.md`),
3. atomic daily-budget guard,
4. guarded balance debit on `tg_user_balances.balance_rub`.

`tg_user_balances` (migration `0019`) is a single-row-per-user prepaid balance, `balance_rub NUMERIC(14,4)`. **This is the credit ledger** (canon: the column is RUB today but the unit is *in-flux → crypto-credit*; `apps/tg-miniapp/CLAUDE.md` says target the credit unit, don't entrench ₽). **Author payout in credits = an `UPDATE tg_user_balances … balance_rub = balance_rub + author_share` on the author's row** — same table, same atomic pattern, no new payout rail needed. The hard constraint: author share can only be created on path (2)-not-taken, i.e. AIAG-supplied model via gateway `:4000`, where a markup margin actually exists.

### F4 — Poe's model: price-per-message + subscription bounty, platform covers inference, Stripe payout, low min

Poe (`creator.poe.com/docs`, `poe.com/blog/...`, TechCrunch 2024-04-09):
- **Price-per-message:** the creator sets a per-message price; Poe pays the creator that price *every time a user messages the bot*. Users see "compute points," creators are **paid in USD**. Poe **covers the underlying model inference cost** via its Bot Query API ("the cost of any model inference used by any bot you query will be automatically covered by Poe") — so the creator's per-message price is *margin on top of* a cost Poe absorbs. Dynamic pricing API lets price scale with input/output length/complexity.
- **Subscription rev-share:** a second stream — if a bot *causes* a user to subscribe, Poe earmarks **up to $20/user** (annual) / $10 (monthly) shared among the monetizing creators that drove the subscription.
- **Rails:** payout via **Stripe**, **$10 minimum**, **23 countries**, USD.

**Transposition for us:** Poe's "per-message price set by creator, platform covers inference" maps cleanly to our gateway markup, but with one safety inversion — **we do NOT let the creator set an arbitrary surcharge that we then have to honor**; instead the author earns a **share of the markup margin we already charge** (F1 design), so the floor is structurally non-negative for us. Poe's subscription bounty has **no analog** for us (we are prepaid-credit, not subscription) — drop it; the single mechanic is per-run margin share. Poe's $10/Stripe min becomes a **credit-balance threshold** (e.g. accrued credits auto-sweep into the author's spendable balance once past the hold; no external rail, so no real "minimum" is needed — but keep a dust threshold to avoid micro-row churn).

### F5 — GPT Store proves the failure mode to avoid: opaque engagement pool

OpenAI's GPT Store pays a US-only pool "based on user engagement," with a **25 conversations/week** gate, no published formula, no disclosed pool size. Community reports: **median <$100/quarter, <1% earn meaningfully.** The lesson: an **opaque, engagement-weighted central pool** kills creator trust and produces near-zero payouts for almost everyone. Our model must be **per-transaction, deterministic, and inspectable** (creator can see "this clone, this run, this many credits accrued to me") — which is exactly what the per-request `author_earnings` row already gives us, in contrast to GPT Store's black box.

### F6 — Virtuals Protocol is the casino to avoid: rank/reward by tradable token ⇒ speculation, not usage

Virtuals (datawallet, beincrypto, coinbureau, coinstats 2026): each agent gets a **bonding-curve-launched tradable token**; ranking/visibility tracked token market cap, not service usage. Documented outcome: **on-chain volume was dominated by bonding-curve speculation and secondary-market churn, not durable demand for agent services**; monthly protocol revenue collapsed from its Jan-2025 peak; "revenue does not cleanly accrue to token holders"; fear of "an influx of low-quality or speculative projects." Real-usage agents (Luna, AIXBT) were rare exceptions among thousands.

**Direct implications for R-11 (these are hard "do-nots"):**
- **No per-template token, no bonding curve, no tradability.** A template is a config artifact, not a security. Author reward is a **claim on realized credit-margin**, denominated in the same internal credit unit users spend — it is a *receivable*, not a tradable asset (also keeps us on the RU fiat entity per canon §6 two-entity boundary; tradable tokens would force the foreign crypto entity).
- **Rank by realized margin from distinct paying clones, not by volume or stake.** Wash-trading literature (Yale/arXiv) shows volume is the easiest metric to fake; the antidote is to weight by *distinct funded counterparties* and *net economic effect*, and to discount self-dealing — which is precisely what our `device_fingerprints` + funded-balance + self-exclusion can enforce.

### F7 — Ratings + anti-abuse primitives already exist (web side); reuse shape, add template scope

- Ratings: `gateway_model_reviews` (migration `0007`) — `rating 1..5 CHECK`, optional title/content, `is_hidden`, **`UNIQUE(user_id, model_slug)`** (one review per user per item), plus cached `models.cached_avg_rating` / `cached_review_count`. A `template_reviews` table is a near-verbatim clone keyed on `template_id` + `tg_user_id`.
- Anti-abuse: `fraud_flags` (`flag_type`: `multi_account|api_spike|payment_chargeback|suspicious_fingerprint`, severity, jsonb details, resolve trail) and `device_fingerprints` (FingerprintJS `visitor_id` + IP + user/agent, first/last seen). These are the sybil-detection substrate; they need a TMA-side population path (today they're web-only).

## Concrete recommendation

### A. Data model — the credit-native template twin (new TMA migration)

Add one migration (`00NN_template_economy.sql`, applied via `sudo -u postgres psql aiag` per `packages/database/CLAUDE.md` — app role can't ALTER):

```sql
-- The publishable artifact (settings-not-data, per canon §5).
CREATE TABLE agent_templates (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  author_tg_user_id BIGINT NOT NULL,
  slug          VARCHAR(80) UNIQUE NOT NULL,
  name          TEXT NOT NULL,
  description   TEXT,
  spec          JSONB NOT NULL,            -- persona/SOUL.md, model SLUGS (no keys), tools, MCP defs (no tokens), schedules (no chat-ids)
  default_model_slug TEXT,                 -- shown on the card with est. run price
  visibility    VARCHAR(10) NOT NULL DEFAULT 'private',  -- private | public
  status        VARCHAR(16) NOT NULL DEFAULT 'live',     -- draft | live | frozen | depublished
  parent_template_id UUID REFERENCES agent_templates(id),-- lineage (remix/fork)
  version       INTEGER NOT NULL DEFAULT 1,
  author_share_bps INTEGER NOT NULL DEFAULT 1500,        -- author's cut of OUR markup margin, basis points (default 15%)
  cached_avg_rating NUMERIC(3,2),
  cached_review_count INTEGER NOT NULL DEFAULT 0,
  clone_count   INTEGER NOT NULL DEFAULT 0,              -- denormalized, see ranking
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Lineage edge on the instantiated agent (who it was cloned from).
ALTER TABLE agents ADD COLUMN cloned_from_template_id UUID REFERENCES agent_templates(id);
ALTER TABLE agents ADD COLUMN cloned_from_version INTEGER;   -- pins attribution to a template version

-- Per-run author accrual — the crypto-credit twin of author_earnings.
CREATE TABLE template_author_earnings (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id   UUID NOT NULL REFERENCES agent_templates(id),
  author_tg_user_id BIGINT NOT NULL,
  agent_run_id  UUID NOT NULL REFERENCES agent_runs(id),
  cloner_tg_user_id BIGINT NOT NULL,
  margin_credits   NUMERIC(14,4) NOT NULL,   -- OUR markup margin on this run (NOT gross, NOT upstream cost)
  share_bps        INTEGER NOT NULL,
  author_share_credits NUMERIC(14,4) NOT NULL,
  status        VARCHAR(12) NOT NULL DEFAULT 'accruing', -- accruing | available | swept | reversed
  available_at  TIMESTAMPTZ NOT NULL,        -- hold clock (see §D)
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT uniq_run UNIQUE (agent_run_id)   -- one accrual per run = idempotency
);
CREATE TABLE template_reviews (              -- verbatim clone of gateway_model_reviews
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id UUID NOT NULL REFERENCES agent_templates(id),
  tg_user_id BIGINT NOT NULL,
  rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
  title TEXT, content TEXT, is_hidden BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT uniq_review UNIQUE (tg_user_id, template_id)
);
```

**Spec hygiene (canon §5):** publishing must strip secrets from `spec` — model **slugs only (no keys)**, MCP **defs without tokens**, schedules **without private chat-ids/paths**, and a secret-scan on skill scripts. Reuse the column split from the canon table (✅ shared vs 🔒 private).

### B. Payout model — author share of OUR margin, in credits (mechanics)

The single mechanic (drop Poe's subscription bounty — we have no subscription):

1. A run completes for an AIAG-supplied model. In the gateway/worker we already compute `cost` = `upstreamUsd × markup` (R-06: markup lives per-row, `pricing.ts`). Define **`margin_credits = charged_credits − upstream_cost_credits`** (the spread we keep). The author share is **`author_share_credits = margin_credits × share_bps / 10000`** — never a cut of upstream cost, never a cut of gross. Floor at 0; if `margin ≤ 0` (mispriced), author earns 0 (we never pay out of our own pocket).
2. **Where it hooks:** extend `settleRun` (`apps/agent-worker/src/db.ts`) inside the **same `sql.begin`**, after the cloner's balance debit and **only on the path where `isExternal === false`** and `agents.cloned_from_template_id IS NOT NULL`. Insert one `template_author_earnings` row (`ON CONFLICT (agent_run_id) DO NOTHING`). Mirror the web side's robustness: wrap the accrual in its own guard so an accrual failure **never rolls back the user debit** (the web `aiag_settle_charge` does this with an inner `BEGIN/EXCEPTION`; in `settleRun` use a try/catch that swallows accrual errors and logs, since the debit is the load-bearing write).
3. **Self-dealing exclusion (baked in):** skip the accrual when `cloner_tg_user_id == author_tg_user_id`. This is the cheapest, highest-value anti-abuse guard and must be in the hook, not a later batch job.
4. **Payout = credit sweep, not a fiat rail.** A repeatable job (BullMQ, same infra as R-06's catalog-sync) runs daily: for `template_author_earnings` rows with `status='accruing' AND available_at < NOW()`, atomically `UPDATE tg_user_balances SET balance_rub = balance_rub + SUM(author_share_credits)` for the author and flip rows to `swept`. Author-earned credits are **spendable inside TMA** (run their own agents, top up) — this keeps everything on the RU fiat entity and avoids the crypto-payout/KYC problem entirely. Cash-out to fiat/crypto is explicitly **out of scope** until the two-entity legal structure exists (canon §6, §12).

> Why share-of-margin and not Poe-style creator-set price: a creator-set surcharge means we owe the creator a number we don't control and must reconcile against a cost that floats with the provider; a margin share is *structurally* bounded by money we already collected. It also composes with R-06's per-row markup and the `isExternal ⇒ 0` rule without touching either.

### C. Publish / clone / remix with lineage + attribution

- **Publish:** `POST /api/tma/templates` — snapshot the author's agent `spec` (after secret-strip), set `visibility='public'`, `status='live'`, `author_tg_user_id = caller`. Versioned: editing a live public template bumps `version` and keeps old clones pinned to their `cloned_from_version` (attribution stability — Remix-3D-style version lineage from the external research).
- **Clone:** `POST /api/tma/agents { from_template_id }` — copy `spec` into a new `agents` row, set `cloned_from_template_id` + `cloned_from_version`, `clone_count++`. The clone's **runs accrue to the template author** via §B as long as the cloner uses an AIAG model.
- **Remix/fork:** clone a public template *as a new template* with `parent_template_id` set — full lineage chain. **Attribution-only by default (no recursive royalty stacking)**: the *direct* `cloned_from_template_id` author earns; ancestors get **credit-attribution on the card** ("remixed from X → Y") but **not a cut**. Recursive royalties are a known complexity/abuse magnet (infinite-chain fee farming) and Poe/GPT-Store don't do it — defer multi-hop royalty splits as an open question (§Open). Lineage is displayed; money flows one hop.

### D. Holds, fees, reversals

- **Hold:** copy the web side's `available_at = NOW() + INTERVAL '30 days'` (`settle-charge.sql:145`). Rationale identical: covers the topup-confirmation/chargeback window before credits become the author's. (TON topups are server-verified via TonCenter, but the deposit-watchdog gap R1-6 means a hold is prudent.)
- **Platform fee:** implicit — the platform keeps `margin × (1 − share_bps/10000)`. Default `share_bps = 1500` (author 15% of margin) as a conservative launch number; tune later. **Do not hardcode in code** — it lives per-template (`author_templates.author_share_bps`) so we can A/B and grandfather, mirroring the "markup is per-row, never hardcoded" rule (`pricing.ts`, global `CLAUDE.md`).
- **Reversals:** if a run/topup is later flagged (chargeback, fraud), flip the matching `template_author_earnings` row to `reversed`; if already `swept`, debit it back from the author's balance with the same guarded `UPDATE … WHERE balance_rub >= x RETURNING` pattern (clawback can fail safely if the author already spent it — then carry a negative reconciliation row, never force balance negative).

### E. Ranking by REAL usage (the anti-Virtuals core)

Rank public templates by a **usage-and-margin score**, never by a tradable token, raw run count, or stake:

```
score = w1 * distinct_paying_cloners_30d         -- breadth of real demand
      + w2 * realized_author_margin_credits_30d  -- depth of real economic value
      + w3 * bayesian_rating(template_reviews)   -- quality, shrunk toward global mean
      - w4 * abuse_penalty                        -- sybil/self-deal signal from §F
```
- **`distinct_paying_cloners`** counts cloners whose runs *actually debited a funded balance* (excludes own-key/`isExternal` runs — those produce no margin, so they cannot be farmed for rank) **and** are distinct by `device_fingerprints.visitor_id` + funded `tg_user_balances`. This is the wash-trading antidote: faking rank requires N distinct funded accounts on N distinct devices, each spending real credits that net us margin — i.e. the attack *pays us* and is self-limiting (the exact failure of Virtuals' free-to-churn token volume is structurally impossible here).
- **Bayesian/shrunk rating** (not raw avg) prevents a single 5-star self-review from topping the board; use `cached_review_count` as the shrink weight.
- Recompute `score` in the same daily BullMQ job that sweeps payouts; store on `agent_templates` for cheap sort. **Never expose a "market cap" or tradable price** anywhere in the UI.

### F. Anti-abuse guardrails (sybil, fake usage)

1. **Self-exclusion in the accrual hook** (§B-3) — author ≠ cloner, enforced at write time.
2. **Funded-real-spend gate** — only runs that debit a funded `tg_user_balances` (margin > 0) accrue and count for rank. Own-key runs and zero-cost runs are economically inert for the author. This makes "fake usage" cost the attacker real money that becomes our margin.
3. **Device/IP sybil clustering** — populate `device_fingerprints` from the TMA (today web-only); raise a `fraud_flags` row (`flag_type='multi_account'`) when M clone-accounts share a `visitor_id`/IP and concentrate runs on one author's templates. Discount or freeze those accruals (`status='reversed'`) pending review.
4. **Velocity / api_spike** — reuse `fraud_flags.flag_type='api_spike'`; cap per-cloner accrual rate and flag implausible run bursts on a new template.
5. **Rating integrity** — `UNIQUE(tg_user_id, template_id)` (one review per user) + only allow a review from a user who has **actually run a clone** (gate on existence of an `agent_runs` row), killing drive-by review farming.
6. **Manual freeze** — `agent_templates.status='frozen'` mirrors `models.status` and immediately stops accrual (the hook should filter `status='live'`, exactly like the web hook filters `m.status='live'`).

## Risks

- **₽-vs-credit unit drift.** `tg_user_balances.balance_rub` is RUB-named but canonically migrating to crypto-credit (both TMA CLAUDE.md files). If the author-credit sweep and the cloner-debit ever run in different units, authors are paid 1000×-class wrong. Mitigation: **one unit, one table** — author share and user debit both touch `tg_user_balances` in the same unit; do the unit migration once, globally, before launch (coordinate with R-06's cost-mapping and the open double-ledger decision).
- **Margin definition is load-bearing.** If `margin_credits` is mistakenly computed as gross or includes upstream cost, the platform pays creators out of cost and loses money on every run. Mitigation: compute `margin = charged − upstream_cost` at one place, floor at 0, unit-test it, and add a CI assertion `author_share ≤ margin` always.
- **Breaking the `isExternal` short-circuit.** Adding the accrual must not move/soften the `if (isExternal) return` in `settleRun` (own-key = free, enforced rule). Accrual lives strictly *after* the debit on the non-external path. The `run-settle.integration.test.ts` must be extended to assert: external run ⇒ 0 author accrual.
- **Accrual rollback hazard.** A naive insert inside `settleRun` that throws would roll back the user's debit (all-in-one `sql.begin`). Mitigation: wrap accrual in try/catch (log + continue), as the web `aiag_settle_charge` does with its inner exception block — settlement must succeed even if accrual fails.
- **Sybil-by-real-spend residual.** A determined attacker *can* fund many accounts and run a template to inflate rank — but it costs them real credits and earns us margin, so it's self-funding for us; cap the upside with distinct-funded-device weighting and the 30-day hold so flagged rings can be reversed before sweep.
- **Recursive-remix fee farming.** If we ever add multi-hop royalties, chained forks become a fee-extraction abuse. Mitigation: ship single-hop attribution only (decision §C); revisit with explicit caps if creators demand it.
- **Prod migration discipline.** New tables/columns need `sudo -u postgres psql aiag`; migrations are manual/untracked — verify live prod state before assuming sequence numbers (`packages/database/CLAUDE.md`).
- **Templates aren't built at all.** R-11's economy presupposes the §11-Этап-3 template tables/clone path that canon marks 🔨 not-built. This research defines the economy layer; it cannot ship before the publish/clone substrate it sits on. Sequence: template substrate → economy hook.

## Open questions

1. **Default `author_share_bps`?** 15% of margin is a conservative placeholder. Needs a founder call balancing creator incentive vs platform margin (Poe lets creators set price; GPT Store pays a thin pool — we sit between). Tunable per-template by design.
2. **Multi-hop remix royalties — ever?** Recommend single-hop (direct cloner's author earns; ancestors get attribution only). Revisit only with hard anti-farming caps.
3. **Can author-earned credits be cashed out to fiat/crypto, or only spent in-app?** Recommend **spend-only** at launch (keeps everything on the RU fiat entity, no KYC/payout rail). Cash-out gates on the two-entity legal structure (canon §6, §12) — same blocker as x402 / user wallet.
4. **Double-ledger coordination (R1-4).** This design assumes the worker's `tg_user_balances` debit + gateway markup is the intended margin model. If the founder rules "single billing authority," the point where `margin_credits` is computed moves, and the accrual hook must follow it.
5. **Hold length (30d) appropriate for crypto topups?** Web uses 30d for chargeback cover; TON topups are non-reversible once on-chain, so a shorter hold may be safe — but the R1-6 deposit-watchdog gap argues for keeping 30d until topup confirmation is hardened.
6. **Do public templates need pre-publish human moderation** (like `models.status='pending_author_consent'`/`moderation`), given prompt-injection/secret-leak risk in shared `spec`? Recommend an automated secret-scan + a lightweight report-and-freeze flow rather than blocking review at launch.

## Adversarial review

**Reviewer:** adversarial staff eng (code-grounded re-read + external fact-check), 2026-06-03.
**Verdict: PARTLY holds up.** The strategic spine is correct and well-sourced — no token/no bonding curve (Virtuals), per-transaction deterministic accrual not an opaque pool (GPT Store), share-of-margin not creator-set surcharge, payout-in-credits to the same `tg_user_balances` row, self-deal exclusion + 30-day hold. The external facts (Poe price-per-message / platform-covers-inference / Stripe / $10 min / 23 countries; Virtuals bonding-curve revenue collapse from the Jan-2025 peak) all re-verified true. **But the single most load-bearing mechanic — the one every payout number depends on — is not implementable as written against the live code.** The recommendation should not be greenlit for build until the blocker below is fixed.

### BLOCKER — `margin_credits` is NOT computable in `settleRun`; §B-1 is fiction against the live worker

R-11 §B-1/§F2/Risk-2 all hinge on `margin_credits = charged_credits − upstream_cost_credits`, "computed at one place in the gateway/worker." **It is computed in neither, and the worker has no access to either side of that subtraction:**

- `settleRun` (`apps/agent-worker/src/db.ts:328-376`) receives **only** `costRub` — a single scalar. It never sees upstream USD, the rate, or the markup. There is no field to subtract from.
- That `costRub` is **not the gateway's charge at all.** The worker computes it locally via `estimateCostRub()` (`agent-runner.ts:223-227`) from a **hardcoded `PRICING` table** (`agent-runner.ts:99-108`) × `USD_TO_RUB = 90` (`:30`). This is the worker's *own* estimate, fully divorced from the gateway's real pricing.
- The gateway's *actual* cost math (`calcCostRub = upstreamUsd × rate × markup × batchDiscount × caching`, `packages/api-gateway/src/lib/pricing.ts:23-35`) runs **inside the gateway** and its result is **never returned to the worker.** The worker fires a chat-completion at `:4000`, reads `usage` tokens, and throws the gateway's price away.

So the TMA "margin" R-11 wants to pay authors out of **does not exist as a number anywhere the accrual hook can read.** Worse: because the worker's `estimateCostRub` already includes no markup and the gateway's markup is invisible to it, the worker debits the user its *own* estimate — the gateway markup is, on the TMA path, effectively **double-counted or lost depending on which key is live**, and on the documented `AIAG_GATEWAY_KEY`-unset fallback the run goes **direct to OpenRouter with zero gateway involvement** (`agent-runner.ts:84-94`), so margin is structurally zero. R-11 §F2's "faking rank requires real spend that nets us margin" assumes a margin the current TMA path does not realize.

**This is not a tuning detail — it inverts a stated safety property.** R-11 Risk-2 says "if `margin_credits` is mistakenly computed as gross … the platform pays creators out of cost and loses money." Against the live code that is the *default*, not the mistake: there is no margin number to floor, so any naive implementation pays the author a cut of the user's full charge (which on the fallback path is just OpenRouter cost) → **negative platform margin on every cloned run.** The recommendation acknowledges the risk in prose but its own §B-1 mechanic walks straight into it.

### Other material issues

1. **`agent_runs.cost_rub` is `NUMERIC(10,4)` but `tg_user_balances.balance_rub` is `NUMERIC(14,4)` and R-11's `template_author_earnings.margin_credits` is `NUMERIC(14,4)`.** A `FK agent_run_id → agent_runs(id)` with a 14,4 margin derived from a 10,4 cost is fine numerically, but R-11 never reconciles the precision/scale split, and its "one unit, one table" mitigation (Risk-1) silently assumes all three columns share scale. Minor, but it's exactly the class of drift that produces the "1000×-wrong" payout the doc itself flags.

2. **`authorShareRub(marginRub, tierPct)` returns `Math.round(marginRub * tierPct) / 100` (`revshare.ts:90-92`) — that is RUB-rounding-to-kopecks, not bps.** R-11 §A/§B switches to a `share_bps` (basis-point) model with `× share_bps / 10000`. That is a *reasonable* divergence, but R-11 claims it "mirrors" / "reuses the pattern verbatim" — it does not; it's a different rounding domain. Sub-kopeck/sub-cent micro-accruals on cheap runs will round to 0 under the web helper and to tiny dust under the bps model. The "dust threshold" (§F4/§B-4) is hand-waved with no concrete floor; without it, `template_author_earnings` row churn on sub-₽0.01 accruals is real (every tool-loop iteration of a cheap model).

3. **The web accrual hook accrues on `_total_rub` (GROSS), not margin.** Look at `settle-charge.sql:144`: `gross_rub … net_rub, author_share_rub` are all `_total_rub * _tier_pct` — i.e. the *existing production* author-earnings hook pays a share of the **gross charge**, NOT of margin. R-11 F1/§30 asserts twice that "the share is computed on margin, not gross … the design principle to carry over verbatim." **That is factually wrong about the code it cites as the template.** The pure helper is named `authorShareRub(marginRub,…)` but the SQL feeds it gross. So R-11's headline "carry the margin principle over verbatim from the web side" is carrying over a principle the web side does not actually implement. Either the web side has a latent over-payment bug, or R-11 misread it — either way the "verbatim reuse" claim is unsafe and must not be copied blindly.

4. **`isExternal`-test claim is sound but incomplete.** R-11 Risk-3 correctly says don't move `if (isExternal) return`. But it misses that the *provider-picker* path (`provider_id NOT NULL`, BYOK via `agent_provider_credentials`) sets `isExternal=false` (`agent-runner.ts:46-58`) while charging only `calcByokFeeRub()` (a fixed BYOK fee, markup-bypassed, `pricing.ts:37-40`). So a clone run on a BYOK provider is `isExternal=false` (would accrue under §B-2's condition) yet has **no markup margin** — only a flat fee. R-11's accrual condition (`isExternal===false && cloned_from_template_id IS NOT NULL`) would try to pay an author a share of a margin that is a fixed fee, not a spread. The hook needs a third gate: accrue only on the true gateway-markup path, excluding BYOK-fixed-fee.

5. **Concurrency mismatch with the cited web pattern.** R-11 §B-2 says "mirror the web side's robustness … inner BEGIN/EXCEPTION." But `settleRun` is explicitly **READ COMMITTED with no SERIALIZABLE/retry loop** (`db.ts:312-326`), whereas the web `aiag_settle_charge` serializes via `SELECT … FOR UPDATE` on the org row (`settle-charge.sql:51-56`). Wrapping an accrual `INSERT` in a JS try/catch inside `sql.begin` is fine, but R-11 conflates the two isolation models as "the same shape" — they are not, and the author-balance `UPDATE` it proposes (§B-4 sweep) touches `tg_user_balances` rows that are *also* the cloner-debit target, reintroducing the exact lock-ordering surface the worker deliberately kept simple. Sweep-job vs live-debit contention on the same table is unaddressed.

6. **`agent_templates.slug UNIQUE` + public publish = squatting / impersonation vector** unmentioned in §F anti-abuse. Global unique slugs across all authors invite name-grab and brandjacking; needs per-author namespacing or reserved-slug policy.

7. **Open-Q5 (hold length) leans on a half-truth.** "TON topups are non-reversible once on-chain, so a shorter hold may be safe." True for the chain, but the actual reversal risk R-11 itself raises (Risk re: clawback) is *fraudulent top-up / flagged ring*, which is independent of on-chain finality. 30-day hold is defensible; the stated rationale ("TON irreversible ⇒ could shorten") is the wrong reason and could mislead a future tuner into shortening it.

### Tightened recommendation

Keep the strategy (no token, per-tx deterministic accrual, credit payout, self-exclusion, real-spend-weighted ranking, single-hop attribution). **Before any build, close the blocker by making margin a first-class, gateway-authoritative number — do not let the worker invent it:**

1. **Gateway returns realized margin.** The `:4000` gateway already computes `upstreamUsd`, `markup`, and `cost`. Surface `cost_credits` AND `upstream_cost_credits` (or `margin_credits` directly) back to the worker per request (response header or a `gateway_transactions`-keyed lookup by `gateway_request_id`). The TMA worker must **stop using `estimateCostRub`/local `PRICING` for billing** on the gateway path — debit and accrue off the gateway's authoritative figure, or the user-charge and the author-share are computed in two unrelated unit systems.
2. **Accrue from `margin = gatewayCharge − gatewayUpstreamCost`, floored at 0, with a hard invariant test `author_share ≤ margin` AND `margin ≥ 0`.** Pass margin (not just `costRub`) into `settleRun`. If margin is unavailable (fallback-to-OpenRouter path, or gateway didn't return it) → **accrue 0**, never guess.
3. **Resolve the F1 contradiction first.** Audit whether the web `aiag_settle_charge` paying `author_share_rub = _total_rub × tier` (GROSS) is intended or a bug. R-11's whole "reuse the margin principle" framing is invalid until this is settled. Do **not** copy the web SQL hook verbatim — it accrues on gross.
4. **Add the BYOK gate:** accrue only when the run used the AIAG-markup gateway path (margin > 0 from a real spread), explicitly excluding both `isExternal=true` and `provider_id`-BYOK-fixed-fee runs. Extend `run-settle.integration.test.ts` to assert zero accrual on all three of: external, BYOK-fixed-fee, and gateway-fallback-to-OpenRouter.
5. **Specify the dust floor concretely** (e.g. no `template_author_earnings` row below a fixed credit epsilon; carry sub-threshold accrual forward in a per-(template,author) running remainder rather than writing churn rows).
6. **Namespace template slugs per author** (or add a reserved-slug + report-and-freeze flow) to close the squatting vector.
7. **Address sweep-vs-debit lock ordering** on `tg_user_balances` explicitly (sweep author credits in its own pass, never inside the cloner-debit tx).

Net: the *economics design* is right and the anti-casino stance is correct and well-evidenced; the *implementation claim* (§B-1 "margin computed at one place in gateway/worker") is false against the live code and is the single thing that, shipped as written, makes the platform lose money on every cloned run. Fix margin-authority first; the rest is sound.
