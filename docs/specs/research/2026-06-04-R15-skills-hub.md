# R-15 — Skills hub: format & sharing

> Research for wireframe screen 29 «Маркет скиллов». Investigates the emerging *Agent Skills*
> standard (SKILL.md / agentskills.io), how Anthropic Claude Skills + Hermes define and share
> skills, and maps it to OUR existing template-publish + 4-built-in-tools + per-agent-MCP model.
> Date: 2026-06-04. Sources cited inline with access date.

## 1. The emerging standard — `SKILL.md` / agentskills.io

**There is now a real, named, multi-vendor open standard.** A skill is **a folder with a
`SKILL.md` file**: YAML frontmatter (metadata) + Markdown body (instructions), optionally
bundling `scripts/`, `references/`, `assets/`. Originally authored by Anthropic, **released
as an open standard**, and published at **agentskills.io** with a formal spec, a reference
validator (`skills-ref`), and a GitHub repo (`agentskills/agentskills`).

Source: https://agentskills.io (Overview + Specification, accessed 2026-06-04).

### 1.1 The frontmatter spec (verbatim from the spec page)

| Field | Required | Constraint |
|---|---|---|
| `name` | **Yes** | 1–64 chars, `[a-z0-9-]` only, no leading/trailing/consecutive hyphen, **must match parent dir name** |
| `description` | **Yes** | 1–1024 chars; says *what it does AND when to use it*; keyword-rich for matching |
| `license` | No | license name or bundled-file reference |
| `compatibility` | No | ≤500 chars; env requirements (intended product, system pkgs, network) |
| `metadata` | No | arbitrary string→string map (clients store extra props here, e.g. `author`, `version`) |
| `allowed-tools` | No | space-separated pre-approved tools, e.g. `Bash(git:*) Read` (**experimental**) |

Minimal valid skill:
```markdown
---
name: pdf-processing
description: Extract PDF text, fill forms, merge files. Use when handling PDFs.
---
(instructions…)
```

Source: https://agentskills.io/specification (accessed 2026-06-04).

### 1.2 Progressive disclosure — the load model (the load-bearing idea)

Three stages, by token budget:
1. **Discovery** (~100 tokens): only `name` + `description` of every skill loaded at startup.
2. **Activation** (<5000 tokens recommended): full `SKILL.md` body loaded when a task matches.
3. **Execution** (as needed): `scripts/` / `references/` / `assets/` loaded only when required.

Keep `SKILL.md` <500 lines; push detail into one-level-deep reference files.
Source: https://agentskills.io/specification (accessed 2026-06-04).

### 1.3 Who adopted it (it is NOT just Anthropic)

The agentskills.io client showcase lists **40+ adopters**: Claude / Claude Code, **OpenAI
Codex**, **Gemini CLI**, Cursor, GitHub Copilot + VS Code, JetBrains Junie, OpenCode,
OpenHands, Goose (Block), Letta, Roo Code, Kiro, Databricks/Snowflake, Spring AI, Laravel
Boost, **nanobot** (a Telegram/Discord/Slack personal-agent with MCP + skills), and others.
This is a genuine cross-vendor format, not a single-product feature.
Source: https://agentskills.io (Client Showcase, accessed 2026-06-04).

### 1.4 How Anthropic Claude implements + distributes them

Claude scans available skills, loads only the minimal info/files when matched; works across
Claude apps, Claude Code, and the API. Distribution channels:
- **Claude Console** (API devs) + a `/v1/skills` endpoint;
- the **`anthropics/skills` marketplace** (Claude Code via plugins);
- **manual install** in `~/.claude/skills`;
- a partner directory at claude.com/connectors.

Security note from Anthropic: skills carry **code-execution** capability → *"stick to trusted
sources"*; the Code Execution Tool (beta sandbox) is required to run bundled scripts.
Source: https://claude.com/blog/skills (redirect from anthropic.com/news/skills, accessed 2026-06-04).

### 1.5 How Hermes implements them (directly relevant — Hermes is our intended core)

Hermes (`NousResearch/hermes-agent`) is **already agentskills.io-compatible** and ships a
full skills subsystem — this is the strongest signal for our roadmap because Hermes is the
runtime we intend to manage.

- Skills live in **`~/.hermes/skills/`** (source of truth), in category dirs, each skill a
  folder with `SKILL.md` + `references/` + `templates/` + `scripts/` + `assets/`.
- Frontmatter is the standard plus a Hermes namespace: `metadata.hermes.{tags,category,config}`,
  optional `platforms: [macos,linux,windows]`.
- **Three-level progressive disclosure**: `skills_list()` (~3k tokens) → `skill_view(name)` →
  `skill_view(name, path)`.
- **Invocation: `/skill-name [request]` slash commands** in CLI *and messaging platforms*
  (incl. Telegram) — plus natural-language via the `skills` toolset.
- **Skill bundles**: one slash command loads several skills together.
- **Hub commands**: `hermes skills browse | search | install <source> | check | update`.
- **Sources**: official repo skills, skills.sh (Vercel public directory), `/.well-known/skills/`
  endpoints, GitHub `owner/repo/path`, community hubs (ClawHub/LobeHub), direct SKILL.md URLs,
  and **custom "taps"** (`hermes skills tap add my-org/hermes-skills` = any repo with a `skills/`
  dir).
- **Security scanning is built in**: every hub skill is scanned for data-exfiltration, prompt
  injection, and destructive commands before install; `--force` overrides only non-dangerous
  findings.
- **Closed learning loop**: Hermes can *autonomously create a skill* after a complex task
  (5+ tool calls) via a `skill_manage` tool (create/patch/edit/delete/write_file).
- **Conditional activation**: `requires_toolsets` / `fallback_for_toolsets` hide a skill when
  the matching tool is (un)available (e.g. a DuckDuckGo skill only shows when no web toolset).

Source: https://hermes-agent.nousresearch.com/docs/user-guide/features/skills + repo README
(accessed 2026-06-04).

**Key takeaway:** "skill" in the standard = **a Markdown knowledge/instruction document with
optional bundled scripts**, loaded by progressive disclosure. It is *not* the same primitive
as our "tool" (a JSON function the model calls) or "MCP server" (a remote tool endpoint) — a
skill is the *connective procedural layer above* tools+MCP. The mature products treat all
three as complementary: skills tell the agent *how/when*; tools+MCP are *what it can call*.

## 2. What we have today (verified against code, 2026-06-04)

Our current model already contains the seeds of a skills hub — under different names.

### 2.1 The publish/clone flow (`agent_templates`)
- `0031_agent_templates.sql`: a template is a **share-spec, secrets-impossible-by-schema**
  row — `name, description, system_prompt, model_slug, tools (JSONB), mcp_endpoint_url,
  suggested_skills (JSONB), price_credits, visibility, fork_parent_id, clone_count`.
- There is **deliberately ZERO secret column** — no `*_api_key`, `*_auth`, `*_encrypted`. A
  provider key or MCP auth token *physically cannot leak* into a published template.
- Publish route (`agents/[id]/publish/route.ts`) snapshots only the share-subset; clone is
  FREE in slice 1, paid author-rent in slice 2 (`0032_template_rentals.sql`); ratings exist
  (`0033_template_ratings.sql`); author income tracked (`me/author-income`).
- **The template table already has a `suggested_skills JSONB` and a `tools JSONB` column** —
  the schema anticipated skills before the hub existed.

### 2.2 The 4 built-in tools (`apps/agent-worker/src/tools.ts`)
`web_search` (DuckDuckGo scrape, free), `calc` (sandboxed math, free), `image_gen` (Kie
nano-banana-pro, **8 credits/image**), `memory` (per-agent KV in Postgres, free). Selected
per-agent via `agent.tools[]` whitelist (`pickToolDefs`); empty = no tools. `code_interpreter`
is declared-but-intentionally-unimplemented (degrades gracefully, no arbitrary exec).

### 2.3 Per-agent MCP (`apps/agent-worker/src/mcp-client.ts`)
Read-only v1: one transient Streamable-HTTP client per run, SSRF-guarded `safeFetch`
(allowlist `[]`), empty client capabilities (no sampling/roots/elicitation), ≤32 tools,
15s timeout, 8k result cap. Tools namespaced `mcp__`. The agent stores `mcp_endpoint_url`
(shareable) + the auth token (NOT shareable, kept encrypted on the agent, never on template).

### 2.4 The runtime reality
Per `/CLAUDE.md` + `apps/agent-worker/CLAUDE.md`: the runtime is a **stateless BullMQ→gateway
loop**, no managed Hermes, no per-user process, no `~/.hermes/skills` dir, no file bundle
execution, no script sandbox. **We cannot today execute a skill's bundled `scripts/`** — and
SECURITY.md's eval-runner-nsjail-sandbox is still a TODO. This is the single biggest
constraint on how much of the standard we can adopt now.

## 3. Mapping the standard onto our product

| agentskills.io concept | Our nearest existing primitive | Gap |
|---|---|---|
| Skill = folder w/ `SKILL.md` (frontmatter + instructions) | `system_prompt` + `suggested_skills`/`tools` JSONB on a template/agent | We have no *first-class skill object*; instructions are baked into one prompt |
| `name` + `description` discovery metadata | template `name`/`description` | direct fit |
| Progressive disclosure (3-level lazy load) | n/a (we inject full prompt) | not needed at v1 scale; matters only if skills get large |
| Bundled `scripts/` (code exec) | `code_interpreter` (unimplemented), no sandbox | **blocked** — no script sandbox on a 2GB box |
| Bundled `references/` (knowledge docs) | none | a skill = a markdown doc we *prepend/attach* — trivially shippable |
| MCP server attach | our per-agent MCP (read-only) | direct fit — MCP **is** the "external tools" half of a skill |
| Hub browse/search/install + security scan | our template marketplace + publish/clone | direct fit — **our template hub already IS a skills hub minus the SKILL.md primitive** |
| Author rent / pricing | `price_credits` + rentals | direct fit; monetization already solved |
| `/skill-name` slash invocation (Hermes) | n/a (we run agents, not slash cmds) | only relevant once managed-Hermes ships |

**Core insight:** a "skills hub" is **not a new system for us — it is a re-labeling and
slight generalization of the template marketplace we already shipped.** A *skill* that is
"a knowledge doc + a set of built-in tools + an MCP endpoint" maps **1:1** onto fields we
already have (`description`, `tools[]`, `mcp_endpoint_url`, `suggested_skills`). The ONE part
of the standard we genuinely cannot do now is **executable bundled `scripts/`** (no sandbox).

So the honest framing for screen 29 «Маркет скиллов»: **a skill in OUR product v1 = a curated,
installable bundle of {built-in tools + (optional) a knowledge/instruction doc + (optional) an
MCP server}**, NOT arbitrary code. That is fully shippable on current infra and is exactly how
Hermes's own `fallback_for_toolsets` skills and MCP-backed skills already behave.

## 4. Thin v1 vs full community hub

### 4.1 Thin shippable v1 — "Каталог скиллов" (built-ins + MCP), NO new runtime
A read-only **catalog of installable capability bundles**, where each card is one of:
- **a built-in tool** (web_search / calc / image_gen / memory) — install = add to `agent.tools[]`;
- **a knowledge skill** = a `SKILL.md`-shaped markdown doc (frontmatter `name`+`description` +
  body) that we **prepend/attach to the agent's system prompt** on install (no code exec);
- **an MCP server** = a pre-vetted `mcp_endpoint_url` (user pastes their own auth token).

Mechanics — all reuse existing infra:
- **Storage**: add one table `skills` (or reuse `agent_templates` with a `kind='skill'`),
  schema mirroring the share-spec rule (NO secret columns). Adopt the standard's frontmatter
  fields verbatim: `name` (1–64, `[a-z0-9-]`), `description` (≤1024), optional `license`,
  `metadata.author/version`. This buys forward-compat + import/export of real SKILL.md files.
- **Install** = the existing clone/attach action: write the tool name into `agent.tools[]`
  and/or append the skill body to `system_prompt` and/or set `mcp_endpoint_url`. No new
  execution path, so **no new attack surface** beyond what MCP v1 already vetted.
- **Authoring/sharing** = the existing publish/clone/rent/rating flow, unchanged. Authors can
  set free or `price_credits` (author-rent model already built).
- **Built-in seed catalog** = the 4 tools + a handful of starter knowledge skills (e.g.
  «SEO-ревью», «Юридическая проверка», «Резюме встречи») as first-party SKILL.md docs.
- **Honesty labels (PRODUCT.md rule)**: `live` for built-in tools + MCP + knowledge skills;
  **`R&D`/`скоро`** badge on anything implying code execution / bundled `scripts/` — do NOT
  surface a runnable "scripts" skill until a sandbox exists.
- **Commission rule unchanged**: built-in image_gen debits credits; web_search/calc/memory and
  user-own MCP = 0 (BYOK rule).

This is ~1 migration + 1 list/detail screen + reuse of clone — days, not weeks, and ships on
the 2GB box.

### 4.2 Full community hub (deferred — needs the managed-Hermes runtime + a sandbox)
Everything the thin v1 *can't* honestly do:
- **Executable `scripts/` bundles** — requires the eval-runner **nsjail sandbox** (SECURITY.md
  TODO) or Daytona-per-tool (synthesis D-2). Hard-blocked on current infra.
- **`/skill-name` slash invocation inside Telegram** — only meaningful once managed-Hermes
  (with its native `~/.hermes/skills` + slash router) is provisioned per user. Deferred R&D.
- **Open community submission + import from external taps** (GitHub `owner/repo/path`,
  skills.sh, `/.well-known/skills/`, direct SKILL.md URL) with our own **security scan**
  (data-exfil / prompt-injection / destructive-command — mirror Hermes's scanner) before an
  install is allowed.
- **Progressive disclosure at scale** (3-level lazy load) — only needed once skills are large
  and numerous; irrelevant at v1 size.
- **Skill bundles + conditional activation** (`requires_toolsets`/`fallback_for_toolsets`).
- **Autonomous skill creation** (Hermes's closed learning loop) — far-future.

### 4.3 Recommendation (one line)
Ship **screen 29 as a "Каталог скиллов" v1 = catalog of {4 built-in tools + first-party
knowledge SKILL.md docs + vetted MCP servers}, installed via the existing clone/attach flow,
priced via the existing author-rent model, adopting the agentskills.io frontmatter verbatim for
forward-compat** — and **hard-defer** executable `scripts/`, slash-command invocation, and open
community submission behind an `R&D`/`скоро` label until a script sandbox + managed-Hermes
exist. This re-labels infrastructure we already shipped (template hub + tools + MCP) as a
standards-aligned skills hub with essentially zero new runtime risk.
