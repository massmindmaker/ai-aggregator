AIAG · синтез ресёрча · 12 пунктов · 2026-06-03

Архитектурные решения, порядок билда, риски, развилки для основателя

Главный вывод: денежный путь — это и есть продукт, почти каждый пункт ресёрча — про корректность денег. Два хребта: (1) починить единый биллинг-авторитет и заставить шлюз возвращать реальную маржу — прежде чем строить что-либо, что кому-то платит; (2) разрешить развилку Stars-vs-крипта — потому что продажа AI-кредитов за крипту внутри мобильного Telegram нарушает ToS и приводит к тихому делистингу. Адверсариальные ревью оказались сильными и поймали реальные дыры (маржа, стриминг с ₽0, обход дневного лимита, ложная изоляция, юр-инверсия).
Ключевые решения (D-0…D-14)
D-0Единый биллинг-авторитет + шлюз возвращает маржуhigh

Ключевое. Сейчас воркер сам выдумывает цену (хардкод × USD_TO_RUB=90) и выбрасывает реальную стоимость шлюза → маржи как числа не существует. Без этого тул-брокер и выплаты авторам теряют деньги на каждом прогоне. `tg_user_balances` = единственный леджер TMA; шлюз = white-label upstream + счётчик себестоимости.

D-1Кредит = USD (микро-USD integer); убить USD_TO_RUB=90high

1 кредит = 1 USD; ₽ только для отображения. FX-риск переезжает в маржу (COGS в ₽ по ЦБ, выручка в USDT) — закладываем в наценку/реконсиляцию.

D-2Managed-Hermes: Daytona-first, но экономику пересчитатьmedium

Daytona-сэндбоксы (kube-green отвергнут). НО ревью разнесло экономику: песочница изолирует только тулзы, а сам `hermes gateway` висит резидентно 300-600МБ на нашем хосте — «idle≈free» неверно. Реальный вопрос Phase-0: мультиплексит ли один gateway много юзеров. Daytona = shared-kernel, для публичных шаблонов нужен microVM.

D-3Control-plane Hermes: co-located sidecar + запись файлов, без форкаhigh

Дашборд Hermes = писабельный FastAPI (~50 эндпоинтов) на loopback БЕЗ токена. Sidecar дёргает его напрямую. SOUL.md — запись файла. Sanitizing-экспортёр (стрип ключей/памяти) для публичных шаблонов. `--insecure` — это footgun, не использовать.

D-4Gonka: GO, но как ОДИН опциональный провайдерhigh

Копия openrouter.ts→gonka.ts. GonkaGate комиссия 5%+10% (стакается на 1.25 → ~1.375). opengnk-прокси НЕ на прод-VPS (OOM убьёт money-path). Track 2b (хранить ключи юзеров) — вне скоупа без KMS.

D-5Реальный рантайм: AI SDK + pgvector + OTel, НЕ стримить биллинг-вызовmedium

Слой поверх существующего цикла (не выкидывать). Критично: OpenAI-стриминг возвращает usage:null → стрим биллинг-вызова рискует закрыть прогон в ₽0. Биллинг-вызов не стримим; фолбэк на оценку (никогда 0).

D-6Провайдер-каталог: один реестр (таблицы шлюза), нативные адаптеры в шлюзеmedium

Синк models.dev. Конверсия /1M→/1k при синке (самый вероятный баг ×1000). Дыра: BYO Anthropic/Google-ключ ломается при «воркер только OpenAI» → роутим ВСЕ нативные ключи через шлюз. Объединить два механизма BYOK.

D-7SSRF egress-guard (safeFetch) — строим ПЕРВЫМhigh

resolve-then-pin, HTTPS-only, блок ULA/mapped/CGNAT, ре-валидация на редиректах. Воркер фетчит user base_url с расшифрованным ключом без проверки.

D-8initData: ручной timingSafeEqual + 600s + Redis-нонсhigh

Ревью поймало: рекомендованная либа сама использует `!==` (не constant-time) → не чинит таймин-оракул. Чиним вручную + one-shot nonce против replay.

D-9Тул-брокер: reserve→execute→settle/refund сейчасhigh

Чинит реальную дыру: дорогой тул в упавшем прогоне не списывается. + фикс обхода дневного лимита (списание тула тоже инкрементит spent_today). Крипта не нужна.

D-10…D-14x402 (defer), MCP (outbound OAuth showcase), creator-economy (margin-share, blocked на D-0), grammY Business delivery, character pipeline (ambient→voice→talking)см. док

Детали и коррекции — в SYNTHESIS.md. Creator-economy: доля от МАРЖИ (не gross), выплата в кредитах, анти-казино (без токенов агентов).

Развилки для основателя
FD-1 · ГЛАВНЫЙ БЛОКЕР · противоречит прежнему решению

Telegram ToS запрещает продажу AI-кредитов за крипту внутри мобильного клиента → Mini App тихо делистят. Это против нашего «TON-only, без Stars».

Рекомендация ресёрча — Structure C: два рельса, единый невыводимый USD-кредит: Stars на мобиле (топап через desktop/web где комиссия ~3-4%, не 32%; учесть 21-дн холд + флор 1000 Stars), USDT/TON на web/desktop, BYOK = первоклассный compliance-лейн на мобиле (свой ключ = не продаём цифровой товар → Stars не обязателен). «Крипто-нативная мобилка» — НЕ рекомендуется (риск делистинга без маржи казино).

  • FD-2 — кредиты выводимые или строго невыводимый prepaid-SaaS? (невыводимый = вне VASP/e-money лицензий — самый сильный compliance-рычаг)
  • FD-3 — зарубежная юрисдикция + сплит юрлиц + локализация ПД РФ (152-ФЗ экстерриториален; текущий один зарубежный VPS с данными РФ-юзеров — несоответствие)
  • FD-4 — дефолт author_share (15% маржи — плейсхолдер)
  • FD-5 — кто платит при ответе агента в бизнес-чате клиента (Telegram Business)
  • FD-6/7/8 — комиссия Gonka (впитать/показать); talking vs ambient карта + стоковые vs клон-голоса; x402 self-host vs hosted (defer)
Сквозные риски
  • RK-1 2GB VPS — физический потолок; managed-Hermes-резиденты, pgvector-сборка, self-host observability/forge конкурируют с money-path. «Нужен второй бокс» — честный ответ.
  • RK-2 Маржа-авторитет = единая точка, от которой зависят ВСЕ денежные фичи. D-0 первым, инварианты `margin≥0` и `author_share≤margin` в CI.
  • RK-3 Telegram-ToS-стена против всей крипто-кредит-модели (см. FD-1). Плумбинг (леджер/реконсилятор/jetton) строить можно — он верен при обеих структурах; поверхность и валюта — founder-гейт.
  • RK-4 Двух-юрлицовая граница предполагается кодом, но не enforced (крипта/USDC/$-компьют на зарубеж; ПД РФ на РФ-инфре).
  • RK-8 Прод-миграции ручные/без трекинга; ₽→USD миграция живого баланса — самая опасная (freeze-window, dry-run на дампе).
