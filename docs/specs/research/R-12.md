# R-12 — Character portrait + voice pipeline (technique)

**Researcher:** senior staff eng
**Date:** 2026-06-03
**Scope:** the TECHNIQUE for generating CONSISTENT character portraits + short looping/holographic video character-cards from a single founder reference image, billed through our existing Kie path; plus per-character TTS voice. Faces themselves wait on founder references — this is about the repeatable pipeline.
**Primary code read:** `packages/api-gateway/src/upstreams/kie.ts` (live gateway adapter), `packages/upstream-adapters/src/adapters/kie.ts` (typed adapter, curated model list), `packages/api-gateway/CLAUDE.md`, wireframe `docs/wireframes/tma/characters-video.html`.
**External (verified 2026-06-03):** docs.kie.ai (nano-banana-pro image-to-image, kling-2.6 image-to-video, elevenlabs text-to-speech-multilingual-v2), kie.ai pricing pages, nano-banana consistency guides, fal.ai OmniHuman. Note: `kie.ai/*` marketing pages return 403 to WebFetch and `firecrawl` is down (404) — `docs.kie.ai` doc pages and WebSearch snippets were the working sources.

---

## Summary

The product already ships the exact wiring this pipeline needs: the gateway's Kie adapter (`packages/api-gateway/src/upstreams/kie.ts`) speaks Kie's **unified jobs API** (`POST /api/v1/jobs/createTask` → `GET /api/v1/jobs/recordInfo?taskId=…`), already routes `nano-banana*` and `kling*` model strings through the generic `jobs` family, already passes a `reference_image_url` for images and an `image_url` for video, and already strips brand markers per the white-label rule. So R-12 is **a content/technique recipe over an existing transport**, not new infrastructure — with two small adapter gaps to close (multi-reference array + an audio-driven avatar call).

The recommended pipeline is three stages, all on Kie, all async-job:

1. **Identity anchor (one-time per character):** take the founder's single reference photo → produce a small **character sheet** (front + 3/4 left + 3/4 right, neutral light) with **`nano-banana-pro`** (Gemini 3 Pro Image) using `image_input` (up to 8 reference URLs) + an explicit **identity-lock prompt**. This sheet — not the raw single photo — becomes the reusable reference set, lifting first-pass consistency from ~60-70% to ~85-90% per the public guides.
2. **Portrait generation (per scene/pose):** feed the 3-image sheet back into `nano-banana-pro` for every new portrait. Fixed `aspect_ratio: "9:16"` (vertical card), `resolution: "2K"`. **Caveat: Kie's nano-banana-pro exposes NO `seed` parameter** (confirmed in docs) — consistency comes from the reference sheet + prompt, not from seed locking. (Our typed adapter and gateway both accept a `seed` field, but Kie will ignore it for this model.)
3. **Holographic video card (per character):** image-to-video from the chosen portrait. Two distinct techniques depending on whether the card should *talk*:
   - **Ambient loop (no speech):** `kling-2.6/image-to-video`, `image_urls:[portrait]`, `duration:"5"`, `sound:false`, prompt describing subtle motion (breathing, hair drift, blink, holographic shimmer). Cheap, on-brand for a "living card."
   - **Talking portrait (lip-synced to the character's voice):** **Kling AI Avatar** (`image_url` + `audio_url`, up to 5 min) — drive it with the TTS clip from stage 4. ByteDance **OmniHuman** ($0.14/s on fal) is the fallback if Kie's avatar quality disappoints.
4. **Per-character voice (TTS):** **`elevenlabs/text-to-speech-multilingual-v2`** on the same Kie jobs API — pin one `voice` id per character, tune `stability`/`similarity_boost`/`style`, supports RU. Store the voice id on the character row. MiniMax-Speech / Qwen3-TTS are the open-weight fallbacks (zero-shot clone from a 3-second sample) if a founder wants a *cloned* voice rather than a stock one.

Net: one reference photo in → a reusable 3-pose sheet → consistent vertical portraits → a 5-second looping (or talking) holographic card + a fixed character voice, entirely through the Kie transport we already operate, billable through the existing gateway markup.

## Key findings (with sources)

### F1 — The transport already exists and already routes these exact models

`packages/api-gateway/src/upstreams/kie.ts` classifies any model string that is not `veo*`/`suno*` into the **`jobs` family** (`familyOf()`), which posts to `/api/v1/jobs/createTask` with body `{ model, input }` and polls `/api/v1/jobs/recordInfo?taskId=…` (`endpointsFor`, `createTask`, `pollOnce`). It parses the stringified `resultJson.resultUrls` / `videoUrl` / `imageUrl` out of the completed record (`extractUrls`). `imageGeneration()` already maps `reference_image_url → input.image_url`; `videoGeneration()` already maps `image_url`, `duration_s → duration`, `aspect_ratio`. So **`nano-banana-pro`, `nano-banana-2`, `kling-2.6/image-to-video` are reachable today** with no new endpoint code — only the `input` field names need to match Kie's spec (see F5/F6 gaps).
The curated typed adapter (`packages/upstream-adapters/src/adapters/kie.ts`) lists `nano-banana-pro` (`per_image: 0.015`), `nano-banana-2` (`0.008`), `kling-3.0`, `veo-3*`, `suno-v4-5`, `midjourney-v7` — so the catalog seam is already aware of these families. White-label is mandatory (`packages/api-gateway/CLAUDE.md`: "Never leak the upstream brand … in model metadata") — the card UI must surface "AIAG portrait", never "Kling"/"Gemini".

### F2 — Identity consistency is a reference-sheet + prompt technique, NOT a seed technique (for Kie nano-banana-pro)

Nano Banana Pro (Gemini 3 Pro Image) keeps identity via an internal "identity latent" — it maps a face to a stable latent fingerprint and edits only requested attributes ([prompting.systems](https://prompting.systems/blog/nano-banana-pro-character-consistency-guide), [chatsmith.io](https://chatsmith.io/blogs/ai-guide/using-gemini-nano-banana-consistent-characters-ai-images-00037)). Measured behaviour from the consistency guides ([laozhang.ai](https://blog.laozhang.ai/en/posts/nano-banana-pro-face-consistency-guide)):
- **~85-90% first-pass consistency** with a systematic reference sheet vs **~60-70%** from a bare single photo; proper workflow cuts regeneration ~30-40%.
- **Optimal 3-6 reference images** (front + 3/4 left + 3/4 right, ≥1024², face 30-50% of frame, even light). Consistency *plateaus at ~6 and degrades past ~10*. Model accepts up to 8 via the API and can track up to 5 characters.
- **Seed:** a fixed seed reportedly adds only "10-15%" and "does not guarantee identical output"; it helps during sheet creation, not production batches. **And on Kie's `nano-banana-pro` job there is no `seed` field at all** (F5). → Identity lock here is references + prompt, full stop.
- **Identity-lock prompt formula (verbatim from the guide):** *"Maintain the exact same facial features as the reference images — identical eye shape, nose bridge contour, jawline angle, lip proportions, and skin texture."* + scene details. Vague "same person" underperforms.
- Failure modes to guard against: eye-shape drift (too few angles), jawline change (uneven reference lighting), skin-tone shift (white-balance mismatch), expression bleed (over-strong expressions in references).

**Implication:** the single founder photo is the *seed input*, but the durable anchor is a generated 3-pose sheet. Generate the sheet once, store the 3 URLs on the character, reuse them as `image_input` on every later generation.

### F3 — Exact Kie API: nano-banana-pro image-to-image (verified docs.kie.ai)

Endpoint `POST /api/v1/jobs/createTask`, model **`"nano-banana-pro"`**, `input`:

| field | type | values | notes |
|---|---|---|---|
| `prompt` | string | ≤10,000 chars | required |
| `image_input` | array | up to **8** URLs | reference images; JPEG/PNG/WebP, ≤30 MB each |
| `aspect_ratio` | string | `1:1,2:3,3:2,3:4,4:3,4:5,5:4,9:16,16:9,21:9,auto` | default `1:1` → **use `9:16`** |
| `resolution` | string | `1K,2K,4K` | default `1K` → **use `2K`** |
| `output_format` | string | `png,jpg` | default `png` |

**No `seed`.** Source: [docs.kie.ai/market/google/pro-image-to-image](https://docs.kie.ai/market/google/pro-image-to-image). The reference field is **`image_input` (array)** — NOT the singular `image_url` our adapter currently sends (F5).

### F4 — Exact Kie API: kling-2.6 image-to-video + Kling AI Avatar (verified)

**Ambient loop** — model **`"kling-2.6/image-to-video"`**, `input`: `prompt` (≤1000), `image_urls` (array, **max 1**, JPEG/PNG ≤10 MB), `sound` (bool, required), `duration` (`"5"`|`"10"` sec, default `"5"`), optional `callBackUrl`. No `aspect_ratio`/`negative_prompt`/`cfg` — aspect follows the input image, so the 9:16 portrait yields a 9:16 clip. Source: [docs.kie.ai/market/kling/image-to-video](https://docs.kie.ai/market/kling/image-to-video).

**Talking portrait** — **Kling AI Avatar 2.0** (audio-driven): `image_url` (portrait) + `audio_url` (drives lip-sync + motion), up to **5-minute** continuous output, Standard (720p, cheaper) vs Pro (higher fidelity). Source: [kie.ai/kling-ai-avatar](https://kie.ai/kling-ai-avatar) + [docs.kie.ai/market/kling](https://docs.kie.ai/market/kling/image-to-video). Field name is **`image_url`** (singular) for the avatar family, distinct from `image_urls` for plain i2v — easy to get wrong.

### F5 — Two small adapter gaps (the only code work)

1. **Multi-reference array.** `kie.ts:imageGeneration()` sets `input.image_url = req.reference_image_url` (singular). nano-banana-pro wants **`image_input: string[]`**. The `ImageRequest` contract carries one `reference_image_url`. → add an optional `reference_image_urls?: string[]` to `ImageRequest` and, for `nano-banana*` models, write it to `input.image_input`; keep `image_url` for legacy single-ref models. Without this, only one of the three sheet poses reaches Gemini and consistency drops back toward the 60-70% band.
2. **Audio-driven avatar.** Plain `videoGeneration()` sends `image_url`+`prompt`+`duration` — correct for `kling-2.6/image-to-video` (modulo `image_urls` array name) but it never sends `audio_url`. For the talking card, add an `audio_url` passthrough on `VideoRequest` so `kling-ai-avatar` jobs can be created. (`kling-2.6` uses `image_urls` array, `kling-ai-avatar` uses `image_url` singular + `audio_url` — branch on model string, the adapter already does family branching.)

Neither needs a new endpoint; both are `input`-shape fixes inside the existing `jobs` family. The poll/extract path (`extractUrls`) already handles `videoUrl`/`resultUrls`, so the returned MP4 needs no new parsing.

### F6 — Per-character voice (TTS) on the same transport

**Primary: `elevenlabs/text-to-speech-multilingual-v2`** (Kie jobs API, [docs.kie.ai/market/elevenlabs/text-to-speech-multilingual-v2](https://docs.kie.ai/market/elevenlabs/text-to-speech-multilingual-v2)). `input`: `text` (≤5000), `voice` (voice id, e.g. `EkK5I93UQWFDigLMpZcX`), optional `stability` (0-1, def 0.5), `similarity_boost` (0-1, def 0.75), `style` (0-1, def 0), `speed` (0.7-1.2), `language_code` (ISO 639-1 — supports RU), `timestamps`. Returns a `taskId` → MP4/audio URL via the same `recordInfo` poll. **Pin one `voice` id per character row** = a stable per-character voice. Our gateway adapter doesn't yet expose `audioSpeech` through Kie jobs (the gateway `kieUpstream.audioSpeech` posts to the suno family path), so add an `elevenlabs/*` branch to the audio path, or just call the jobs family directly from agent-worker — it's the same `createTask` body.

**Fallbacks / cloned voices:** **MiniMax-Speech** (zero-shot clone from reference audio, no transcript, 32 langs incl. RU — [arxiv 2505.07916](https://arxiv.org/pdf/2505.07916)) and **Qwen3-TTS** (open-source, 3-second clone, self-hostable, claims to beat MiniMax/ElevenLabs on similarity — [github.com/QwenLM/Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS)). Use these only if a founder wants a *cloned* voice; stock ElevenLabs voices are simpler and avoid voice-likeness consent issues.

### F7 — Indicative unit economics (per character, per card)

Kie pay-as-you-go, no subscription ([technology.org](https://www.technology.org/2025/11/24/the-real-cost-of-nano-banana-pro-api-why-developers-choose-kie-ai-for-ai-image-generation/), [aifreeapi.com](https://www.aifreeapi.com/en/posts/nano-banana-pro-pricing-2k-4k)):
- nano-banana-pro: **~$0.09/image** at 1K-2K, **~$0.12** at 4K (our curated adapter's `0.015` row is stale — update). nano-banana-2: from ~$0.04.
- kling-2.6 i2v 5s: order ~$0.30-0.50/clip (Kling i2v tier; confirm in dashboard — hidden pricing per `kie.ts` gotcha).
- Kling AI Avatar: ~$0.056/s (Std) – ~$0.115/s (Pro) per [fal](https://fal.ai/models/fal-ai/kling-video/ai-avatar/v2/pro); OmniHuman ~$0.14/s ([fal](https://fal.ai/models/fal-ai/bytedance/omnihuman)).
- ElevenLabs TTS: per-character billing; a ~10s line is fractions of a cent.

A full character (3-pose sheet + 1 portrait + 1 five-second loop + one voice line) lands roughly **~$0.6-1.0 of upstream cost**, before the gateway's per-row markup. Treat as estimate — Kie media pricing is partly hidden until login (`kie.ts` comment: "hidden pricing … admin must set manually").

## Concrete recommendation

**Pipeline (all on Kie, all async via the existing gateway jobs path):**

**Stage 0 — Anchor (once per character).** Founder uploads ONE reference photo → S3 → URL. Call `nano-banana-pro` 3× (or one call per pose) with `image_input:[photoUrl]`, `aspect_ratio:"9:16"`, `resolution:"2K"`, prompts: front / 3/4-left / 3/4-right, each carrying the identity-lock sentence (F2). Store the 3 result URLs as the character's `reference_sheet` (jsonb). This sheet is the durable identity, not the raw photo.

**Stage 1 — Portrait (per pose/scene).** `nano-banana-pro`, `image_input:[sheet0,sheet1,sheet2]` (all three), `9:16`, `2K`, prompt = identity-lock + scene/wardrobe/lighting. Regenerate ≤2× if drift; pick the keeper.

**Stage 2 — Holographic card.** Default **ambient loop**: `kling-2.6/image-to-video`, `image_urls:[portrait]`, `duration:"5"`, `sound:false`, prompt = "subtle living-portrait motion: slow blink, faint breathing, hair drift, holographic edge shimmer, locked framing." For a **talking** card: generate the voice line (Stage 3) → `kling-ai-avatar` with `image_url:portrait` + `audio_url:voiceClip`.

**Stage 3 — Voice (per character, reusable).** `elevenlabs/text-to-speech-multilingual-v2`, fixed `voice` id stored on the character, `stability≈0.4`, `similarity_boost≈0.8`, `style≈0.2`, `language_code:"ru"`. Output audio URL feeds the avatar and/or plays under the card.

**Adapter changes (small, in `packages/api-gateway/src/upstreams/kie.ts` + `interface.ts`):**
1. `ImageRequest.reference_image_urls?: string[]` → for `nano-banana*`, emit `input.image_input` (array); keep `image_url` for others.
2. `VideoRequest.audio_url?` passthrough; branch `kling-ai-avatar` (`image_url` singular + `audio_url`) vs `kling-2.6/image-to-video` (`image_urls` array + `sound`).
3. Add an `elevenlabs/*` model branch to the audio path (or call `createTask` directly from agent-worker).
4. Refresh the curated price rows (`nano-banana-pro 0.09`, etc.) — current `0.015` is wrong.

**Data model:** add to the character/agent row: `reference_photo_url`, `reference_sheet_urls jsonb`, `voice_id`, `card_video_url`, `portrait_url`. Generation is async — store `taskId`s and reconcile on poll (the existing `recordInfo` loop).

**Why this stack:** zero new transport (reuses the live, white-labelled Kie jobs adapter and gateway billing); one provider for image+video+voice (simpler auth, one BYOK surface); the consistency lever (reference sheet + identity-lock prompt) is the empirically strongest one available given Kie nano-banana-pro has no seed; vertical 9:16 throughout matches the holographic-card wireframe.

## Risks

- **No seed on Kie nano-banana-pro.** Determinism is impossible; consistency is statistical (~85-90% with the sheet). Budget for ≤2 regenerations per portrait and a human "keeper" pick. If hard determinism is ever required, that needs a different provider (e.g., a Flux/LoRA character-LoRA path) — out of scope here.
- **Hidden / volatile Kie media pricing.** `kie.ts` already documents that some models have login-only pricing; the curated `0.015` nano-banana row is already stale vs the ~$0.09 public figure. Pricing must be admin-confirmed in the Kie dashboard, not trusted from code, before any user-facing markup is set.
- **Field-name footguns.** `image_input` (nano-banana, array) vs `image_urls` (kling i2v, array, max 1) vs `image_url` (kling avatar, singular) vs our adapter's current singular `image_url`. A wrong field silently drops references → identity collapse. Needs a per-model mapping table + a test asserting the array reaches Kie.
- **White-label leak.** Cards must never show "Kling"/"Gemini"/"ElevenLabs"; the `extractUrls` output and any error strings surfaced to the TMA must be sanitized (gateway CLAUDE.md hard rule). The MP4/audio URLs are Kie-hosted — re-host to our S3/CDN so the asset domain doesn't leak the provider.
- **Voice-likeness / face-likeness consent.** Cloned voices (MiniMax/Qwen) and avatars of real people raise consent/biometric concerns (and RU 152-FZ posture). Default to stock ElevenLabs voices + fictional/founder-owned faces; gate any real-person cloning behind explicit consent.
- **Latency / 2 GB VPS.** Each stage is an async Kie job (image seconds, video tens of seconds–minutes). The card build is multi-job and must run as a BullMQ pipeline with polling, never inline in a request. Re-hosting large MP4s must stream, not buffer, to avoid a memory spike on the shared box.
- **Avatar duration cost.** Talking avatars bill per second (5 min Kling Pro is large). Cap card length (≤5-10 s) for the marketplace; reserve long avatar clips for paid/explicit actions.

## Open questions

1. **Talking vs ambient as the default card?** Ambient loop is cheap and always-on; talking avatar is dearer and needs a script + voice per card. Which is the default product surface, and is talking a paid upgrade?
2. **Re-host policy:** do we mirror every Kie asset to our S3/CDN immediately (white-label + durability) or lazy-cache? Affects storage cost on the 2 GB box / S3 bill.
3. **Stock vs cloned voices:** ship a curated set of ~10 ElevenLabs voice ids (incl. RU male/female) for founders to pick, or allow per-character voice cloning (MiniMax/Qwen) with consent? Cloning adds a consent flow.
4. **Reference-sheet UX:** auto-generate the 3-pose sheet on character creation (cost up front, best consistency) or generate lazily on first portrait? Recommend up-front.
5. **Determinism need:** is ~85-90% consistency acceptable for the marketplace, or does any character demand pixel-stable identity (→ would force a LoRA/Flux path Kie can't give)?
6. **Card aspect/format:** confirm 9:16 2K is the holographic-card spec (matches `docs/wireframes/tma/characters-video.html`); confirm loop length (5 s) and whether the UI loops client-side or we bake a seamless loop.

## Adversarial review

**Verdict: holds up — partly.** The core architectural thesis (this is a content/technique recipe over the *gateway's* live Kie jobs adapter, with two small `input`-shape gaps) is correct and the verified API facts are solid. But two of the seven "key findings" lean on a misread of which adapter is which, the consistency numbers are vendor-blog marketing (not measured), the unit economics are understated by ~2-3×, and at least one named model (Kling AI Avatar) was never read in a working doc page — it's reconstructed from a 403'd marketing URL. None of this sinks the pipeline; it changes the cost story, the confidence framing, and one code-change line.

### What I independently re-verified (and it checks out)
- **Gateway transport (kie.ts).** Confirmed by reading the file: `familyOf()` routes anything not `veo*`/`suno*` to `jobs` → `POST /api/v1/jobs/createTask`, body `{ model, input }`, poll `/jobs/recordInfo`, `extractUrls` handles `resultUrls`/`videoUrl`/`imageUrl`. So `nano-banana-pro`/`kling-2.6/image-to-video` are reachable today. **True.**
- **nano-banana-pro API.** Re-fetched docs.kie.ai/market/google/pro-image-to-image: `image_input` array up to 8, `aspect_ratio` enum incl. `9:16`, `resolution` `1K/2K/4K`, **no `seed`**, `output_format png/jpg`. **All true.**
- **kling-2.6 i2v API.** Re-fetched docs: `image_urls` array **max 1**, `sound` bool required, `duration` enum `"5"`/`"10"`, no aspect param. **True.** Note the doc page contains *only* i2v — it does NOT document Kling AI Avatar (see issue 3).
- **F5 gap #1 (singular `image_url`).** Confirmed: `imageGeneration()` writes `input.image_url = req.reference_image_url` and `ImageRequest` carries a single `reference_image_url` (interface.ts line 54). Nano-banana-pro wants `image_input: string[]`. Real gap, real consistency hit if unfixed. **True.**

### Key issues

1. **F1/F7 conflate two different adapters — and cite the wrong one's price.** The report repeatedly says "our curated adapter's `0.015` row is stale" and treats `packages/upstream-adapters/src/adapters/kie.ts` as "the catalog seam [that] is already aware of these families." But that typed adapter is a **separate, older, non-jobs adapter**: its `submitAsync()` posts to `/api/v1/image/generate`, `/api/v1/veo/generate`, `/api/v1/suno/generate` — endpoints that are *not* the unified jobs API the live gateway uses, and that don't match the verified Kie spec (no jobs `input` wrapper, sends a flat `image_url` + `seed`). Its `CURATED_KIE_MODELS` list does not even contain `kling-2.6/image-to-video` (it has `kling-3.0`). So "the seam is already aware of these models" overstates readiness, and recommendation step 4 ("refresh the curated price rows in this file") would be **editing a dead/legacy adapter**, not the one in the money path. The price rows that matter for billing are `model_upstreams.markup` + the gateway registry, not this `CURATED_KIE_MODELS` array. Action: drop the "curated adapter" framing; the only code that ships is `api-gateway/src/upstreams/kie.ts` + `interface.ts`.

2. **F6 misstates the audio routing.** The report says the gateway "`kieUpstream.audioSpeech` posts to the suno family path," implying elevenlabs needs an endpoint change. Reading the code: `audioSpeech()` calls `createTask(req.modelId, …)`, and `createTask` routes via `familyOf(model)`. `familyOf("elevenlabs/text-to-speech-multilingual-v2")` returns **`jobs`**, not `suno` — so it already hits `/api/v1/jobs/createTask`. The endpoint is already correct. The *real* gap is the **`input` shape**: `audioSpeech()` emits `{ prompt, voice, format }`, but elevenlabs wants `{ text, voice, stability, similarity_boost, style, speed, language_code }`. `prompt` → must be `text`, and the voice-tuning knobs (the whole point of a per-character voice) are dropped on the floor. So the fix is field-mapping, not an endpoint branch — and it's a third real `input`-shape gap the report under-specified.

3. **Kling AI Avatar field names are unverified — and the report admits the source 403'd, then asserts the schema anyway.** F4/F5 state `kling-ai-avatar` takes `image_url` (singular) + `audio_url`, 5-min max. The header says `kie.ai/*` marketing pages return 403 and firecrawl is down; the i2v doc page I re-read does **not** contain the avatar schema.
