# R-03 — Gonka integration spike

**Status:** research complete · **Date:** 2026-06-03 · **Author:** staff-eng research subagent
**Unblocks:** Gonka grant deliverable #1 (`docs/specs/2026-06-03-gonka-grant-application-draft.md`).
**Scope:** verify Gonka's real OpenAI-compatible base URL(s), models, auth model, latency/reliability caveats, the `gonkalabs/opengnk` SDK, GonkaGate, delegated wallets; then give concrete steps to add Gonka (a) as a provider routed through OUR `:4000` gateway and (b) as a BYO-wallet free provider in the picker.

---

## 1. Summary

Gonka is a Layer-1 decentralized AI-compute network (token **GNK**, mainnet live since 2025-09-15). It is **OpenAI-compatible by design**, but there is **no single official hosted base URL** for app developers. Access splits into three concrete layers, and the right choice depends on whether we want zero-commission BYO-wallet or markup-through-our-gateway:

1. **Self-hosted `opengnk` proxy** (gonkalabs/opengnk, MIT, Docker) — exposes `http://localhost:8080/v1`, signs every request with **your GNK wallet** (secp256k1 private key), discovers nodes from `https://node4.gonka.ai`, and routes inference through Transfer-Agent-whitelisted nodes. This is the "pay in GNK / BYO-wallet" path.
2. **GonkaGate** (`https://api.gonkagate.com/v1`) — a managed broker. **API-key auth, prepaid USD balance, no wallet/crypto needed.** `$10` free credit on signup. This is the easiest "API key" path and the lowest-friction way to get the spike green.
3. **Other community brokers** — `proxy.gonka.gg`, `gate.joingonka.ai`, `router.gonkascan.com`, `gonka.pw`, `gonka-api.org`, `gonkabroker.com`, `gonkagate.com`. Each is an independent third party deciding its own pricing/SLA/models.

**Models:** only **`Qwen/Qwen3-235B-A22B-Instruct-2507-FP8`** is reliably live for mainnet inference today. Kimi K2.6 and MiniMax M2.7 have validated golden references and were being added via the DevShards mechanism (May 2026) but are not guaranteed broadly available. Treat the model list as **discovered at runtime via `GET /v1/models`**, never hardcoded.

**Reliability caveat:** the network went through a **DevShards migration (v0.2.12)**. The old proxy `gonka-gateway.mingles.ai` is flagged unreliable in our own grant notes; `node4.gonka.ai:8000` "can hang" per the opengnk README — use `https://node4.gonka.ai` (443, no port). During the ~180-epoch (~6 month) **Grace Period from mainnet launch, inference runs at zero GNK cost**, so cost modeling is provisional.

**Recommendation (TL;DR):** Spike with **GonkaGate API-key** path first (fastest green, no wallet ops), wire it as a normal markup upstream behind `:4000` exactly like `openrouter.ts`. In parallel, stand up the **self-hosted `opengnk` proxy** on the VPS for the **BYO-GNK-wallet = zero-commission** picker option. Do NOT make Gonka a dependency — it is one optional provider plus a grant.

## 2. Key findings (with sources)

### 2.1 Access model A — self-hosted opengnk proxy (BYO-wallet, pay in GNK)
`gonkalabs/opengnk` is a **Docker-based, OpenAI-compatible proxy** (MIT). It exposes a local `http://localhost:8080/v1` and signs every upstream call with a Gonka wallet, so the **client-side API key is ignored** ("any string works; auth happens server-side via wallet signatures"). [opengnk README]

- **Base URL exposed:** `http://localhost:8080/v1` (port via `PORT`, default `8080`).
- **Endpoints:** `GET /health`, `GET /v1/models`, `POST /v1/chat/completions` (stream + non-stream), `GET /` (web UI).
- **Run:**
  ```bash
  git clone https://github.com/gonkalabs/opengnk.git
  cd opengnk && cp .env.example .env   # edit credentials
  make run          # == docker compose up -d
  docker compose --profile sanitize up -d   # optional PII redaction
  ```
- **Env vars (exact):**
  | Var | Default | Purpose |
  |---|---|---|
  | `GONKA_PRIVATE_KEY` | — | hex secp256k1 single-wallet key (64-char) |
  | `GONKA_WALLETS` | — | `privkey:address,privkey:address,…` round-robin (takes priority over single key) |
  | `GONKA_ADDRESS` | derived | bech32 `gonka1…` account address |
  | `GONKA_SOURCE_URL` | `https://node4.gonka.ai` | node discovery gateway |
  | `PORT` | `8080` | proxy port |
  | `SIMULATE_TOOL_CALLS` | `false` | strip tool defs, inject system prompt, re-parse JSON → OpenAI tool format |
  | `NATIVE_TOOL_CALLS` | `false` | forward native tool calls (needs node with `--enable-auto-tool-choice`) |
  | `SANITIZE` | `false` | redact emails/keys/names before upstream |
- **Wallet/account setup (the `inferenced` CLI):**
  ```bash
  export ACCOUNT_NAME=my-gonka-account
  export NODE_URL=http://node1.gonka.ai:8000
  ./inferenced create-client $ACCOUNT_NAME --node-address $NODE_URL
  ./inferenced keys export $ACCOUNT_NAME --unarmored-hex --unsafe   # → GONKA_PRIVATE_KEY
  ```
  Fund via the Gonka.gg faucet (`https://gonka.gg/faucet`) or transfer GNK from a funded account.
- **Network routing:** proxy discovers active participants from `node4.gonka.ai`, filters to whitelisted **Transfer Agent** addresses (feature v0.2.9+), then routes inference through `https://node4.gonka.ai/v1`. Non-whitelisted nodes return `Transfer Agent not allowed`.

Sources: [github.com/gonkalabs/opengnk](https://github.com/gonkalabs/opengnk) · README (raw main).

### 2.2 Access model B — GonkaGate (managed broker, API key, USD)
GonkaGate makes Gonka "usable like a normal API product": **OpenAI-compatible, prepaid USD billing, no wallet/token ops.** [gonkagate.com]

- **Base URL:** `https://api.gonkagate.com/v1`
- **Auth:** single API key (`Authorization: Bearer <key>`). Register at `gonkagate.com/en/register`; **$10 free credit** on signup.
- **Billing:** prepaid USD balance; cost = network cost + GonkaGate platform fee; final USD spend shown in dashboard (not returned per-request in the API body).
- **Models:** see `gonkagate.com/en/models` (changes with the network).
- **Docs:** `gonkagate.com/en/docs/quickstart`, API ref `…/en/docs/api/reference/overview`, principles `gonkagate.com/en/docs/guides/overview/principles`.

Source: [gonkagate.com/en](https://gonkagate.com/en).

### 2.3 Access model C — official "developer quickstart" = brokers
The official `gonka.ai/docs/developer/quickstart/` explicitly tells app developers to access Gonka **through community brokers** that expose OpenAI-compatible APIs with `Authorization: Bearer <API_KEY>` — **no wallet/private key/signature needed for broker access.** Listed broker base URLs (examples): `proxy.gonka.gg`, `gonkagate.com`, `gate.joingonka.ai`, `router.gonkascan.com`, `gonka.pw`, `gonka-api.org`, `gonkabroker.com`. Each broker decides pricing, payment method, rate limits, models, SLA, data handling. Tool calling is supported (`"type":"function"` only; vLLM backend → no Assistants API features like code_interpreter/file_search).

Source: [gonka.ai/docs/developer/quickstart](https://gonka.ai/docs/developer/quickstart/).

### 2.4 Models actually available
- **Live for mainnet inference today:** `Qwen/Qwen3-235B-A22B-Instruct-2507-FP8` (the canonical example slug in every doc).
- **Golden references / being added via DevShards (NOT guaranteed live broadly):** Qwen3-0.6B, Qwen3-235B variants (DeepGEMM, pubkey-v2), **Kimi K2.6**, **MiniMax M2.7**. New models enter through on-chain governance.
- **DeepSeek:** not part of the current mainnet lineup as of this research.
- **Rule:** model set is per-broker and changes with the network → always call `GET /v1/models` at runtime; never hardcode the slug list.

Sources: WebSearch (gonka model availability, 2026); [gonka.ai/docs/host/quickstart](https://gonka.ai/docs/host/quickstart/).

### 2.5 Auth model summary (3 distinct shapes)
| Path | Auth | Pays in | Wallet needed | Best for us |
|---|---|---|---|---|
| opengnk self-host | wallet signature (server-side); client key ignored | GNK | yes (`GONKA_PRIVATE_KEY`) | BYO-wallet = zero-commission picker |
| GonkaGate | `Bearer <API_KEY>` | prepaid USD | no | fastest spike + markup upstream |
| other brokers | `Bearer <API_KEY>` | per-broker (USD/crypto/credits) | no | optionality / fallback |

### 2.6 Latency & reliability caveats
- **Grace Period:** ~180 epochs (~6 months) from 2025-09-15 mainnet launch → **inference at zero GNK cost**, daily GNK distributed to hosts; issuance decreases over time. Pricing/economics post-grace are not yet stable → cost modeling is provisional.
- **DevShards migration (v0.2.12):** inference now settled through devshard escrow sessions — a public node creates a devshard escrow for your account and routes requests to executors inside that session. This is a recent architecture change → expect instability windows.
- **Endpoint gotcha:** use `https://node4.gonka.ai` (443). The opengnk README warns `http://node4.gonka.ai:8000` "can hang" for discovery.
- **Our own grant note** flags the old proxy `gonka-gateway.mingles.ai` as unreliable, "moving to devshards."
- **No published latency SLA.** Qwen3-235B-A22B is a large MoE → expect higher TTFT than OpenRouter-hosted small models; must be measured in the spike. No uptime guarantee on the decentralized path.

Sources: WebSearch (Gonka launch / grace period / devshards); opengnk README; internal grant draft (lines 47).

### 2.7 GonkaGate vs delegated wallets vs agent accounts
- **GonkaGate** = a broker that hides crypto behind USD + API key (section 2.2). It is the easiest mapping to our existing API-key-upstream pattern.
- **Delegated wallets / agent accounts** = Gonka Roadmap **Track 2 P3**. There is **no first-class, documented "delegated wallet" REST primitive** surfaced in the public docs yet. The closest shipped building block is **`GONKA_WALLETS` multi-wallet round-robin** in opengnk — multiple funded wallets, requests spread across them. Our grant deliverable #2 ("delegated agent wallets / budget card") is therefore **something WE build on top** (per-agent spend policy + our R0 atomic ledger enforcing daily/per-call caps), backed by a dedicated Gonka wallet per agent — not a Gonka-native feature we can call. **Open question for founder/Gonka.**

Sources: [gonka.ai/docs](https://gonka.ai/docs/); internal grant draft (Track 2 P3, lines 30-34); opengnk multi-wallet section.

## 3. How Gonka maps onto OUR architecture

Our `:4000` gateway already abstracts upstreams via `UpstreamAdapter` (`packages/api-gateway/src/upstreams/interface.ts`) and dispatches by provider name in `registry.ts`. The DB is the source of truth for slugs/markup via `resolveModel()` (`src/routing/resolver.ts`): `models` → `model_upstreams` (price + `markup`, default 1.25) → `upstreams` (provider, ru_residency, latency, uptime). **OpenRouter (`src/upstreams/openrouter.ts`) is the exact template** — Gonka is also OpenAI-compatible, so a Gonka adapter is ~95% a copy with a different base URL and key source.

Key facts that constrain us (from `packages/api-gateway/CLAUDE.md` + `CLAUDE.md`):
- **A slug must exist in the registry** or routing returns 400 "Unknown model."
- **White-label is a hard rule** — Gonka adapter must strip any provider-revealing fields, same as openrouter.ts does (`delete provider/system_fingerprint/native_finish_reason`).
- **Commission rule (in code):** AIAG-supplied model routed via `:4000` → debit balance + apply markup. **User's own key/provider (OpenRouter / Gonka / BYOK) → charge ZERO.** This is the dividing line between the two integration tracks below.

## 4. Concrete recommendation — integration steps

### Track 1 — Gonka as a markup provider behind OUR `:4000` gateway (deliverable #1, fastest)
Use **GonkaGate** (API key, USD) so there is no wallet plumbing in the gateway.

1. **Create `packages/api-gateway/src/upstreams/gonka.ts`** — copy `openrouter.ts`, change:
   - `const GONKA_BASE = process.env.GONKA_BASE_URL || 'https://api.gonkagate.com/v1';`
   - `selectKey(byok) => byok || process.env.GONKA_API_KEY;`
   - keep the white-label stripping (`provider`, `system_fingerprint`, `native_finish_reason`, `message.reasoning`) verbatim.
   - keep `chat`, `chatStream`, (optionally `embeddings` — likely unsupported on Gonka, omit until `/v1/models` confirms).
2. **Register it** in `registry.ts`:
   ```ts
   case 'gonka':
     return process.env.GONKA_API_KEY ? gonkaUpstream : mockUpstream;
   ```
3. **Seed the DB** (prod migration, manual per our deploy notes):
   - insert into `upstreams` a row `provider='gonka'` (`ru_residency=false`, measured `latency_p50_ms`/`uptime`).
   - insert into `models` slug e.g. `gonka/qwen3-235b` (`type='chat'`).
   - insert into `model_upstreams` mapping the model → the gonka upstream with `upstream_model_id='Qwen/Qwen3-235B-A22B-Instruct-2507-FP8'`, prices, and `markup` (default 1.25). **Do not hardcode price** — set from measured cost (note: zero during grace period → set a nominal markup-only price or flag as promo).
4. **Add env to `/srv/aiag/shared/.env`:** `GONKA_API_KEY=…`, optionally `GONKA_BASE_URL`.
5. **Spike acceptance:** `curl :4000/v1/chat/completions` with `model=gonka/qwen3-235b` via `AIAG_GATEWAY_KEY` → real Qwen3 completion; verify ledger debit + markup applied; measure p50 latency.

### Track 2 — Gonka as a BYO-wallet FREE provider in the picker (zero-commission)
This honors the "own provider = free" rule. Two sub-options:

- **2a (recommended for grant story): self-hosted opengnk proxy on the VPS.** Run the Docker proxy with a funded `GONKA_PRIVATE_KEY`; it exposes `http://127.0.0.1:8080/v1`. Add a second gateway upstream `provider='gonka-byow'` pointing `GONKA_BASE_URL=http://127.0.0.1:8080/v1` with **markup=1.0 and free flag** (no balance debit), so it follows the BYOK/own-provider zero-commission path. ⚠️ VPS is 2GB RAM with 5 pm2 procs — the proxy is light (Node/Docker, no model weights — inference is remote), but verify memory headroom before deploying.
- **2b (true BYO-wallet by end user):** picker stores the user's `GONKA_PRIVATE_KEY`/`GONKA_ADDRESS` as a per-agent credential (reuse the provider-connection BYOK plumbing, migration 0026 `agent_provider_credentials`). The worker/gateway passes it through to a proxy instance. **Security:** storing a raw secp256k1 private key is materially riskier than an API key — must be encrypted at rest and never logged. Prefer 2a for the spike; defer 2b until we have key-vault handling.

Picker UI: provider-picker screen 17 already drafts "Gonka = free / BYO-GNK"; agent budget = delegated wallet on screen 33 (`docs/wireframes/tma/index.html`).

### Track 3 — delegated agent wallets (deliverable #2) — build on top
No Gonka-native delegated-wallet API exists. Implement as: per-agent dedicated Gonka wallet (or a `GONKA_WALLETS` pool) + **our** R0 atomic ledger enforcing daily-cap/per-call-cap/tool-allowlist + one-tap revoke + audit log. The enforcement layer is already the R0 deduct ledger; the new part is the spend-policy table and revocation. Confirm with Gonka whether a native delegation primitive is on their P3 timeline before promising the "wallet-native" framing.

## 5. Risks

1. **Single live model.** Only Qwen3-235B-A22B is dependably available → the "Qwen3, Kimi, others" claim in the grant draft is over-stated; soften to "Qwen3 today, Kimi/others as the network adds them." (Verify live list via `/v1/models` before submission.)
2. **Network instability (DevShards migration).** Recent v0.2.12 architecture change + flagged-unreliable legacy proxy. Routing through Gonka must have a fallback (our gateway already falls back to mock/other upstreams; ensure Gonka failures don't break agent runs).
3. **Grace-period economics.** Zero-cost inference now → no real pricing signal; post-grace GNK cost + GNK volatility (grant paid in GNK) makes long-term unit economics unknown.
4. **Private-key custody (Track 2b).** Holding users' raw GNK private keys is a high-value secret-management liability; API-key/broker path or our-own-wallet (2a) avoids it.
5. **No latency/uptime SLA** on the decentralized path; large MoE model → higher TTFT. Must measure, not assume.
6. **Broker trust.** GonkaGate/other brokers are independent third parties (data handling, pricing, SLA all theirs) — white-label + PII rules still apply; treat like any external upstream.
7. **VPS memory.** Track 2a adds a Docker proxy to an already-tight 2GB/5-proc box — verify headroom (proxy itself is light, but Docker daemon overhead is non-trivial).

## Adversarial review

**Verdict: holds up — partly.** The architecture and the core integration plan are sound and the load-bearing facts check out, but two material errors and several under-stated risks need correcting before this drives a grant submission or a prod deploy. (Reviewer independently re-verified against GonkaGate's own site, the official `gonka.ai/docs/developer/quickstart`, the `gonkalabs/opengnk` README, and the v0.2.12 release notes on 2026-06-03.)

### What verified correctly (no change needed)
- **opengnk proxy** — base URL `http://localhost:8080/v1`, all env vars (`GONKA_PRIVATE_KEY`/`GONKA_WALLETS`/`GONKA_ADDRESS`/`GONKA_SOURCE_URL`/`PORT`/`SIMULATE_TOOL_CALLS`/`NATIVE_TOOL_CALLS`), the `https://node4.gonka.ai` discovery URL, the **client key ignored / wallet-signature** auth model, the `inferenced` CLI flow, and the **`node4.gonka.ai:8000` "can hang"** warning are all confirmed verbatim from the README. Section 2.1 is accurate.
- **Official broker model (2.3)** — confirmed: "For most developers, the simplest way to use Gonka is to call a **community broker**," `Authorization: Bearer <API_KEY>`, the exact 7-broker URL list, `type:"function"`-only tool calling, and **no Assistants API** (`code_interpreter`/`file_search` unavailable, vLLM backend). Accurate.
- **Grace period (2.6)** — confirmed: 180 epochs (~6 mo) from 2025-09-15, zero GNK inference cost, GNK minted per epoch to hosts with decaying issuance. Accurate.
- **GonkaGate base URL + $10 credit** — `https://api.gonkagate.com/v1` and **"Start with $10 free credits"** are confirmed on GonkaGate's own homepage. The $10 claim (lines 14, 66) **survives** the challenge — an initial WebSearch contradicted it, but the vendor's own page settles it in R-03's favor.

### Material errors to fix
1. **GonkaGate fees are mis/under-stated (lines 67, 90, 139).** R-03 says only "platform fee" with no number. Actual structure: **5% on deposit + 10% on usage**, and the API key has a specific format (**`gp-...`**, not OpenAI's `sk-...`). This is load-bearing: the 10% usage fee **stacks on top of our default 1.25 markup** in `model_upstreams`. So the effective take-rate on a GonkaGate-routed AIAG model is ~1.25 × 1.10 ≈ **1.375**, not 1.25. Either eat the 10% (margin hit) or surface it in the seeded price — must be a conscious decision, not silent. Add the `gp-` prefix and the 5/10 split to §2.2 and §4-Track-1.
2. **Minimum deposit omitted (Track 1 feasibility).** GonkaGate requires a **prepaid minimum (~$20 USDT)** to go beyond the $10 trial. The "$10 free credit" is enough for the *spike acceptance curl*, but **not** for sustained grant-demo traffic — budget the deposit. Track 1 is not truly "no money down" past the smoke test.

### Under-stated risks (sharpen, don't add narrative)
3. **Grace-period end is closer than implied (Risk 3).** v0.2.12 already ships "**consensus-level machinery for transaction fees**" and multi-model PoC. Fee infrastructure landing *now* means the zero-cost window is operationally ending before the nominal ~6-month mark (which itself expires ~2026-03 — i.e. it may **already be past** relative to today, 2026-06-03). R-03 treats grace pricing as "provisional/future"; reframe as "**likely already metered or imminently so** — confirm live GNK cost before pricing, do not assume free."
4. **Track 2b key-custody risk is correctly flagged but the recommendation should be a hard NO for the spike, not "defer."** Holding end-users' raw secp256k1 keys is a different liability class than API keys (irreversible on-chain theft, no revocation). Tighten line 147/Risk 4 to "**2b is out of scope until a vetted KMS/HSM path exists** — not merely deferred."
5. **Self-hosted opengnk on the 2GB VPS is riskier than "light" suggests (2a / Risk 7).** R-03 itself notes the box runs 5 pm2 procs at 2GB. Adding the **Docker daemon + proxy** is the wrong place to find out about memory pressure — an OOM here can take down the *money path* (gateway/worker). Recommendation: do **not** co-locate 2a on the prod VPS for the spike; run opengnk on a throwaway/separate host (or skip 2a entirely and demo Track 1 + 2b-via-our-own-wallet). This also de-risks Track 3.
6. **No fallback wiring is asserted, only assumed (Risk 2).** R-03 says "our gateway already falls back" — verify that `resolver.ts`/`registry.ts` actually fail over a *single-upstream* model when Gonka 5xx/times-out, or a Gonka outage hard-fails any agent pinned to a `gonka/*` slug. Add a concrete fallback `model_upstreams` row (a second upstream for the same slug) as an acceptance criterion, not a hope.

### Tightened recommendation
- **Track 1 (GonkaGate) remains the right deliverable-#1 spike** — fastest green, real model, no wallet ops. Proceed, but: (a) record the **5% deposit + 10% usage** fee and the **`gp-` key format**; (b) decide explicitly whether the 10% is absorbed or passed into the seeded price (don't let it silently compress margin under the 1.25 markup); (c) plan the **~$20 deposit** beyond the $10 trial; (d) add a **fallback upstream** for the `gonka/*` slug as an acceptance gate.
- **Treat Gonka as currently metered**, not free — verify live `GET /v1/models` *and* a real per-token cost before seeding `model_upstreams`; flag as promo only if the API actually returns zero cost.
- **Do NOT co-locate the opengnk Docker proxy on the prod VPS** for the spike. Track 2a → separate host or skip; Track 2b (raw user keys) → **out of scope until KMS exists**.
- Everything else (white-label stripping, slug-must-exist, openrouter.ts-as-template, "single live model = Qwen3-235B, soften the Kimi/others claim", delegated-wallet = we-build-it) stands as written.
