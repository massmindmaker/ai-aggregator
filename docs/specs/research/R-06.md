# R-06 — Provider-picker data model + adapters

**Researcher:** senior staff eng (code-grounded)
**Date:** 2026-06-03
**Scope:** sync models.dev catalog → provider/model registry; provider adapters in the Hono gateway (native Anthropic/Google vs generic OpenAI-compatible); cost mapping (cost_in/cost_out); routing + graceful fallback; SSRF hardening for user-supplied `base_url` (R1-7).
**Primary code read:** `packages/api-gateway/src/{upstreams,routing,lib,proxy.ts,config.ts}`, `apps/agent-worker/src/{agent-runner,db,crypto}.ts`, `apps/tg-miniapp/{src/lib/external-agent.ts, app/api/tma/agents/route.ts, .../test-external/route.ts}`, `apps/web/src/app/api/providers/route.ts`, migrations `0004_gateway_core.sql` & `0026_provider_catalog.sql`, spec `docs/superpowers/specs/2026-05-30-provider-picker-toolbroker-spec.md`, `docs/specs/2026-06-02-r1-verified-plan.md`.

---

## Summary

The product already has **two parallel provider registries that do not match the spec or each other**, and the catalog-sync layer the brief asks about (`0023`/models.dev) was never built — the foundation that shipped is `0026`, a hand-seeded 8-row table with no `models_catalog`, no `npm`/adapter field, and no cost columns.

1. **Gateway registry (live, used for billing):** `upstreams` + `models` + `model_upstreams` (migration `0004`). Pricing is `price_per_1k_input/output` + per-row `markup`. Resolution = `resolver.ts` → `engine.ts` (5 routing modes). Adapters = `packages/api-gateway/src/upstreams/*` selected by a hardcoded `switch(provider)` in `registry.ts`. **All adapters are OpenAI-compatible** — there is no native Anthropic or Google branch anywhere in the gateway today.
2. **Provider-picker catalog (P0 foundation, mostly inert):** `providers` + `agent_provider_credentials` + 4 new `agents` columns (migration `0026`). `GET /api/providers` reads it. The worker's `resolveUpstream()` has a `provider_id` branch wired — **but the write path that would populate `provider_id`/`auth_ref` does not exist** (the agents `POST` route only handles legacy `external_openai`). So the branch is dead code on prod.
3. **The brief's `0023` design (models.dev sync, `models_catalog`, `npm_adapter`, native adapter dispatch) was never implemented.** The implementer renamed/reduced it to `0026`. This is the gap R-06 must close.

The catalog-sync should be built, but it should feed the **gateway** registry (`models`/`model_upstreams`), which is where billing/markup/white-label already live — not a third disconnected `models_catalog`. Native adapters (Anthropic, Google) belong in the gateway `upstreams/` directory behind the existing `UpstreamAdapter` interface, NOT in the worker. The worker should always talk OpenAI-compatible to either our gateway (aiag) or a user's endpoint; native protocol translation is the gateway's job.

The SSRF guard (R1-7, high) is the **one piece that is both load-bearing and currently broken**: `validateExternalUrl` is a string-level pre-flight on the create path only; the worker `resolveUpstream` fetches the decrypted-key request to a user-controlled `base_url` with **zero runtime check**, vulnerable to DNS-rebind and IPv6 ULA. Fix = a `safeFetch` egress guard in the worker (resolve-then-pin), not just a better regex.

## Key findings (with sources)

### F1 — There are TWO registries; the brief conflates them

| Registry | Tables | Migration | Purpose | Pricing unit |
|---|---|---|---|---|
| **Gateway routing catalog** | `upstreams`, `models`, `model_upstreams` | `0004_gateway_core.sql` | The `:4000` gateway's source of truth for valid slugs, routing, markup, billing | `price_per_1k_input/output` NUMERIC(18,10), `markup` NUMERIC(5,4) default 1.25 |
| **Provider-picker catalog** | `providers`, `agent_provider_credentials`, `agents.{provider_id,model_id,auth_ref,base_url_override}` | `0026_provider_catalog.sql` | Per-agent BYO-key connection (TMA) | none — no cost columns at all |

- `model_upstreams` schema: `packages/database/migrations/0004_gateway_core.sql:71-84`.
- `providers` schema (8 hand-seeded rows, `auth_kind` constrained to `'api_key'` only): `0026_provider_catalog.sql:31-55`.
- Resolver JOINs the gateway tables, not `providers`: `packages/api-gateway/src/routing/resolver.ts:42-52`.
- `CLAUDE.md` (packages/api-gateway): *"The model registry is the source of truth for valid slugs… Routing/markup decisions key off the registered upstream."*

**Implication:** the brief's "planned migration 0023" never landed; the shipped `0026` is a thinner thing. Do not invent a third `models_catalog`. The catalog-sync should **upsert into `models` + `model_upstreams`** (gateway tables) so the slug a synced model produces is automatically valid for billing/markup/white-label, and reuse `providers` (0026) only for the TMA BYO-key picker UI.

### F2 — models.dev/api.json shape is confirmed; cost unit is USD per 1M tokens

Verified live (WebFetch `https://models.dev/api.json`, 2026-06-03). Top-level object keyed by provider id:

```jsonc
{ "openai": {
    "id": "openai", "name": "OpenAI",
    "npm": "@ai-sdk/openai",                 // adapter hint — THE field that picks native vs generic
    "env": ["OPENAI_API_KEY"],
    "api": "https://api.openai.com/v1",       // default base_url
    "doc": "https://...",
    "models": {
      "gpt-4o": {
        "id": "gpt-4o", "name": "GPT-4o", "family": "gpt-4o",
        "attachment": true, "reasoning": false, "tool_call": true, "temperature": true,
        "knowledge": "2023-10", "release_date": "...", "last_updated": "...",
        "modalities": { "input": ["text","image"], "output": ["text"] },
        "open_weights": false,
        "limit": { "context": 128000, "output": 16384 },
        "cost": { "input": 2.5, "output": 10.0, "cache_read": 1.25, "cache_write": 0 }
      } } } }
```

- **`cost.input` / `cost.output` are USD per *million* tokens.** Optional `cache_read`/`cache_write` (also /1M) and `tiers`/`context_over_200k` for volume/long-context premiums.
- `npm` is the adapter discriminator (`@ai-sdk/openai`, `@ai-sdk/anthropic`, `@ai-sdk/google`, `@ai-sdk/openai-compatible`, `@ai-sdk/amazon-bedrock`, `@ai-sdk/azure`, …). ~137 providers.
- **Unit-mismatch risk (cost mapping bug):** the gateway stores `price_per_1k_*`, models.dev gives `/1M`. Sync MUST divide by 1000 (`cost.input / 1000`). The brief's `0023` design stored `cost_in` "USD / 1M tokens" directly into `models_catalog` — that column would have been off by 1000× vs the gateway's `/1k` math. **Pick ONE unit; recommend storing `/1k` to match `model_upstreams` and `resolver.ts`'s `Number(price_per_1k_input)`.** This is the single most likely silent money bug in this workstream.

### F3 — Gateway has NO native adapters today; all upstreams are OpenAI-compatible

- `registry.ts:20-35` dispatches `provider` → adapter via `switch`: `openrouter`, `kie`, `ollama`, `groq`, else `mock`. Every text adapter (`openrouter.ts`, `groq.ts`, `ollama.ts`) hits an OpenAI-shaped `/chat/completions` and returns `ChatResponse` (OpenAI shape). Kie is async-jobs only.
- The `UpstreamAdapter` interface (`upstreams/interface.ts:91-100`) is already the right seam for native branches: `chat()`, `chatStream?()`, `embeddings?()`, plus media methods.
- **There is no Anthropic (`/v1/messages`, `x-api-key`, `anthropic-version`) or Google (`:generateContent`) branch.** The brief asks for these. They belong here, behind `UpstreamAdapter`, selected by a new `upstreams.adapter` column (mirrors models.dev `npm`).
- White-label stripping is per-adapter and load-bearing: `openrouter.ts:73-96` deletes `provider`/`system_fingerprint`/`native_finish_reason`/`reasoning`. Any native adapter MUST translate the upstream's response into the OpenAI `ChatResponse` shape AND strip brand markers (Anthropic's `model`/`stop_reason`, Google's `candidates`/`safetyRatings`). `CLAUDE.md`: *"White-label is a hard rule."*

### F4 — The provider-picker `provider_id` path is wired in the worker but has no write path (dead on prod)

- Worker reads `provider_id`/`auth_ref` and resolves the credential: `agent-runner.ts:42-58` + `db.ts:98-130` (`loadProviderCredential`).
- But the create route (`apps/tg-miniapp/app/api/tma/agents/route.ts:86-103`) only writes `connection_type`/`external_*`. **Nothing ever sets `agents.provider_id` or inserts `agent_provider_credentials`.** Confirmed: no INSERT into `agent_provider_credentials` anywhere in `apps/`.
- `db.ts:122-128` decodes `enc_key` as `Buffer.from(r.enc_key, 'base64')`; the (not-yet-written) BYOK write route MUST store `encryptSecret(key).toString('base64')` to match. AES-256-GCM crypto already exists and is mirrored: `apps/tg-miniapp/src/lib/crypto.ts` + `apps/agent-worker/src/crypto.ts` (`encryptSecret`/`decryptSecret`/`hintFromSecret`, key `TMA_KEY_ENCRYPTION_KEY`, layout `iv(12)|ct|tag(16)`).

**Implication:** R-06 delivery is not just "add adapters" — it must close the write path (agents `POST`/`PATCH` accepting `provider_id`/`connection_kind`/`api_key`, inserting the encrypted credential, setting `auth_ref`) for any of this to be reachable.

### F5 — SSRF (R1-7, high, confirmed_bug): create-time string check only; runtime fetch is unguarded

- `validateExternalUrl` (`external-agent.ts:40-58`) is a *string/regex* check run **only at create time** (route.ts:97) and on the test probe (`test-external/route.ts:30`). Gaps vs a real guard:
  - No DNS resolution → **DNS-rebind**: a hostname that passes the regex at create time can resolve to `127.0.0.1`/`169.254.169.254` at run time.
  - IPv6 ULA (`fc00::/7`, `fd00::/8`) **not covered** — only `::1` is. `fe80::` link-local not covered.
  - IPv4-mapped IPv6 (`::ffff:127.0.0.1`) and encoded/decimal/octal IPv4 (`0x7f.1`, `2130706433`) not covered.
  - `0.0.0.0` covered; `100.64.0.0/10` (CGNAT) and `192.0.0.0/24` not.
- The worker then does `fetch(url, …)` with the **decrypted user key in the Authorization header** (`agent-runner.ts:172`, `postChat`) against `agent.base_url_override`/`external_base_url` with **no runtime check at all**. R1-7 verdict (`r1-verified-plan.md:11,24`): *"DNS-rebind + decrypted-key exfil. external_openai branch live; provider_id branch latent."*
- The gateway's `proxy.ts` is a generic pass-through `fetch` with no egress guard either — but it is only fed gateway-DB base URLs today (not user input), so the live exposure is the worker.

## Recommendation

### A. Catalog sync — feed the GATEWAY registry, normalize to /1k, ops-owned columns survive

Build `apps/agent-worker/src/catalog-sync.ts` as a BullMQ repeatable job (D#13: in-process, no OS cron, no container) on a new `catalog-sync` queue, `repeat: { pattern: '0 4 * * *' }`. It:

1. `fetch('https://models.dev/api.json')` (~2 MB), parse.
2. For each provider → upsert `upstreams` (id, provider, `base_url` from `api`, new `adapter` column from `npm`). **Never overwrite ops columns** `enabled`, `markup`, `ru_residency` — `ON CONFLICT (id) DO UPDATE SET base_url=…, adapter=…, metadata=…, updated_at=NOW()` (explicit column list excluding ops fields).
3. For each model → upsert `models` (slug = `<provider>/<model_id>`, type from modalities, `display_name`, `metadata` carrying `tool_call`/`reasoning`/`modalities`/`limit`) and `model_upstreams` (`price_per_1k_input = cost.input / 1000`, `price_per_1k_output = cost.output / 1000`, keep existing `markup`).
4. **Staleness, never hard-delete:** add `models.status` (`'live'|'stale'`); mark all `'stale'` pre-sync, flip seen rows to `'live'`, `synced_at=NOW()`. Agents may reference dropped models.
5. **Banned providers:** keep `upstreams.enabled=false` for subscription/OAuth-only providers (white-label + RKN posture). Sync must not flip `enabled`.

Add columns via prod ALTER (`sudo -u postgres psql aiag` — app role can't ALTER):
```sql
ALTER TABLE upstreams ADD COLUMN IF NOT EXISTS adapter VARCHAR(40);     -- 'openai'|'anthropic'|'google'|'openai_compatible'|'bedrock'|'azure'
ALTER TABLE models    ADD COLUMN IF NOT EXISTS status  VARCHAR(16) NOT NULL DEFAULT 'live';
ALTER TABLE models    ADD COLUMN IF NOT EXISTS synced_at TIMESTAMPTZ;
```
Keep `0026.providers` as the **TMA BYO-picker UI catalog only** (it already powers `GET /api/providers`); do not let it diverge into a second pricing source. Optionally, the sync can also refresh `providers.api_base`/`enabled` from the same payload so the picker list stays current.

> Why feed the gateway tables and not a new `models_catalog`: billing, markup, white-label stripping and the "valid slug" gate already key off `models`/`model_upstreams` (`resolver.ts`, `CLAUDE.md`). A second catalog means a model can be pickable but unbillable (or billed at a stale/duplicated price). One registry, one price.

### B. Adapter design — native branches live in the GATEWAY, worker stays OpenAI-only

Add a `adapter` discriminator to the registry dispatch and two native adapters behind the existing interface:

```
registry.ts:  switch (upstream.adapter ?? 'openai_compatible') {
  case 'openai_compatible': case 'openai':  return openAiCompatibleUpstream(upstream.base_url)
  case 'anthropic':                          return anthropicUpstream(upstream.base_url)
  case 'google':                             return googleUpstream(upstream.base_url)
  case 'bedrock': case 'azure':              throw provider_not_supported_yet  // stub, wire later
}
```

- **Generic OpenAI-compatible** (`openRouterUpstream` generalized to accept a `base_url`): covers OpenAI, DeepSeek, Mistral, Groq, OpenRouter, Ollama, vLLM, and any custom endpoint. This is the 90% path.
- **Anthropic native** (`upstreams/anthropic.ts`): `POST {base}/v1/messages`, headers `x-api-key` + `anthropic-version: 2023-06-01`; map OpenAI `messages[]`→Anthropic `system`+`messages`, `max_tokens` required; map response `content[0].text`→`choices[0].message.content`, `usage.input_tokens/output_tokens`→`prompt_tokens/completion_tokens`, `stop_reason`→`finish_reason`. Strip `model`/`id` brand markers per white-label rule.
- **Google native** (`upstreams/google.ts`): Google ships an OpenAI-compatible base (`…/v1beta/openai`, already seeded in `0026` row `google`). **Prefer the OpenAI-compatible base over native `:generateContent`** — then Google needs *no* native branch, just the generic adapter pointed at that base. Only write a native Google branch if a model is missing from the OAI-compat surface.
- Keep all adapters returning the OpenAI `ChatResponse` shape so `settle`/logging/pricing stay unchanged (`interface.ts:21-32`). Reuse the streaming SSE loop pattern from `openrouter.ts:100-147`.
- **Pragmatic cut:** ship generic-OpenAI (fully) + Anthropic-native; treat Google via its OAI-compat base; stub Bedrock/Azure as `provider_not_supported_yet`. This matches the spec's own "pragmatic cut" and keeps the surface shippable on the 2 GB VPS.

The worker (`agent-runner.ts`) never gains an adapter switch — it always POSTs OpenAI-shape to either `127.0.0.1:4000/v1` (aiag, billable) or the user's endpoint (external, cost 0). Native translation is centralized in the gateway, where white-label and markup already live.

### C. Cost mapping — single conversion point, /1k, markup unchanged

- Convert at sync time: `price_per_1k = cost / 1000`. Do the division in `catalog-sync.ts`, store `/1k`, leave `lib/pricing.ts` (`cost = upstreamUsd × rate × markup × batchDiscount × caching`) and `resolver.ts` untouched.
- Carry `cache_read` into `metadata` and feed it through the existing `caching_factor`/`CACHING_DISCOUNT` path (`pricing.ts:26-33`) rather than inventing a new column.
- Do not hardcode markup; it stays per-row in `model_upstreams.markup` (`CLAUDE.md`, FIX C8). For BYO-key (external) agents, cost stays **0** — the `if (isExternal) return` short-circuit in `settleRun` (`db.ts:353`) and `agent-runner.ts:334` is the enforced commission rule; do not touch it.

### D. Routing + graceful fallback — extend, don't rebuild

- Keep the 5-mode engine (`engine.ts:92-118`: auto/fastest/cheapest/balanced/ru-only) and policy filters. A synced model with N upstreams becomes N `model_upstreams` candidates automatically — no engine change.
- The worker's existing degraded fallback (`agent-runner.ts:190-213`: gateway 404/model_not_found → direct OpenRouter) is the right shape. Generalize it slightly: on gateway `model_not_found`, the gateway should itself try the next `model_upstreams` candidate before returning 404 (engine already returns a pool; today the route picks one). Add a per-candidate try/next loop in the chat route, capped at the candidate count, so a single dead upstream doesn't fail the request. Health/circuit data already exists (`0008_health_circuit.sql`).
- **DEFAULT_MODEL fix (known latent bug):** `nousresearch/hermes-4-405b` (`agent-runner.ts:28`) is NOT in the gateway registry → gateway 400. The catalog sync will register `nousresearch/*` slugs from models.dev; verify the default slug lands as a valid `models.slug` post-sync, or change the default. (`apps/agent-worker/CLAUDE.md` flags this explicitly.)

### E. SSRF guard (R1-7) — runtime egress guard, resolve-then-pin

This is the highest-severity, must-ship item. A better regex is insufficient (DNS-rebind defeats it). Build `apps/agent-worker/src/lib/egress-guard.ts` exporting `safeFetch(url, init)`:

1. Parse URL; **HTTPS only** (or `http://127.0.0.1:4000` explicitly allowlisted for the aiag gateway loopback).
2. `dns.lookup(host, { all: true })` → get ALL resolved IPs.
3. Reject if ANY resolved IP is in a blocked range. Cover the full set the current regex misses:
   - IPv4: `0.0.0.0/8`, `10/8`, `100.64/10` (CGNAT), `127/8`, `169.254/16` (link-local + `169.254.169.254` metadata), `172.16/12`, `192.0.0/24`, `192.168/16`, `198.18/15`, multicast `224/4`, reserved `240/4`.
   - IPv6: `::1/128` (loopback), `fc00::/7` (ULA — **the gap**), `fe80::/10` (link-local), `::ffff:0:0/96` (IPv4-mapped — re-check the embedded v4), `64:ff9b::/96` (NAT64), multicast `ff00::/8`.
   - Normalize encoded IPv4 (octal/hex/decimal) before classifying.
4. **Pin the connection to the vetted IP to close the TOCTOU/rebind window:** connect to the resolved IP (set it as the connect target / custom `lookup` that returns only the vetted address), send `Host:` and SNI = original hostname. In Node/Bun: pass a custom `lookup` to the agent, or resolve→build an undici `Agent` with `connect: { lookup }` that re-validates and returns the single pinned IP. The point is the IP that was *validated* is the IP that is *connected to*.
5. Allowlist: `127.0.0.1:4000` (aiag gateway) + `openrouter.ai` (documented fallback). Everything else must pass the resolver guard.
6. Use `safeFetch` in `agent-runner.ts postChat` for the external/provider_id branches (aiag-gateway loopback bypasses via allowlist). Keep `validateExternalUrl` as the cheap create-time pre-flight AND share the same IP classifier (single source of truth — reuse the classifier in `external-agent.ts`).

Per `r1-verified-plan.md:24`, this is Wave-1, effort M, parallelizable. Note R1-7 also flags the `provider_id` branch as latent — when the BYO write path (F4) lands, it inherits the same `base_url_override` SSRF surface, so `safeFetch` must wrap that branch too from day one.

## Risks

- **Cost unit 1000× error (money bug).** models.dev is /1M; gateway is /1k. A sync that stores the raw value over- or under-charges by 1000×. Mitigation: convert in one place, add a unit assertion test, and a CI sanity check (e.g. no `price_per_1k_input > 1` for known-cheap models).
- **Two registries drift.** If sync feeds a new `models_catalog` (per the dead `0023` spec) instead of `models`/`model_upstreams`, a model can be UI-pickable but unbillable, or billed at a duplicated/stale price. Mitigation: single registry (gateway tables); `0026.providers` stays UI-only.
- **White-label leak via native adapters.** Anthropic/Google responses carry brand markers (`stop_reason`, `candidates`, model ids). A naive pass-through leaks the upstream. Mitigation: every native adapter normalizes to `ChatResponse` AND strips brand fields; add a test asserting no `anthropic`/`google`/`gemini`/`claude` substring in returned metadata for aiag-routed calls.
- **SSRF residual via redirects.** `safeFetch` must also re-validate on every redirect hop (or disable auto-redirect and re-check), else a 302 to `http://169.254.169.254` re-opens the hole. Bun/undici follow redirects by default.
- **2 GB VPS memory.** models.dev/api.json is ~2 MB JSON; parsing + ~thousands of upsert rows daily is fine, but stream/batch the upserts (chunked `INSERT … ON CONFLICT`) rather than one giant statement to avoid a memory spike on the shared box.
- **Write-path scope creep.** R-06 cannot ship adapters in isolation; the `provider_id`/`agent_provider_credentials` write path (F4) is a prerequisite for the picker to be reachable. Treat it as in-scope or explicitly sequence it first.
- **Prod migration discipline.** Migrations are manual/untracked and the app role can't ALTER (`packages/database/CLAUDE.md`). New columns need `sudo -u postgres psql aiag`; verify live prod state before assuming sequence numbers.

## Open questions

1. **One registry or two?** Recommend folding catalog-sync into the gateway `models`/`model_upstreams` and keeping `0026.providers` UI-only. Needs a founder/architecture nod since the `0023` spec assumed a separate `models_catalog`.
2. **markup for synced models:** what default `markup` do freshly-synced `model_upstreams` rows get — global `DEFAULT_MARKUP=1.25` (config.ts:18) or a per-provider value? The `0023` spec put markup on `providers`; the live schema puts it on `model_upstreams`. Pick the per-row location (already live) and seed 1.25.
3. **Which providers to enable at launch?** ~137 providers in models.dev; most are not white-label-safe / RKN-safe. Need an explicit allowlist (the brief's "banned providers set false"). Who owns that list?
4. **Bedrock/Azure:** ship as `provider_not_supported_yet` stubs now (recommended) or invest in SigV4/deployment-path now? SigV4 is heavy for a 2 GB single-VPS MVP.
5. **R1-4 dependency (double-ledger):** cost mapping here assumes the worker's `tg_user_balances` debit + gateway markup is the *intended markup model* (per r1-verified-plan Wave-0). If the founder rules "single billing authority," the cost-application point moves and this design's "store /1k in model_upstreams" must coordinate with that decision.
6. **Streaming for native Anthropic:** Anthropic SSE event shape differs from OpenAI deltas; do we need streaming for native adapters in v1, or is non-streaming acceptable for the agent loop (which today calls `callModel` non-streaming, `stream:false`)? The worker loop does not stream, so native streaming can be deferred.

- **F5 (SSRF):** `validateExternalUrl` is string/regex, create-time only; `postChat` (`agent-runner.ts:155-173`) does a bare `fetch` with the decrypted key and zero runtime IP check. The enumerated regex gaps (IPv6 ULA, IPv4-mapped, octal/decimal, CGNAT) are all genuinely absent from `external-agent.ts:20-38`. Accurate; correctly rated highest-severity.

### Key issues (where it is wrong / incomplete)

1. **HOLE — Recommendation B silently breaks BYO native-protocol keys.** The doc's thesis is "worker always talks OpenAI-shape; native translation lives in the gateway." But the gateway's native adapter would use **AIAG's** system key, while a BYO user supplies **their own** Anthropic/Google key stored in `agent_provider_credentials`. The worker's `provider_id` branch (`agent-runner.ts:49-57`) points `url` *directly* at `cred.base_url ?? p.api_base` — and `0026` seeds `anthropic` = `https://api.anthropic.com/v1` (line 48), which is **not** OpenAI-compatible. So a BYO-Anthropic-key agent makes the worker POST OpenAI-shape to `api.anthropic.com/v1/chat/completions` → 404/400. R-06's "worker stays OpenAI-only" design has **no working path for a BYO key against a native-protocol provider.** Either (a) the worker must route BYO native keys *through* the gateway using the existing `x-upstream-key` BYOK seam (`chat.ts:41`) so the gateway's native adapter does the translation with the user's key, or (b) the `providers` seed for `anthropic`/`google` must use OpenAI-compatible bases only (Anthropic has none today; Google does — `/v1beta/openai`, already seeded). This is the single biggest gap and it is not in the Risks section.

2. **Two BYOK mechanisms, unreconciled.** The gateway already has request-level BYOK via `x-upstream-key` (`chat.ts:41`, `calcByokFeeRub` fixed fee). The worker has a *separate* BYOK via `agent_provider_credentials`. R-06 never connects them. If issue #1 is fixed via (a), these must be the same path. Decide one BYOK authority before building.

3. **Recommendation B understates the plumbing.** Dispatch today is `getUpstream(upstream.provider)` keyed on the `upstreams.provider` *string* (`chat.ts:68`). Adding `switch(upstream.adapter)` requires threading a new `adapter` field through **four** layers — `resolver.ts` SELECT (add `u.adapter`), the `DbRow` type, `engine.ts` `Upstream`/`UpstreamCandidate` types, and the route — not just `registry.ts`. As written ("add a discriminator to the registry dispatch") an implementer will wire registry.ts and find `upstream.adapter` is `undefined`. Call out the resolver/engine type changes explicitly.

4. **Missing white-label leak in a response HEADER.** The Risks section covers body brand-markers but misses `chat.ts:159`: `c.header('X-AIAG-Upstream', upstream.provider)`. For a native adapter this header emits `anthropic`/`google` to the client — a white-label violation the body-stripping does not catch. Add to the white-label test (assert the header too).

5. **Recommendation D rationale is factually wrong (fix still feasible).** "the engine already returns a pool; today the route picks one" — no: `pickUpstream` (`engine.ts:92-118`) returns a **single** upstream. The pool lives in the *resolver* (`model.candidates`, exposed at `chat.ts:58`). The try/next loop is still implementable (the route holds `model.candidates`), but the proposed mechanism is misattributed; an implementer following the text will look in the wrong module. Also: a fallback loop that re-issues a billable upstream call needs idempotency care vs `settleCharge`/the partial-unique `gateway_transactions` idempotency index — not mentioned.

6. **Provider count inflated.** R-06 says "~137 providers." The authoritative source (sst/models.dev, MIT) advertises **75+**. Minor, but it feeds Open Question #3 (allowlist size) — the real curation burden is ~half what's stated. (Upside: MIT license + public `api.json` confirmed, so the legal/feasibility basis for daily sync is fine.)

7. **DEFAULT_MODEL fix is hand-waved.** D says "the sync will register `nousresearch/*` slugs … verify the default lands." But models.dev's id for that model may not be `nousresearch/hermes-4-405b`, and the slug scheme R-06 proposes is `<provider>/<model_id>` — which may not equal the worker's hardcoded `DEFAULT_MODEL` (`agent-runner.ts:28`). Safer: pin `DEFAULT_MODEL` to a slug you *control after sync*, or seed that one row by hand and assert it in CI. "Verify post-sync" is not a fix.

### Minor / nits
- `config.ts:18` `DEFAULT_MARKUP=1.25` confirmed; Open-Q#2's recommendation (seed `model_upstreams.markup=1.25` per-row) is right.
- Gateway `PORT` default is `8787` (config.ts:9); it listens on `:4000` only via env. The worker hardcodes `127.0.0.1:4000` — fine, but the egress-guard allowlist must match whatever `:4000` actually is in prod env, not the schema default.
- Staleness via `models.status` is good, but `resolver.ts:51` filters `m.enabled = TRUE` only — a `'stale'` model is still resolvable unless the sync also flips `enabled` or the resolver adds `AND status='live'`. The doc says "agents may reference dropped models" but doesn't say how a stale model is *prevented from billing at a stale price*. Specify the resolver guard.

### Tightened recommendation
Adopt A, C, E broadly; **rework B and re-scope D.**
- **B (revised):** Route ALL billable native-protocol traffic — AIAG-supplied *and* BYO-key — through the gateway. The gateway owns native adapters; the worker stays OpenAI-only by sending BYO keys to the gateway via the existing `x-upstream-key` seam (unify the two BYOK paths, issue #2). For providers with no OpenAI-compatible surface (Anthropic), the worker MUST NOT fetch them directly. Thread `adapter` through resolver→engine→route (issue #3). Strip the `X-AIAG-Upstream` header for native (issue #4).
- **E (keep, tighten):** `safeFetch` resolve-then-pin is correct and must ship first. Add: re-validate on every redirect hop (already noted), and apply it to the gateway `proxy.ts`/native-adapter `fetch` too, since under revised-B user-controlled base_urls now reach the gateway.
- **C/A (keep):** single registry, convert `/1000` once, add the unit-assertion test + a CI check (`price_per_1k_input < 1` for known-cheap models). Gate billing on `status='live'` in the resolver (minor nit), not just `enabled`.
- **D (re-scope):** correct the "engine returns a pool" wording → loop over `model.candidates` in the route; add settle-idempotency handling for the retry.
- **Sequencing:** F4 write-path + the BYOK-unification decision (issue #1/#2) are blocking prerequisites; do not start adapters until they're resolved. Fix `DEFAULT_MODEL` by seeding+asserting one slug, not by post-hoc verification.
