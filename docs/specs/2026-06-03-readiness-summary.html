1 · GO / NO-GO — deploy Wave-0 + D-8 now

GOconditional

Ship it. The three branches form a clean linear stack (6 commits, +1036/-41, 16 files). runtime RAM delta ≈ 0 no migrations no new runtime deps / processes

The billed worker call is non-streaming, so the "stream → settles at ₽0" risk does not apply. The change is forward/back compatible — a revert just drops billing back to the local estimate; no data corruption.

The one real risk is build-time, not runtime: tma next build OOM on the 2 GB box. Fully mitigable. Gate conditions below.

GO conditions (must all hold)

  • ① Run the Pattern-A test gate green first — disposable aiag_test DB + vitest, no prod write.
  • ② Build gateway (+worker) via CI (no VPS OOM). Build tma + agent-worker on the VPS with the OOM guard (swap on + --max-old-space-size=1536 + pm2 stop web during the tma build) — or run the tma build in CI too.
  • ③ No migration step — none exist in the stack.
  • ④ Post-deploy smoke passes: D-8 replay → 401, D-0 margin logged + balance debited, DEFAULT_MODEL no longer 400s, safeFetch blocks private IPs.
  • ⑤ Finish D-8 before calling it "secure": the Redis one-shot nonce (SET hash 1 NX EX 600) is not yet wired in the verify route — the hash is surfaced but replay defense is still absent until it lands.
  • ⚠ Strip X-AIAG-Charged-Rub / X-AIAG-Upstream-Cost-Rub at nginx — white-label leak if exposed.

Standing recommendation (not a blocker): upgrade prod 2 GB → 4 GB before real TMA traffic — removes the build-OOM friction permanently.

3 · Prioritized next-5 backend tasks (dependency order)

  1. Merge + deploy Wave-0 & finish D-0/D-8 [D-0 · D-7 · D-8]

    Merge the three Wave-0 branches, deploy, and strip the two X-AIAG-* billing headers at nginx. Finish D-8 by wiring the Redis one-shot nonce in the verify route (hash already surfaced). Persist realized margin to a column (not just a log line) so D-9/D-12 can read it.

    Unblocks the entire money path; closes the two shipped security fixes.

  2. D-9 tool broker (reserve → settle/refund) [D-9]

    Add tools catalog + tool_calls ledger tables; reserve→execute→settle/refund; a per-call guarded spent_today_rub += price increment. Closes the confirmed unbilled-tool leak (paid image_gen in a later-failed run is silently free) + the daily-budget bypass. No crypto. Depends on (1).

    Stops real money leaking on every failed-after-tool run.

  3. Deposit reconciler — the #1 user-facing hole [R-04]

    Add a server-side lt-watermark cron in apps/worker as the authoritative crediter (TonCenter/TonAPI), demote the client poll to UX, and add per-user deposit memo/address mapping to kill loss-mode-2. Correct under any FD-1 structure — build now, no founder decision needed.

    Fixes the biggest product hole: a user who closes the app before the poll succeeds can pay and not be credited.

  4. D-6 catalog-sync + native adapters + BYOK unification [D-6]

    Daily models.dev BullMQ sync into gateway models/model_upstreams with /1M→/1k conversion + CI assertion (the 1000× bug is currently unguarded); a native Anthropic adapter (then Google-via-OAI-compat) behind UpstreamAdapter; route BYO native keys through the gateway's x-upstream-key seam; add the TMA BYOK write route so migration-0026 credentials actually save. Depends on (1).

    Makes "connect a non-OpenAI provider key" real end-to-end instead of 404.

  5. D-1 ledger + USD anchor (highest blast radius) [D-1]

    Introduce tg_ledger_entries double-entry + projection, switch the credit unit to integer micro-USD, delete USD_TO_RUB=90 (both copies), and run the dry-run-first, freeze-window, SUM-invariant live-balance migration. Do last in this batch — after D-0 margin is trusted in prod.

    Removes the hardcoded FX scalar and the single-mutable-balance risk — but it's the most dangerous migration, so it goes after everything above is green.

4 · What is NOT done overall

Wave-0 (money-correctness + cheap-security) is done on branches, not merged to master. Waves 1–3 are almost entirely unbuilt. The largest hole: there is no reliable money-in path — deposit is native-TON-coin + text-comment + client-poll only.

User-facing features with no working backend

  • Topping up reliably — client-poll of TON coin matched by a text comment; no server reconciler, no USDT jetton. #1 hole
  • Non-OpenAI provider keys (Anthropic/Google) — schema + reader only; no write route, no native adapter → would 404
  • Live/streamed agent replies — runs are async BullMQ; run route is a 202 stub; no SSE
  • Agent semantic memory — flat key-value TEXT only; no pgvector recall
  • Telegram delivery — raw fetch /sendMessage DM card; labels cost in "₽"; no grammY, no Business, no per-user bot
  • Creator earning from templates — no publish/clone/lineage/payout tables; blocked on D-0 storing margin
  • Per-call tool billing safety — paid tool in a failed run is silently free; tool spend can exceed daily budget

Whole subsystems NOT built (R&D / later waves)

  • D-2/D-3 Managed Hermes — no Daytona/Modal, no provisioning, no control-plane sidecar; infra-blocked on 2 GB + HERMES-CANNOT remotely
  • D-4 Gonka provider — no adapter, no upstream seed
  • D-5 real runtime — no AI-SDK swap, no pgvector, no OTel, no SSE
  • D-10 x402 outbound — deferred to real demand
  • D-11 MCP — no SDK, no /mcp mount; prereq agent_tokens table doesn't exist (one shared AIAG_GATEWAY_KEY today)
  • D-12 creator economy — blocked on D-0; web aiag_settle_charge accrues on gross, not margin (latent over-payment to NOT copy verbatim)
  • D-13 Telegram Business delivery — no apps/tg-bot, no business_connection passthrough
  • D-14 character pipeline — Kie transport exists; three input-shape gaps unaddressed (voice-tuning knobs dropped)
  • Jetton (USDT-on-TON) — no 0x0f8a7ea5 parsing, no master allowlist; "1000× jUSDT" item confirmed phantom

Honest shippable surface today: Journeys 1, 2 (minus streaming/tool-approve/trace), 3 (local templates), 4, 5 (basics), 6 (external endpoint only), 9 (TON only), 10 (enforcement), 14.1 (DM card). Journeys 7, 8, 11, 12, 13 are BRANCH or NOT-BUILT → Board B (R&D).
