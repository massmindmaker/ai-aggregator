Кредит-хаб

Наш внутренний кредит (USD-пеггед, 1 кр = 1¢) — единая единица ценности. Вокруг него — сменные адаптеры, которые конвертируют ЛЮБОЙ платёжный рельс внутрь (приём) и наружу (выплата). Новый рельс = новый адаптер, не переписывание ядра. Та же логика, что наш провайдер-пикер для моделей — только для денег.

01Схема: приём → кредиты → выплата

Юзер никогда не видит ни TON, ни USDC, ни газа — он видит кредиты. Чейны прячутся в адаптерах.

02Три слоя

  • ВХОД — юзер → рельс (TON / USDC / …) → кредиты. Работа on-ramp-адаптеров.
  • ЕДИНИЦА — всё считается в наших кредитах. Лимиты, бюджеты, ренты, наценка. Леджер = единственный источник правды (уже построен: tg_ledger_entries, атомарный settleRun).
  • ВЫХОД — кредиты → off-ramp-адаптер платит провайдеру (модель / тулза / автор). Каждый mint и burn — запись в леджере.

03Сценарии — где какой рельс

1 · Пополнил и общается с агентом
TON → 500 кр. Ответ = 2-5 кр (модель + наценка). Coinbase не участвует.
2 · Агент генерит картинку (наша тулза)
8 кр/вызов списали. Coinbase не участвует.
3 · Арендовал шаблон у автора
Рента 200 кр → автору 100% (наш cut 0%) + модель сверху. Coinbase не участвует.
4 · Агент юзает ВНЕШНЮЮ x402-тулзу будущее
Тулза: «402, заплати 0.01 USDC» → мы платим через Coinbase → списываем ~1.25 кр. Единственный сценарий с Coinbase.
5 · Автор выводит заработок будущее
Кредиты → off-ramp → TON / USDC на его кошелёк (после FD-2). Выплата наружу.

04Как развивать — фазы

Фаза 1 · сейчас

Ядро без крипто-сложности

TON-вход → кредиты → внутренние выходы (модели + наши тулзы + маркет тулзов v1 в кредитах). Полноценное рабочее приложение. ~готово.

Фаза 2 · хаб открывается

Мульти-крипто вход + x402 выход

Coinbase x402 off-ramp (внешние тулзы) + USDC/мульти-крипто on-ramp. Кредит становится универсальным хабом. Сначала testnet (бесплатно).

Фаза 3 · двусторонне

Выплаты + A2A

Off-ramp выплаты авторам (TON/USDC наружу), агент платит агенту (x402 + ERC-8004). Хаб становится многосторонним.

Принцип

Адаптеры, не хардкод

Каждый рельс = маленький адаптер (quote / accept / pay / confirm). Добавить крипту = добавить адаптер. Ядро (леджер) не трогается.

05Принципы финансового слоя

  • Кредит — единая единица (USD-пеггед). Чейны не показываем юзеру никогда.
  • Адаптеры, а не вшитые рельсы. Один интерфейс, много реализаций (как провайдер-пикер).
  • Леджер = источник правды. Append-only, атомарно (guarded UPDATE…WHERE…RETURNING). Каждый вход/выход — запись.
  • Минимум кастоди. Не строим свой фасилитатор/чейн там, где есть провайдер (Coinbase для x402, TON Connect для TON). Минимальные горячие балансы, managed-кошельки.
  • Пеггед + сверка. Кредит = 1¢; регулярно сверяем леджер с реальными балансами рельсов (что заведено vs что должны).

06Честные флаги

Комплаенс. «Конвертировать любой рельс в кредиты и платить наружу» = по сути функция обмена/кастоди крипты → реальный регуляторный вес. По канону legal пока не факторим (иностранная сущность держит крипту/USDC) — но при масштабе это вернётся. Не игнорируем.
Кастоди-риск растёт с хабом. Чем больше рельсов и балансов — тем больше поверхность атаки. Минимальные горячие балансы, managed/кастодиальные провайдеры, НЕ горячий mainnet-кошелёк на 2GB-проде.
Не строим то, что дают провайдеры. Coinbase x402 (внешние тулзы), TON Connect (вход), крипто-PSP (мульти-крипто on-ramp). Мы — леджер + адаптеры, не банк.

Одной фразой: кредит-хаб = наш леджер в центре + сменные адаптеры приёма/выплаты по краям. Coinbase, TON, будущие крипты — просто адаптеры. Ядро живёт уже сегодня; рельсы добавляются по фазам, не переписывая середину.
